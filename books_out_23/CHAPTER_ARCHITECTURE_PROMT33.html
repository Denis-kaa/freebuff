§4 · Anti-Pattern Atlas — 6 failure-anatomy

Каждый anti-pattern — это failure-path, который Freebuff прошёл (или потенциально прошёл бы). Анатомия: Trigger → Damage → Mitigation. SVG-визуализация структурная, с разделением «как было» и «как стало».

ANTI-1

§4.1 ANTI-1 · RCE через exec() / shell=True

Era G · Episode E-03 · CRITICAL severity
FACT: 11 совпадений exec|shell=True в initial scan удалены за один PR review. Zero regressions в pre-existing test-suite.
DECISION: ANTI-1 зафиксирован в ADR-001 и core_02/LESSONS.md. CI hook canary_no_exec_no_shell.py выполняет grep сканирование на каждый commit.
FUTURE TRIGGER: если в будущем потребуется shell-piping для какой-то нестандартной функции — это сигнал к re-design, а не к реабилитации ANTI-1.
ANTI-2

§4.2 ANTI-2 · Untracked = Safe illusion

Era C · Episode E-10 · HIGH severity
FACT: 11 untracked Python-файлов (metrics.py + 10 wrappers) исчезли после git stash drop. Восстановление: 12 часов bytecode reverse-engineering (dis.dis()) для metrics.py (925 lines).
ANALYSIS: git stash — это не backup. .gitignore, *.pyc cache, .git hidden directory — все «есть» в atomic смысле, но не сохраняются как diff. «Untracked = не существует» — главный lesson.
DECISION: ANTI-2 зафиксирован. CI hook pre_commit_untracked.py fail'ит PR если untracked-files > 10 OR > 5KB суммарно. Codex-стандарт: file в git в течение 4 часов.
FUTURE TRIGGER: если когда-то работает только потому что не в git — это anti-pattern эмеражент. Promote в git-commit asap.
ANTI-3

§4.3 ANTI-3 · Engine Sprawl — новый engine на каждый feature

Era C · Episode E-09 · MEDIUM severity
FACT: 5 новых engine'ов за 4 дня (Era C). 7 конкурирующих SQLite-таблиц в одном context.db. 5 WAL-collision strategies. 3 events для «нового state» (один с dedup, один без). 2 подхода к graceful-degradation.
DECISION: ARC-ARB-005 + ADR-007 Vision зафиксировал Reuse First principle. Прежде чем создать engine, ты ОБЯЗАН argue'нуть, почему существующий не подходит.
CONSEQUENCE: 3 из 7 engine'ов объединены в один (vector_memory + knowledge_engine → Context.Memory). 2 deprecated как stubs. Single-context.db.
ANTI-4

§4.4 ANTI-4 · Silent Failure (lazy import swallow)

Era C — V · Episodes E-28—30 · HIGH severity (ADR-015)
FACT: module-level _LAZY_IMPORT_ERRORS: List[str***REMOVED*** accumulat'ил cross-call pollution: инвокация A fail'ила imports → warnings persist → инвокация B наследовала чужие warnings в свой payload. CI green; observability failure.
DECISION: ADR-013 Phase 11 BaseFactory и ADR-015 migration выполнены в v5.189.32-36. 3-pattern: (A) per-instance self._import_warnings для OOP модулей; (B) Option B3 _LAZY_IMPORT_ERRORS.clear() для functional; (C) PEP 562 __getattr__ shim для backward-compat.
CONSEQUENCE: для whim_capture.py (Episode E-30) — паттерн НЕ применён. Forensics показал: singleton никогда не пишется после module-load, не в __all__, WhimStore без lazy state. ADR-015 N/A. Это валидный «не рефакторинг» outcome.
ANTI-5

§4.5 ANTI-5 · Boilerplate Factory Init

Era V · Episode E-26 · LOW severity (ADR-013)
FACT: 3 sub-classes (TestFactory, ContentFactory, ResearchFactory) имели ~400 lines IDENTICAL boilerplate (init, manifest loader, scenario registry connect, lifecycle hooks). Total: ~1200 lines кода, повторённого 3 раза.
DECISION: ADR-013 — вынести общий класс в core_02/factory_base.py. Sub-classes переопределяют только specialist. Code reduction ~66%.
ANTI-6b

§4.6 ANTI-6b · Vocabulary Drift → silent fallback

Era P · Episodes E-07, E-23 · HIGH severity
FACT: 147 capability-токенов в codebase до whitelist'а. qwen2.5:1.5b silent fallback на drift. Зелёные тесты создавали иллюзию рабочей системы при полностью сломанном routing.
DECISION: CLOSED VOCABULARY contract. core_02/capabilities.py::KNOWN_CAPABILITIES — canonical closed set. Validator raises ValueError at startup. ANTI-6b — он же Lesson ANTI-6b в ADR-008 promt36.
FUTURE TRIGGER: если new capability discovered — должно быть явно зарегистрировано в KNOWN_CAPABILITIES до добавления в code (CAN-016 register-first).

5.1 ADR Detail Format (universal 8-field schema)

Каждый ADR в расширенной schema включает 8 полей ниже. Это соответствует user request "Status · Context · Drivers · Decision · Alternatives · Consequences · Risks · Future Triggers" с полями, верифицированными в реальных ADR файлах проекта (ADR_012, ADR_013).

@decision ADR-001

5.1.1 Model Gateway Universal API

ACCEPTED · IMPLEMENTED · Era G

1. Status

ACCEPTED (Proposed Era I, Encoded v5.x canonical). Implementation: IMPLEMENTED in scripts_01/model_gateway.py + 25 tests covering delegation.

2. Context

До Era I: LLM invocations вызывались прямо из script code через provider-specific endpoints. Каждый script знал, какую модель использовать. Это создавало multi-vendor sprawl.

3. Drivers

(a) Provider agnosticism: замена LLM-провайдера не должна требовать переписывания каждого call site. (b) Auto-fallback при rate-limit или downtime. (c) Closed-vocabulary capability routing (см. ANTI-6b) — gateway валидирует capability against KNOWN_CAPABILITIES ПЕРЕД invocation.

4. Decision

Все LLM invocations идут через единый ModelGateway API. No direct API calls to providers from script code. Реализация: scripts_01/model_gateway.py с priority scoring + fallback chain (qwen2.5:1.5b local → gemini-fallback → retry).

5. Alternatives

(a) Status quo (direct calls): rejected — coupling. (b) LangChain adapter: rejected — extra dependency. (c) OpenAI-SDK with module swaps: rejected — surface area. (d) Custom gateway accepting prompt objects (принято).

6. Consequences

Positive: provider substitution без переписывания calls. Negative: gateway — single point of failure. Mitigation: gateway имеет try/except на каждый call + metrics endpoint /metrics/* для observability.

7. Risks

(a) Gateway SPOF: mitigated через fallback chain. (b) Gateway throughput bottleneck: mitigated через async + queue. (c) Silent quality drop при fallback на qwen2.5:1.5b: mitigated через ANTI-6b closed-vocab, fallback только на explicit user-tier.

8. Future Triggers

  • Если latency превышает 200ms p95 для 100+ concurrent invocations → добавить connection pooling.
  • Если capability drift reintroduce (closed-vocab bypass) → escalate в ADR-update with new validator.
  • Если model_gateway.py превысит 600 lines без sub-module split → refactor to model_gateway/{registry,selector,fallback***REMOVED***.
@decision ADR-002

5.1.2 MCP Server — Pure Python (stdlib http.server)

ACCEPTED · IMPLEMENTED · Era P

1. Status

ACCEPTED · IMPLEMENTED · scripts_01/mcp_server.py + 132 tests green.

2. Context

Anthropic MCP (Model Context Protocol) стал индустриальным стандартом в 2025-2026. FreeBuff хотел expose capabilities через MCP, но официальный Python SDK (mcp) требует Node-side dependencies или тяжёлый Pydantic runtime — несовместимо с Termux ARM64 minimalism.

3. Drivers

(a) Тяжёлый SDK несовместим с Termux (memory/disk/CPU ограничения). (b) Прямая зависимость от узконаправленного пакета — fragility. (c) Потребность в direct JSON-RPC control — для streaming optimizations.

4. Decision

Build MCP server in pure Python: stdlib http.server + ThreadingHTTPServer + custom JSON-RPC framing. No mcp-SDK dependency.

5. Alternatives

(a) Official SDK: rejected (Termux compatibility). (b) FastAPI-based reimplementation: rejected (uvicorn + ASGI = еще одна зависимость). (c) Pure stdlib (принято).

6. Consequences

Positive: zero external deps на MCP layer. Negative: raw stdlib harder to extend; future feature parity с official SDK требует careful manually maintained shims.

7. Risks

(a) Future MCP standard changes → manual porting required. (b) Production высокой concurrency → stdlib ThreadingHTTPServer медленнее asyncio реализаций.

8. Future Triggers

  • MCP spec change → add shim layer + version-pinned branch.
  • Throughput > 1000 RPS → migrate to aiohttp or uvloop.
  • Adoption в multi-instance setup → CircuitBreaker + cross-instance TLS-cert coordination.
@decision ADR-003

5.1.3 MCP Streamable HTTP Transport

ACCEPTED · IMPLEMENTED · Era P

1. Status

ACCEPTED · IMPLEMENTED · supersedes initial transport choice in ADR-002.

2. Context

После ADR-002 baseline, нужен streaming transport для agentic-operations. Batch HTTP response после 30 секунд работы — это lost time для user.

3. Drivers

(a) UX: пользователь видит reasoning в real-time. (b) Atomic rollback через Ctrl-C во время streaming. (c) Token-budget awareness (early-stop streaming).

4. Decision

Transport layer использует ThreadingHTTPServer + Server-Sent Events (SSE) для each tool call. Event schema: event: model.start | tool.call | model.continue | checkpoint | done.

5. Alternatives

(a) WebSocket: rejected (over-engineering для textual stream). (b) Long polling: rejected (latency). (c) SSE (принято).

6. Consequences

Positive: UX rationality <1s. Negative: SSE + Cloudflare Tunnel имеет ограничение на streaming duration (100s на free tier).

7. Risks

(a) Cloudflare free-tier streaming timeout — mitigated через chunked adaptive throttling. (b) Browser session timeout — пользователю connect через long-lived channel.

8. Future Triggers

  • Cloudflare free-tier deadline нарушается часто → migrate to alternative tunnel provider (см. ADR-004 limitations).
  • Atomic rollback fails (SSE disconnect mid-tool-call) → добавить explicit session-recovery point.
@decision ADR-004

5.1.4 FastAPI Wrapper + Cloudflare Tunnel

ACCEPTED · IMPLEMENTED · Era P

1. Status

ACCEPTED · IMPLEMENTED · scripts_01/forge_api.py + forge_interactive_api.py + 20+ tests.

2. Context

MCP server (ADR-002, ADR-003) внутренне используется агентами. Для human-facing REST API нужен second layer — но НЕ FastAPI как replacement MCP. Дополнительный concern: Termux не имеет публичного IP — нужно сделать service доступным извне.

3. Drivers

(a) Browser-friendly REST для dashboard/mobile. (b) Avoid manual port-forwarding на Termux. (c) Decoration поверх MCP для metrics endpoints (/metrics/*).

4. Decision

FastAPI wrapper layer через scripts_01/forge_api.py: REST routes на той же server-side pipeline. Cloudflare Tunnel (cloudflared) exposes port публично через https://freebuff.cftunnel.cloud.

5. Alternatives

(a) Reverse SSH tunnel: rejected (manual maintenance). (b) ngrok: rejected (cost + reliability). (c) Direct IP через connection: rejected (CGNAT unreliable). (d) Cloudflare Tunnel (принято).

6. Consequences

Positive: public URL без manual ops. Negative: dependency на Cloudflare free-tier limits + их uptime.

7. Risks

(a) Cloudflare free-tier SLA — mitigated через fallback на local-only mode при outage. (b) Tunnel bandwidth limit — mitigated через monitoring. (c) Public exposure (HIGH) — mitigated через Episode E-11 Bearer Auth + ANTI-1 hardening.

8. Future Triggers

  • Cloudflare downtime превышающий 24h в месяц → evaluate alternatives.
  • Authentication bypass attempt зафиксирован → emergency rotation + audit.
  • Stale tunnel (24h+ without traffic) → auto-restart policy.
@decision ADR-005

5.1.5 ContextManager Bridge (termux-ai-agent)

ACCEPTED · IMPLEMENTED · Era G-P

1. Status

ACCEPTED · IMPLEMENTED · core_02/context_manager.py + tests in test_context_manager.py.

2. Context

wizard.lib (interactive CLI) и orchestrator.blueprint (corpus loading) до ADR-005 имели direct construction setup. Каждый перезаписывал global context состояние в startup. termux-ai-agent не мог интегрироваться без rewriting.

3. Drivers

(a) Decouple prompting от corpus loading. (b) Unify capability-token resolution через KNOWN_CAPABILITIES subset check. (c) Модульный test surface для context-aware operations.

4. Decision

Создать ContextManager — typed bridge class. Wizard и orchestrator консумируют через bridge interface. termux-ai-agent наследует bridge contract.

5. Alternatives

(a) Global state object: rejected (AN-7 hot-path subscriptions, anti-testability). (b) Function call layer: rejected (no type safety). (c) ContextManager class (принято).

6. Consequences

Positive: unit-testable; explicit lifecycle (init/load/resolve/close). Negative: нужен refactor каждого consumer'а.

7. Risks

(a) Long-lived bridge state утечка; mitigated через explicit close() + GC. (b) Capability drift; mitigated через ANTI-6b в startup validator.

8. Future Triggers

  • Bridge state > 50MB persistent → split context (active+archive).
  • Test count saturated через ContextManager (≥60% of tests touch bridge) → introduce mockable bridge interface.
@decision ADR-006

5.1.6 Lightpanda Headless Browser

PARTIAL · Era P+

1. Status

ACCEPTED · PARTIAL · binary installed via install_lightpanda.sh; not yet integrated в all browser-driven flows — Phase 1.4 outstanding.

2. Context

Browser-automation tasks (screenshots, scraping, dashboard rendering) требуют headless browser. Default options (Playwright, Chromium) — тяжёлые для Termux.

3. Drivers

(a) Lightpanda binary ≈ 6MB vs Chromium ≈ 150MB. (b) Memory ≈ 30MB vs 200MB. (c) Faster startup time.

4. Decision

Adopt Lightpanda (Go-based headless browser) для browser-automation вместо Playwright/Chromium.

5. Alternatives

(a) Chromium/Playwright: rejected (resource weight). (b) curl-based scraping: rejected (no JS support). (c) Lightpanda (принято).

6. Consequences

Positive: aligned с Termux ARM64 constraints. Negative: limited feature parity (не все Chromium-extensions available).

7. Risks

(a) Untested для OAuth2-redirect-flows (JS-heavy). (b) Future maintenance burden: Lightpanda — third-party tool.

8. Future Triggers

  • Если Lightpanda перестаёт поддерживать нужный protocol → maintain fork или migrate back to Chromium subset.
  • Если browser automation используется > 10 сайтов → evaluate full Chromium containerization.
@decision ADR-007

5.1.7 Vision 3.0 · AI Infrastructure Layer

ACCEPTED · IMPLEMENTED · Era C-IV

1. Status

ACCEPTED · IMPLEMENTED · manifests in BUFFY_PROJECT.md v2.0.0; Phase 6 CoWork shipped v5.17-v5.23.

2. Context

Vision 2.0 framing (Agentic Coding Assistant) был слишком узким. Long-lived projects требовали stable platform, не single-shot agent invocations.

3. Drivers

(a) Multi-project context support. (b) Persistent memory across sessions. (c) Multi-agent coord через multi-provider fallback.

4. Decision

Vision 3.0: 4-осевое позиционирование (project-centric · local-first · multi-mode · stateful). Workspace OS = platform name с synonym Freebuff.

5. Alternatives

(a) Vision 2.0 continuation: rejected (framing too narrow). (b) Pure SaaS pivot: rejected (CAN-17 anti-duplication / contradict core principles). (c) Vision 3.0 (принято).

6. Consequences

9.5.4 Consequence chain — cascading architectural effects

Cascade diagram: каждый ADR последовательно влияет на next. Forward chain ADR-001 → ADR-002 → ADR-003 → ADR-007 → ADR-008 → ADR-013 → ADR-015. Каждый downstream ADR зависимо от upstream: менять ADR-001 ОЗНАЧАЕТ переоценить ADR-002, ADR-003, и весь chain.

Critical: ADR-015 (lazy-import migration) был решён ПОСЛЕ ADR-013 (ForgeFacade), потому что BaseFactory создал per-instance boundary, внутри которой lazy import warnings имели attribute-host (self._import_warnings) вместо module-singleton. Это инверсия «fix the surface, then the inside» pattern: ADR-015 был бы невозможен без ADR-013’s per-instance foundation.

Reverse chain — equally important: ADR-007 (Mission Lock vision) retroactively explain’ed почему ADR-001–006 были нужны как building blocks. Mission Lock создал frame, в котором pre-existing decisions выглядели coherent. Это архитектурный Bernstein-effect: retroactive coherence через narrative — каждое отдельное решение было incrementally justified, но в сборе рассказают mission-level story.

Divergence points: ADR-008 и ADR-009 разошлись от canonical Mission chain — они не о routing/data, они о governance rules и override controls. Это правильная orthogonal по ANTI-3 (engine sprawl) — новые concerns должны получать свои ADR-decision nodes, не squeezing в existing.
