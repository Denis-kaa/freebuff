## Книга проекта (Project Book)

**Файл:** `docs/engineering-memory/PROJECT_BOOK.md`

Это нарративная память проекта: почему принимались решения, что ломалось, какие кризисы заставляли менять курс и какие уроки остались. При старте каждой сессии агент ДОЛЖЕН ознакомиться с ключевыми главами и использовать Project Book как первичный источник контекста проекта.

**Ключевые главы:**

- **Глава 1. Genesis: FreeBuff 2.0 (2026-07-28)** — исходная архитектура и первые 500+ тестов.
- **Глава 2. Эра протоколов: MCP, HTTP, FastAPI, туннели** — наружние интерфейсы и транспорты.
- **Глава 3. Первый security-кризис: убиваем `exec` и `shell=True`** — почему безопасность стала архитектурой.
- **Глава 4. Реструктуризация v5.0.0** — переход к `docs/core/`, `pompts/` как контракты.
- **Глава 5. Лавинное наращивание** — метрики, presence, RAG, плагины и дублирование.
- **Глава 6. The July 31 Crisis** — потеря и восстановление `metrics.py` из байткода.
- **Глава 7. Второй security-кризис** — закрытие shell-exec и Bearer auth.
- **Глава 8. Поворот к Workspace OS** — переход от наборов скриптов к операционной среде.
- **Эпилог. Engineering Memory** — зачем нужна внешняя память проекта.

### Архитектура
- Модульность; одна основная задача на модуль (Single Responsibility).
- Минимальная связанность; понятная структура каталогов.
- DRY: нет дублирования, нет магических чисел/строк.

### Читаемость
- Понятные имена функций и переменные.
- Комментарии и docstrings.
- README или инструкция запуска.
- Единый стиль оформления.

### Надёжность
- Обработка ошибок (try/except, set -e).
- Логирование действий.
- Корректное завершение при ошибках, не оставлять повреждённые файлы.
- Проверка существования файлов/директорий и прав доступа.
- Идемпотентность.
- Восстановление после сбоя.

### Безопасность
- Без root; работа в Termux без дополнительных привилегий.
- Секреты только в переменных окружения / `.env`.
- Валидация входных данных.
- Никаких произвольных shell-команд без проверки.
- Экранирование пользовательского ввода.

### Совместимость
- Termux / Android / ARM64, POSIX-совместимые команды.
- Проверка наличия необходимых утилит перед запуском.

### Производительность
- Минимизация RAM, диска, лишних процессов.
- Кэширование и избежание повторных тяжёлых операций.

### Логирование и UX
- Логирование начала/завершения, ошибок, предупреждений.
- Режимы DEBUG и QUIET.
- Понятный прогресс, дружелюбные ошибки, не засорять терминал.
- `--help`, `--version`, корректные exit-коды.

### Конфигурация, документация, тестируемость, масштабируемость
- Настройки в конфигурационном файле со значениями по умолчанию.
- Установка/запуск/примеры/CLI/структура/зависимости задокументированы.
- Тестовые сценарии, примеры входных данных и ожидаемые результаты.
- Легко расширяться новыми модулями и плагинами.

### Инженерные принципы
- KISS, DRY, SOLID где применимо.
- Никакой преждевременной оптимизации.
- Код, который можно понять через год.
