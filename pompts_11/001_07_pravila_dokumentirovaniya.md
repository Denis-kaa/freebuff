Промт: "Правила документирования для терминального агента"

Контекст

Я работаю над проектом blueprints_v3 — терминальный AI-агент на базе FreeBuff, адаптированный для Android (Termux + proot-distro ubuntu). Проект активно развивается, и мне нужна система документирования, которая автоматически создает структурированные документы при изменении кода, архитектуры или принятии решений.

Задача

Настрой систему правил для агента, чтобы он создавал следующие типы документов при необходимости:

Обязательные документы (всегда):

1. ARCHITECTURE.md — описание архитектуры проекта:
   · Слои (presentation, domain, data, infrastructure)
   · Компоненты и их взаимодействие
   · Диаграммы (plantuml/mermaid)
   · Технический стек
   · Паттерны проектирования
2. README.md — общее описание проекта:
   · Что это и для чего
   · Быстрый старт
   · Установка
   · Использование
   · Команды
3. SESSION_DUMP.md — лог сессии работы агента:
   · Дата/время
   · Выполненные задачи
   · Ошибки и их решения
   · Изменения в коде
   · Ссылки на релевантные документы

Рекомендуемые документы (по запросу или при изменениях):

4. DECISIONS.md — архитектурные решения:
   · Проблема
   · Рассмотренные альтернативы
   · Выбранное решение
   · Обоснование
   · Последствия
5. IMPLEMENTATION.md — детали реализации:
   · Пошаговые инструкции
   · Ключевые файлы и их назначение
   · Зависимости
   · Конфигурация
6. REFERENCES.md — источники и референсы:
   · Ссылки на документацию
   · Использованные статьи
   · Аналоги и их архитектура
   · Сравнительные таблицы
7. ROADMAP.md — план развития:
   · Этапы реализации
   · Текущий статус
   · Планируемые фичи
   · Сроки
8. COMPARISON.md — сравнение с аналогами:
   · OpenClaw
   · FreeBuff
   · Codebuff
   · Другие решения
   · Таблица сравнения по критериям
9. TROUBLESHOOTING.md — решение проблем:
   · Частые ошибки
   · Решения
   · Диагностика
   · Советы

Документы для исследований и экспериментов:

10. BRAINSTORM.md — идеи и подходы:
    · Список идей
    · Оценка сложности
    · Потенциальные решения
    · Приоритеты
11. EXPERIMENTS.md — результаты экспериментов:
    · Что тестировали
    · Результаты
    · Выводы
    · Следующие шаги
12. GLOSSARY.md — терминология проекта:
    · Ключевые термины
    · Определения
    · Аббревиатуры
13. CONTRIBUTING.md — правила для контрибьюторов:
    · Стандарты кода
    · Процесс ревью
    · Тестирование
    · CI/CD
14. SECURITY.md — политика безопасности:
    · Уязвимости
    · Отчеты
    · Практики
15. MIGRATION.md — миграции и брейкинг-чейнджи:
    · Версионирование
    · Что изменилось
    · Как обновиться
16. PERFORMANCE.md — производительность:
    · Метрики
    · Бенчмарки
    · Оптимизации
17. API.md — API документация:
    · Эндпоинты
    · Форматы запросов/ответов
    · Примеры
18. DEPLOYMENT.md — развертывание:
    · Требования
    · Инструкции
    · Переменные окружения

Правила для агента

1. После каждого коммита/изменения:
   · Обновить ARCHITECTURE.md если изменилась структура
   · Обновить README.md если добавилась новая функциональность
   · Создать запись в SESSION_DUMP.md
2. При принятии архитектурного решения:
   · Создать запись в DECISIONS.md с обоснованием
3. При исследовании новых подходов:
   · Добавить в BRAINSTORM.md
   · Если проведен эксперимент — в EXPERIMENTS.md
4. При реализации новой фичи:
   · Обновить IMPLEMENTATION.md
   · Добавить примеры в API.md если нужно
5. При сравнении с аналогами:
   · Обновить COMPARISON.md
6. При обнаружении проблемы:
   · Добавить в TROUBLESHOOTING.md

Формат документов

Все документы в Markdown с структурой:

· Заголовки (h1, h2, h3)
· Списки (маркированные/нумерованные)
· Таблицы
· Код-блоки с указанием языка
· Диаграммы Mermaid
· Ссылки на другие документы

Задачи для агента

1. Создать все перечисленные документы с базовым содержанием
2. Настроить автоматическое обновление при изменениях
3. Добавить шаблоны для каждого типа документа
4. Связать документы перекрестными ссылками
5. Создать INDEX.md с навигацией по всем документам

1. ONBOARDING.md — для новых пользователей
2. FAQ.md — частые вопросы

4. MODULES.md — описание модулей

Формат ответа

1. Список всех документов с описанием
2. Шаблоны для 5 ключевых документов (ARCHITECTURE, README, DECISIONS, IMPLEMENTATION, REFERENCES)
3. Правила автоматического создания/обновления
4. Структура папки docs_10/
5. Дополнительные варианты документов с обоснованием
