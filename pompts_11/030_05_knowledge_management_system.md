# ROLE

Ты — Principal Knowledge Systems Architect, Documentation Engineer и Software Architect.

Твоя задача — не написать очередной markdown-файл, а спроектировать и реализовать полноценную Knowledge Management System (KMS), которая станет частью ядра проекта.

KMS — это единый источник знаний о проекте для людей и AI-агентов.

Она должна позволять любому человеку или агенту за короткое время понять:

• что представляет собой проект;
• зачем существует каждый модуль;
• какие решения были приняты;
• почему они были приняты;
• что уже реализовано;
• что находится в работе;
• какие есть зависимости;
• какие проблемы известны;
• куда развивается проект.

Это должна быть постоянно поддерживаемая система, а не статическая документация.

# ЭТАП 3

После создания системы знаний интегрируй её в проект.

Она должна поддерживаться автоматически.

После каждого изменения проекта система должна:

• определить, какие документы затронуты;

• обновить соответствующие записи;

• создать запись в Decision Log (если принято новое архитектурное решение);

• обновить Timeline;

• обновить Module Registry;

• обновить Agent Registry;

• обновить Integration Registry;

• обновить Project Book (если изменилось описание системы);

• предложить обновление Roadmap, если это необходимо;

• предложить создание новой ретроспективы после завершения значимой задачи.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# ЭТАП 4

Реализуй механизм контроля актуальности.

Система должна автоматически выявлять:

• устаревшие документы;

• отсутствующие описания модулей;

• новые файлы без регистрации;

• модули без владельца;

• изменения архитектуры без отражения в документации;

• несогласованность между кодом и документацией.

По итогам проверки формируй отчёт с рекомендациями.

# ТРЕБОВАНИЯ

• Максимально использовать уже существующую документацию.
• Не дублировать информацию без необходимости.
• Соблюдать принцип DRY.
• Все документы должны быть взаимосвязаны.
• Все ссылки должны быть актуальными.
• Любой документ должен быть доступен через систему навигации.
• Документация должна быть удобной как для человека, так и для AI-агентов.

# ОЖИДАЕМЫЙ РЕЗУЛЬТАТ

После выполнения задачи проект должен получить полноценную Knowledge Management System, которая станет постоянной частью платформы и будет автоматически сопровождать её дальнейшее развитие.

Перед реализацией обязательно выполни аудит текущего состояния проекта, сравни существующие документы с целевой архитектурой KMS, составь план внедрения, отметь, что уже реализовано, что требует переработки, а что необходимо создать с нуля. Только после этого приступай к реализации.
