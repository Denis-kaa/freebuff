

MISSION: Полная инвентаризация проекта и проверка консистентности

Цель

Перед дальнейшей разработкой провести полную инвентаризацию проекта и сформировать объективную картину текущего состояния.

На данном этапе запрещается реализовывать новые функции.

Необходимо определить:

что реально существует в коде;

что существует только в документации;

что устарело;

что дублируется;

что является каноническим источником истины.


Результатом должен стать подробный отчёт, который будет использоваться как отправная точка дальнейшей разработки.


---

Задача 1. Инвентаризация документации

Просканируй всю директорию документации.

Для каждого документа определить:

путь;

назначение;

статус:

актуален;

частично устарел;

полностью устарел;

дубликат;

архив;


когда последний раз изменялся;

с какими компонентами связан;

используется ли другими документами;

необходимо ли сохранить;

необходимо ли обновить;

необходимо ли архивировать;

необходимо ли удалить.


Составить таблицу.

Например:

Документ	Назначение	Статус	Решение




---

Задача 2. Инвентаризация кода

Просканировать весь проект.

Для каждого крупного компонента определить:

путь;

назначение;

степень готовности;

используется ли;

кем используется;

имеются ли дубли;

имеются ли устаревшие реализации;

рекомендуется оставить;

рекомендуется объединить;

рекомендуется удалить.


Например:

| Компонент | Назначение | Используется | Статус |


---

Задача 3. Mapping документации ↔ кода

Для каждого документа определить:

какие файлы кода он описывает.

Для каждого компонента определить:

какой документ его описывает.

Получить двусторонний Mapping.

Например

VISION.md

↓

core/

↓

ContextManager.py

↓

MemoryEngine.py


---

ARCHITECTURE_MANIFEST.md

↓

EventBus

↓

Orchestrator

↓

Plugin API


---

Выявить:

документы без кода;

код без документации;

устаревшие ссылки;

битые ссылки.


---

Задача 4. Проверка соответствия

Проверить, насколько документация соответствует реализации.

Для каждого раздела определить процент соответствия.

Например

Vision

95%

Architecture

87%

Roadmap

63%

Project Book

98%

Engineering Memory

100%


---

Для каждого несоответствия указать

что написано;

что реализовано;

что необходимо изменить.


---

Задача 5. Поиск дублирования

Найти:

дубли модулей;

дубли сервисов;

дубли роутеров;

дубли API;

дубли интеграций;

дубли моделей;

дубли документов.

оставить;

объединить;

архивировать;

удалить.

Не выполнять изменения.

Разделить работы на этапы.

Этап 2

Дублирование

Этап 4

Архитектура

Новые функции

Указать:

трудоёмкость;

ожидаемый эффект;

риски.


---

Ограничения

Не изменять код.

Не изменять документацию.

Не создавать новые компоненты.

Не выполнять рефакторинг.

Не архивировать файлы автоматически.

Только анализ и отчёт.



---

Критерий завершения

Должен быть подготовлен единый документ PROJECT_INVENTORY_REPORT.md, содержащий:

полную инвентаризацию документации;

полную инвентаризацию кода;

двусторонний mapping «документация ↔ код»;

список актуальных документов;

список устаревших документов;

список архивируемых документов;

список актуальных компонентов;

список устаревших компонентов;

список дубликатов;

карту проекта;

перечень канонических Source of Truth;

оценку соответствия документации и кода;

пошаговый план приведения проекта в консистентное состояние.
