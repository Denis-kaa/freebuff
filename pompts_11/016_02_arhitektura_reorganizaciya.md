### Архитектурный принцип: Buffy — Infrastructure Plugin

**Buffy — НЕ новый AI Agent.**

Buffy — Infrastructure Plugin.

Он расширяет существующие Runtime.

Он не заменяет:
- Claude Code
- OpenClaw
- Hermes
- Codex
- Cursor
- FreeBuff
- другие Runtime

Buffy предоставляет дополнительные возможности:
- долговременный контекст
- документацию проекта
- знания проекта
- синхронизацию
- совместную работу
- передачу задач
- маршрутизацию
- Bridge между Runtime
- Collaboration Layer

Любой Runtime должен продолжать работать после удаления Buffy.
Buffy не должен становиться точкой отказа.
Архитектура должна оставаться loosely coupled.

### Android First

**Основная целевая платформа проекта:** Android + Termux.

Все новые функции необходимо оценивать с точки зрения возможности реализации на Android.
Если решение невозможно реализовать на Android — необходимо предложить альтернативу.

Поддержка Linux/macOS/Windows является расширением, а не основной целью проекта.

### Лицензирование

**Buffy не должен нарушать лицензии сторонних проектов.**

Запрещается:
- обход лицензий
- модификация закрытого кода
- использование недокументированных внутренних API

Интеграция должна строиться через:
- CLI
- MCP
- ACP
- публичные API
- официальные механизмы расширения

### 0.1 Три режима работы

Модель, которую нужно зафиксировать — три конкретных режима работы, а не абстрактные "Collaboration"/"Team Mode":

#### Режим 1 — Single
Один пользователь, один воркспейс. Buffy — просто персистентный контекст и мост к одному или нескольким раннтаймам (Claude Code, OpenClaw, Codex), даёт им функции, которых нет из коробки (сохранение контекста между сессиями, документация, знания проекта). Это то, что уже существует и работает — Core + текущий freebuff_plugin.

#### Режим 2 — Cowork (Companion)
Один пользователь, несколько агентов/провайдеров одновременно. Buffy выступает мостом между агентными системами (OpenClaw, Claude Code, Codex) — даёт им общий контекст и возможности, которых нет по отдельности у каждого. Ключевой механизм: **агентная карусель** (round-robin) между провайдерами/runtime'ами — если у одного закончился лимит/токены или пользователь просто экономит, задача передаётся следующему в очереди без потери контекста. Это то, для чего нужен `KeyPool` (ротация ключей провайдеров) и `RuntimeAbstraction`/`Adapter Layer` (переключение между Claude/OpenClaw/Hermes/Codex) — оба уже частично реализованы, но не описаны как единый сценарий "почему это вместе".

#### Режим 3 — Teamwork
Несколько пользователей, несколько агентов, один проект. Каждый участник может использовать свой инструмент (один — Claude Code по подписке, другой — OpenClaw, третий — Codex или Cursor с собственными API-ключами), и Buffy синхронизирует контекст между ними через MCP + ACP. Ключевая функция — разделение и переназначение задач: пользователь настраивает воркфлоу, кто за какую часть отвечает (например, backend/frontend), с переходом от "я один" к "нас трое, каждый со своим воркспейсом" по мере роста проекта, и с возможностью гибко переназначать зоны ответственности. Это то, для чего нужны `ACP Protocol` + `Bridge Layer` (уже production) + `Policy Engine` (в спецификации) — они уже реализованы по отдельности, но не связаны явной моделью "вот сценарий, ради которого это всё вместе".
