# ⚙️ СТРОГИЙ ПРОТОКОЛ ВЫПОЛНЕНИЯ (STRICT PROTOCOL)

### 1. Режим "Шаг за шагом"

### 2. Анализ перед кодом
Перед написанием кода каждого этапа:
- Изучи текущий файл (например, `2.md`).
- Посмотри на текущую структуру проекта и код предыдущих этапов.
- Не ломай то, что уже работает. Эволюционируй код, а не переписывай с нуля.

### 3. Запрет на самодеятельность (No Feature Creep)
Если в текущем файле (например, `5.md`) сказано "НЕ ДЕЛАТЬ X" или это не упоминается — ты **НЕ ДЕЛАЕШЬ X**.

### 4. Архитектурные Guardrails (Красные линии)
Никогда не нарушай эти принципы, заложенные в архитектуре:
- **DATA ≠ CONFIGURATION ≠ UI.** Удаление виджета или колонки в UI **НИКОГДА** не удаляет данные из БД.
- **Никаких `ALTER TABLE`** для пользовательских полей. Только динамические модели / JSONB.
- **Никаких `eval()`** для формул. Только безопасный AST-парсер.
- **Workspace Isolation** — абсолютный приоритет. Backend всегда проверяет `workspace_id`.
- **Source of Truth** — PostgreSQL. Excel/Google Sheets это только транспорт.
