PROMPT: PLUG & PLAY PROJECT MANAGEMENT OS

Роль

Ты — senior full-stack engineer + software architect + UX engineer.

Твоя задача — не просто создать CRUD-приложение, а спроектировать и реализовать гибкую операционную систему управления проектами и производством, в которой пользователь может самостоятельно менять рабочее пространство без изменения исходного кода.

Главный принцип продукта:

«Everything is configurable. Nothing in the workspace should be hardcoded if it can reasonably be configured.»

Пользователь должен иметь возможность:

- добавлять проекты;
- удалять/архивировать проекты;
- добавлять пользовательские колонки;
- удалять/скрывать колонки;
- создавать вычисляемые поля;
- создавать свои представления таблиц;
- добавлять/удалять/скрывать Dashboard-виджеты;
- менять порядок виджетов;
- изменять размеры виджетов;
- создавать собственные фильтры;
- создавать несколько Dashboard;
- сохранять конфигурацию интерфейса;
- возвращать скрытые элементы;
- импортировать данные из Excel;
- экспортировать данные в Excel;
- работать с Google Sheets;
- открывать проект в Drawer без ухода со страницы.

При этом:

«Удаление элемента интерфейса никогда не должно автоматически удалять реальные данные из базы.»

8. Пользовательские колонки

На странице «Проекты» пользователь нажимает:

+ Добавить колонку

Открывается интерфейс:

Название
[________________]

Тип
[ Выпадающий список ▼ ]

Значения
[ Новый ]
[ В работе ]
[ Завершён ]

[ Создать ]

После создания поле становится доступным в таблице.

Важно:

Custom Field не должен физически добавлять новую колонку PostgreSQL.

Не делать:

ALTER TABLE projects ADD COLUMN ...

для каждого пользовательского поля.

Используй безопасную динамическую модель данных.

Предпочтительно:

- metadata в "custom_fields";
- значения в "custom_field_values";
- либо оптимальная JSONB-гибридная архитектура, если она действительно лучше.

Выбери решение, которое обеспечивает:

- нормальную производительность;
- типизацию;
- фильтрацию;
- сортировку;
- миграции;
- экспорт;
- дальнейшее расширение.

Объясни выбор в архитектурной документации.

9. Formula Fields

Пользователь должен иметь возможность создать:

+ Добавить поле
→ Формула

Например:

Цена клиента
-
Себестоимость
=
Маржа

Или:

Количество × Цена
=
Стоимость

Не используй произвольный JavaScript/eval.

Никакого:

eval(user_input)

Формулы должны проходить через безопасный parser/AST или собственный ограниченный expression engine.

Разрешить базовые операции:

+
-
*
/
()

и безопасные функции:

SUM
MIN
MAX
ROUND
IF

При необходимости добавить:

DAYS_BETWEEN
TODAY

Пример:

quantity * unit_price

должен вычисляться системой.

Ошибочная формула не должна ломать страницу.

Показывать понятную ошибку:

Не удалось вычислить формулу:
Поле "Себестоимость" не заполнено.

Каждый widget должен иметь:

19. Удаление

Очень важное правило.

При удалении:

Удалить колонку

НЕ удалять данные автоматически.

Использовать:

is_active = false

или конфигурацию visibility.

То же самое для:

- widgets;
- fields;
- views.

Для проектов использовать:

archive

как безопасное удаление.

Физическое удаление данных должно быть отдельной административной операцией.

29. Anti-hardcoding

Проверь проект на следующие ошибки:

НЕ делать:

if widget == "calendar":
...
if widget == "tasks":
...
if widget == "risks":
...

в одном огромном компоненте.

НЕ делать:

const columns = [...]

как единственный источник истины для интерфейса.

НЕ делать:

ALTER TABLE

при создании пользовательской колонки.

НЕ делать:

eval()

для пользовательских формул.

НЕ делать Dashboard, который невозможно изменить без изменения исходного кода.

Не останавливайся на сообщении:

«"Implementation complete"»

если код не был реально проверен.

34. Финальный результат

В результате должно получиться приложение, которое пользователь воспринимает не как Excel-клон, а как:

«персонализируемое рабочее пространство для управления проектами.»

Основная идея:

                    WORKSPACE
                        │
          ┌─────────────┴─────────────┐
          │                           │
       DATA                    CONFIGURATION
          │                           │
    ┌─────┼─────┐             ┌───────┼────────┐
    │     │     │             │       │        │
 Projects Tasks Items       Fields  Views   Widgets
    │     │     │             │       │        │
    └─────┴─────┴─────────────┴───────┴────────┘
                        │
                        ▼
                  USER INTERFACE
                        │
          ┌─────────────┼──────────────┐
          │             │              │
      Dashboard      Projects       Calendar
          │             │              │
       Widgets        Drawer          Events

Ключевая философия:

«Данные стабильны.
Интерфейс изменяем.
Пользователь управляет представлением данных.
Удаление интерфейсного элемента не уничтожает данные.
Добавление нового поля не требует изменения схемы БД.
Добавление нового Dashboard не требует изменения кода.
Добавление нового Widget происходит через Widget Registry.»
