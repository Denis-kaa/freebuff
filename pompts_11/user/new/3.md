PROMPT 03 — PROJECT DRAWER, PROJECT ITEMS, PRODUCTION & TASKS

Контекст

Предыдущие этапы создали:

- базовую архитектуру;
- PostgreSQL;
- Projects;
- Custom Fields;
- динамические колонки;
- Saved Views;
- фильтры;
- базовый Project Drawer.

Теперь необходимо превратить карточку проекта в полноценный рабочий центр менеджера.

Главный принцип:

«Project — это контейнер заказа. Project Item — конкретная производственная позиция внутри заказа.»

Например:

Проект P024 — Wazzup

├── Худи — 100 шт
├── Футболки — 150 шт
├── Кепки — 50 шт
└── Носки — 200 шт

У каждой позиции должны быть собственные производственные данные.

НЕ пытайся хранить всё это в одной строке проекта.

8. Production Status

Не смешивай все статусы в один общий "stage".

У проекта может быть:

stage = Производство

но отдельные позиции могут находиться:

Худи → Тираж
Футболка → Макет
Кепка → Отгрузка

Поэтому Project Item имеет собственное состояние.

12. Task ↔ Project

Каждая задача должна иметь:

project_id

При необходимости:

Например:

Худи

Такую задачу потом можно показать:

- в Project Drawer;
- в общем списке задач;
- в Dashboard;
- в Calendar.

13. Next Action

Поле:

Следующее действие

НЕ должно быть просто красивым текстом.

Используй его как оперативный слой.

Пример:

Получить ОС по сигналу от клиента

В Dashboard и Calendar можно будет ссылаться на это значение.

Но не превращай "next_action" в замену полноценным Tasks.

Разница:

Next Action
=
быстрое текущее действие проекта

Task
=
полноценная задача с ответственным, сроком и статусом

14. Автоматизация Next Action

Подготовь архитектуру для будущего автоматического предложения следующего действия.

Например:

Если:
signal_status = SENT
и
signal_feedback = EMPTY

Предложить:
"Получить ОС по сигналу"

Но на данном этапе НЕ обязательно реализовывать AI.

Создай сервисный слой:

NextActionService

чтобы позднее туда можно было подключить rule engine или AI.

22. Project Health

Подготовь вычисляемый Project Health.

Например:

Healthy
Attention
At Risk
Critical

Основываться может на:

- просроченном дедлайне;
- незакрытых задачах;
- отсутствии ОС;
- проблемах производства;
- оплате;
- риске.

Но не создавай сложную AI-систему.

Сначала простой deterministic rule engine.

Например:

deadline overdue
→ At Risk

risk_level = critical
→ Critical

Архитектуру сделать расширяемой.

24. Transactions

Операции, затрагивающие несколько сущностей, должны быть transactional.

Например:

Create Project
+
Create Items
+
Create Tasks

Если операция падает — не оставлять половину данных.

---

25. Optimistic locking

Подготовь защиту от ситуации:

Менеджер A открыл P024

Менеджер B изменил P024

Менеджер A сохраняет старые данные

Не должен происходить silent overwrite.

Можно использовать:

updated_at

или version number.

При конфликте:

Проект был изменён другим пользователем.
Обновите данные перед сохранением.

34. Не делать

НЕ создавать:

одну гигантскую таблицу projects

с десятками полей:

item1_status
item2_name
item2_status
item3_name
...

Это запрещено.

НЕ делать ограничение:

maximum 5 items

НЕ смешивать:

Project Status

и:

Production Status

НЕ удалять данные при удалении UI-компонента.

НЕ хранить документы в PostgreSQL blob без необходимости.

НЕ делать второй Audit Log.

35. Финальный отчёт

После завершения предоставь:

1. Что реализовано
2. Какие файлы изменены
3. Какие модели добавлены
4. Какие migrations добавлены
5. Какие API endpoints добавлены
6. Как устроены Project Items
7. Как устроен Production workflow
8. Как связаны Tasks и Projects
9. Как устроены Documents
10. Как устроены Events
11. Какие тесты добавлены
12. Результаты тестов
13. Что осталось
14. Какие архитектурные решения приняты

Не объявляй этап завершённым, пока acceptance scenario реально не проходит.

Главная цель:

«Project Drawer должен стать рабочим центром менеджера: открыть проект → за несколько секунд увидеть состояние → понять следующее действие → посмотреть производство → задачи → документы → изменить данные.»

После этого следующий этап будет посвящён Dashboard Engine, который будет брать эти данные и превращать их в полностью настраиваемое рабочее пространство.
