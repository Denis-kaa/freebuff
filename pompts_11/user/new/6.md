PROMPT 06 — IMPORT / EXPORT ENGINE: EXCEL + GOOGLE SHEETS

Контекст

В предыдущих этапах реализованы:

- Workspace;
- Projects;
- Project Items;
- Production;
- Tasks;
- Documents;
- Dashboard Engine;
- Plug & Play Widgets;
- Calendar & Events Engine;
- Project Drawer.

Теперь необходимо реализовать универсальный Import / Export Engine.

Главная цель:

«Пользователь должен иметь возможность свободно обмениваться данными между веб-приложением, Excel и Google Sheets, не ломая внутреннюю реляционную структуру базы.»

---

1. Главный принцип

Excel и Google Sheets — это внешний формат данных.

Они НЕ должны становиться источником истины приложения.

Источник истины:

PostgreSQL

Схема:

Excel
   ↓
Import Parser
   ↓
Validation
   ↓
Mapping
   ↓
Preview
   ↓
Import
   ↓
PostgreSQL

Экспорт:

PostgreSQL
   ↓
Export Service
   ↓
Flatten / Mapping
   ↓
.xlsx / .csv

Google Sheets:

Google Sheets
   ↕
Sync / Import / Export Layer
   ↕
PostgreSQL

53. No Data Loss Principle

Ни один импорт не должен:

- молча удалять данные;
- молча перезаписывать данные;
- молча менять типы;
- молча создавать дубликаты.

Любое потенциально разрушительное действие:

Preview

Confirmation

ГЛАВНАЯ АРХИТЕКТУРНАЯ ЦЕЛЬ

Пользователь должен иметь ощущение:

««Мои данные принадлежат мне, и я могу свободно забрать их из системы».»

Он может:

Excel
  ↓
App
  ↓
PostgreSQL
  ↓
Dashboard
  ↓
Calendar

и обратно:

App
 ↓
Excel

или:

App
 ↕
Google Sheets

При этом внутренняя система остаётся нормальной реляционной БД, а Excel/Google Sheets являются только внешними интерфейсами обмена данными.

Главный принцип:

«Не адаптировать архитектуру приложения под Excel. А адаптировать Excel к архитектуре приложения.»
