PROMPT 09 — USERS / ROLES / PERMISSIONS / WORKSPACE ACCESS

Контекст

В предыдущих этапах реализованы:

- Workspace;
- Projects;
- Project Items;
- Production;
- Tasks;
- Documents;
- Dashboard Engine;
- Plug & Play Widgets;
- Calendar;
- Import / Export;
- Search / Filters / Saved Views;
- Custom Fields;
- Formula Engine;
- Notifications;
- Automation Engine;
- Risk Engine;
- Event System.

Теперь необходимо реализовать полноценную систему пользователей, ролей и прав доступа.

Главная идея:

«Один Workspace может использоваться несколькими людьми, но каждый пользователь должен видеть и изменять только то, что ему разрешено.»

ГЛАВНАЯ ЦЕЛЬ

После этого этапа приложение должно быть настоящей многопользовательской системой:

                WORKSPACE
                    │
        ┌───────────┼───────────┐
        ↓           ↓           ↓
      Owner       Manager      Viewer
        │           │           │
      ALL         WORK        READ
        │           │           │
        └───────────┼───────────┘
                    ↓
               PROJECTS
                    ↓
              TASKS / ITEMS
                    ↓
             PRODUCTION
                    ↓
               DOCUMENTS
                    ↓
                FINANCE

Главный принцип:

«Безопасность должна существовать на backend уровне. Frontend только отражает доступы, но никогда не является механизмом защиты.»

Второй принцип:

«Workspace должен быть полностью изолирован. Пользователь никогда не должен получить данные другого Workspace просто изменив ID в URL или API-запросе.»

Третий принцип:

«Permissions должны быть универсальными и переиспользуемыми всеми будущими модулями, Dashboard Widgets, Views, Automations, Import/Export и AI-функциями.»
