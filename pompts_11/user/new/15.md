PROMPT 15 — IMPORT / EXPORT: EXCEL + GOOGLE SHEETS

Контекст

Продолжаем разработку Workspace-приложения для управления проектами и производством мерча.

Архитектура уже содержит:

- Projects;
- Project Items;
- Tasks;
- PaymentInfo;
- DocumentStatus;
- Dashboard;
- Plug & Play Widgets;
- Dynamic Columns;
- Custom Fields;
- Universal Views;
- Table / Calendar / Board;
- Filters;
- Sorting;
- Grouping;
- Saved Views;
- Universal Entity Drawer.

Главный принцип:

«Workspace имеет собственную нормализованную модель данных. Excel и Google Sheets являются внешними форматами обмена данными, а не источником истины.»

Не ломать существующую архитектуру.

Не превращать приложение в Excel-клон.

---

1. ЦЕЛЬ ЭТАПА

Реализовать полноценный обмен данными между Workspace и:

1. Excel ".xlsx";
2. CSV;
3. Google Sheets.

Необходимо поддержать:

- экспорт;
- импорт;
- сопоставление колонок;
- импорт Custom Fields;
- предварительный просмотр;
- валидацию;
- отчёт об ошибках;
- безопасное обновление существующих записей;
- создание новых записей;
- защиту от случайной перезаписи данных.

---

2. SOURCE OF TRUTH

Основной источник данных:

PostgreSQL / Workspace.

Excel и Google Sheets:

External Data Sources.

Никогда не делать:

Excel → автоматически полностью заменить БД.

Вместо этого:

Import
→ Parse
→ Mapping
→ Validation
→ Preview
→ User Confirmation
→ Transaction
→ Database

21. IMPORT STRATEGY

Пользователь выбирает:

Создавать только записи, которых нет.

Только обновления

Не создавать новые записи.

22. MATCHING

Для определения существующей записи использовать стабильный идентификатор.

Приоритет:

1. внутренний UUID;
2. display_id;
3. другой явно заданный уникальный ключ.

Никогда не использовать название проекта как единственный надёжный ID.

Например:

P024

должен находить:

Project.display_id = P024

38. EXCEL FORMATTING

Экспортируемый Excel должен быть аккуратным:

- frozen header;
- auto filter;
- разумная ширина колонок;
- даты в нормальном формате;
- числовые значения как числа;
- проценты как значения/формат в зависимости от модели;

52. DEFINITION OF DONE

Этап считается завершённым, если:

- работает Excel Export;
- работает Excel Import;
- работает CSV;
- работает Google Sheets Export;
- работает Google Sheets Import;
- существует Mapping;
- существует Auto-Mapping;
- существует Preview;
- существует Validation;
- существует Dry Run;
- ошибки отображаются понятно;
- существует Import History;
- Custom Fields импортируются;
- Custom Fields экспортируются;
- Project Items не теряются;
- Tasks не теряются;
- связи между сущностями сохраняются;
- существующие записи можно обновлять;
- новые записи можно создавать;
- ID не дублируются;
- импорт транзакционный;
- permissions проверяются;
- Workspace isolation работает;
- Excel и Google Sheets используют общий Import Pipeline;
- существующие Views не ломаются;
- существующий Universal Drawer не ломается;
- существующий Dashboard не ломается.

Главный принцип:

«Excel и Google Sheets — это транспорт данных, а не вторая база данных.»

Workspace остаётся единой системой истины.

Любой внешний источник должен проходить через один и тот же:

Adapter → Mapping → Validation → Preview → Commit

Это позволит в будущем добавить другие источники данных без переписывания всей архитектуры.
