PROMPT 12 — PLUG & PLAY WORKSPACE / ДИНАМИЧЕСКИЙ ИНТЕРФЕЙС

Контекст проекта

Мы создаём веб-приложение для управления проектами и производством мерча.

Основной стек:

Frontend

- Next.js App Router
- React
- TypeScript
- Tailwind CSS
- shadcn/ui
- Lucide Icons

Backend

- Python 3.11+
- FastAPI
- PostgreSQL
- SQLAlchemy 2.0 async
- Pydantic v2
- Alembic

Уже существуют/проектируются:

- Projects
- Project Items
- Tasks
- Payment
- Documents
- Dashboard
- Project Drawer
- Excel Import/Export

Но приложение должно проектироваться не как жёстко зашитая CRM.

Главная архитектурная идея:

«Это рабочее пространство, которое пользователь может сам собирать и перестраивать под себя.»

Необходимо реализовать первый слой этой системы:

PLUG & PLAY UI

Пользователь должен иметь возможность:

- добавлять виджеты;
- удалять виджеты;
- менять порядок виджетов;
- менять размер виджетов;
- скрывать/показывать виджеты;
- добавлять колонки в таблицу;
- удалять колонки;
- менять порядок колонок;
- создавать собственные поля;
- добавлять строки/записи;
- редактировать существующие записи;
- сохранять настройки своего рабочего пространства.

При этом базовые данные приложения не должны зависеть от конкретного расположения элементов интерфейса.

21. FORMULA ARCHITECTURE

Ты отдельно упоминал возможность добавлять строки/колонки с формулами.

На этом этапе не делать полноценный Excel.

Но архитектуру заложить.

Custom field должен потенциально поддерживать:

field_type = formula

Формула должна вычисляться сервером или безопасным expression engine.

Никогда не выполнять:

eval(user_input)

3

ГЛАВНАЯ ЦЕЛЬ ЭТОГО ЭТАПА

Не сделать красивый Dashboard.

А создать фундамент, на котором Dashboard можно пересобирать без переписывания приложения.

Пользователь должен постепенно получить ощущение:

Это МОЁ рабочее пространство.

Он сам решает:

что видеть
что скрыть
что добавить
в каком порядке
какие поля нужны
какие виджеты нужны
какое представление проектов использовать

При этом:

Бизнес-данные
        ↓
остаются стабильными

UI
        ↓
становится конфигурируемым

Это базовый принцип всей дальнейшей архитектуры Workspace.
