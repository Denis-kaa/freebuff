Отличная идея! Добавление пула воркеров (worker pool) с очередью задач — это профессиональный подход, который предотвратит зависание сервера при одновременной загрузке и конвертации нескольких файлов. 

Вот **обновленная версия промта**, в которую интегрирована архитектура очереди задач и пул из 3–5 воркеров для конвертации.

### Промт для разработки веб-приложения "Torrent-DL Web" (с архитектурой воркеров)

**Роль:** Ты опытный Full-Stack разработчик и архитектор. Твоя задача — спроектировать и написать код для веб-приложения для скачивания и конвертации торрентов с использованием асинхронной очереди задач и пула воркеров.

**1. Основная цель**
Создать веб-приложение, которое позволяет добавлять торренты, выбирать файлы, скачивать их и автоматически конвертировать медиа (видео/аудио) в MP4/MP3. Ключевое требование: **конвертация должна выполняться асинхронно через пул воркеров (от 3 до 5 одновременных процессов)**, чтобы скачивание новых торрентов не блокировалось тяжелыми задачами конвертации, и наоборот.

**2. Рекомендуемый стек технологий**
*   **Frontend:** React (Next.js) или Vue 3 + Tailwind CSS (адаптивный UI, темная тема).
*   **Backend:** Node.js (Express/NestJS) или Python (FastAPI).
*   **Очередь задач и Воркеры:** 
    *   *Для Node.js:* Redis + **BullMQ** (с настройкой `concurrency: 5`).
    *   *Для Python:* Redis + **Celery** (с настройкой `worker_concurrency=5`).
*   **База данных:** SQLite (для простоты) или PostgreSQL (для хранения истории и статусов задач).
*   **Real-time:** WebSockets (Socket.io) или Server-Sent Events (SSE) для обновления прогресса загрузки и конвертации в реальном времени.
*   **Инфраструктура:** Docker & Docker Compose (обязательно включает сервисы: `app`, `worker`, `redis`, `db`).

**3. Требования к функционалу**

**3.1. Добавление задач (Input)**
*   Веб-форма с вкладками: Magnet-ссылки (множественный ввод), URL на `.torrent`, Drag-and-drop зона для локальных `.torrent` файлов.
*   Кнопка "Анализировать": бэкенд получает метаданные торрента *без* начала скачивания (через `aria2c --bt-metadata-only` или парсинг файла).

**3.2. Интерактивный выбор файлов (до скачивания)**
*   Frontend отображает таблицу файлов с чекбоксами, размерами и индексами.
*   Инструменты: "Выбрать все", "Снять выделение", ввод диапазонов (например, `1-5, 8`).
*   Динамический подсчет "Общий размер выбранных файлов".
*   Кнопка "Начать загрузку" (активируется после выбора).

**3.3. Процесс скачивания (Download Manager)**
*   Использование `aria2c` (через RPC или child_process) с оптимизациями: `--seed-time=0`, `--max-connection-per-server=16`, `--split=16`, `--file-allocation=none`.
*   Скачивание только выбранных файлов (`--select-file`).
*   Отправка прогресса (%, скорость, ETA) на фронтенд через WebSockets.
*   Проверка свободного места на диске перед стартом. Если места мало → отмена с понятной ошибкой.

**3.4. Конвертация через Пул Воркеров (Post-processing Queue)**
*   **Триггер:** Как только загрузка файла завершается, бэкенд автоматически создает задачу на конвертацию и помещает её в Redis-очередь.
*   **Воркеры:** Запущено от 3 до 5 независимых воркеров (процессов), которые слушают эту очередь.
*   **Логика воркера:** 
    1. Берет задачу из очереди.
    2. Читает выбранный пресет конвертации (см. ниже).
    3. Запускает `ffmpeg` как дочерний процесс.
    4. Стримит прогресс конвертации этого конкретного файла в БД и по WebSocket на фронтенд.
    5. По завершении: обновляет статус задачи на "Готово", освобождает слот воркера для следующей задачи.
*   **Пресеты конвертации (выбираются пользователем перед стартом):**
    1. 🚀 **Быстрый:** `-c copy` (смена контейнера, мгновенно).
    2. 🐌 **Минимальный размер:** CRF 32, preset slow, аудио 96k.
    3. ⚡ **Средний:** CRF 28, preset fast, аудио 128k.
    4. ⭐ **Баланс (по умолчанию):** CRF 23, preset ultrafast, аудио 192k.
    5. 💎 **Высокое качество:** CRF 18, preset medium, аудио 256k.
*   **Субтитры:** Опция "Извлечь в .srt", "Встроить в MP4 (softsub)" или "Игнорировать".
*   **Очистка:** Опция "Удалить исходный файл после успешной конвертации".

**3.5. Управление и История (Dashboard)**
*   Главная панель: карточки активных задач с четким разделением статусов: `Загрузка...`, `В очереди на конвертацию (позиция N)`, `Конвертация... (воркер #X)`, `Готово`, `Ошибка`.
*   Вкладка "История": таблица завершенных задач с возможностью скачать результат через браузер, удалить файлы с сервера или посмотреть логи ошибки.

**3.6. Уведомления**
*   Всплывающие Toast-уведомления в UI.
*   Поддержка Browser Push Notifications о завершении всей пакетной обработки.

**3.7. Безопасность, Ресурсы и Обработка ошибок**
*   **Мониторинг ресурсов:** Воркер должен проверять загрузку CPU/RAM. Если 5 процессов `ffmpeg` нагружают систему на >90%, новый воркер может временно приостановить взятие задач (throttling).
*   **Валидация:** Строгая проверка путей (защита от Path Traversal). Имена файлов должны санитизироваться.
*   **Graceful shutdown:** При остановке Docker-контейнера воркеры корректно завершают текущие `ffmpeg` процессы, а `aria2c` ставится на паузу. Неполные файлы помечаются как "поврежденные" или удаляются.
*   **Изоляция:** Папки `/downloads` и `/converted` должны быть корректно проброшены в контейнер воркера.

**4. Структура проекта (Docker Compose)**
```text
/app
  ├── docker-compose.yml        # Сервисы: frontend, backend, worker, redis, db
  ├── backend/
  │   ├── src/
  │   │   ├── routes/           # API для добавления торрентов, истории
  │   │   ├── services/         # aria2-wrapper, queue-producer
  │   │   ├── workers/          # ffmpeg-conversion-worker (логика пула)
  │   │   └── db/               # Схема БД (задачи, файлы, история)
  │   └── package.json / requirements.txt
  ├── frontend/
  │   └── src/                  # Компоненты: QueueStatus, FileSelector, ProgressBar
  └── data/
      ├── /downloads            # Временные файлы (aria2)
      └── /converted            # Готовые файлы (доступны для скачивания)
```

**5. Переменные окружения (.env)**
*   `DOWNLOAD_DIR=/app/data/downloads`
*   `CONVERT_DIR=/app/data/converted`
*   `DEFAULT_QUALITY=4`
*   `MAX_CONVERSION_WORKERS=5`  # Лимит одновременных задач конвертации
*   `REDIS_URL=redis://redis:6379`
*   `PORT=3000`

**6. Критерии готовности (Чек-лист)**
- [ ] Фронтенд позволяет вставить магнет и получить список файлов до загрузки.
- [ ] Можно выбрать файлы чекбоксами или диапазоном.
- [ ] Загрузка идет через aria2c, прогресс виден в реальном времени.
- [ ] **Реализована очередь задач (Redis + BullMQ/Celery).**
- [ ] **Конвертация выполняется пулом из 3–5 воркеров параллельно, не блокируя основной API.**
- [ ] Прогресс конвертации каждого файла отображается в UI независимо.
- [ ] Готовые файлы можно скачать через браузер.
- [ ] Приложение полностью развертывается одной командой `docker-compose up -d`.

### Что изменилось и почему это лучше:
1. **Четкое разделение ответственности:** Основной веб-сервер (API) только принимает запросы и управляет `aria2`. Тяжелую работу делает отдельный сервис `worker`.
2. **Масштабируемость:** Если сервер мощный, вы можете просто поменять `.env` переменную `MAX_CONVERSION_WORKERS=8`, и система начнет использовать больше ядер CPU без переписывания кода.
3. **Надежность:** Если один процесс `ffmpeg` упадет с ошибкой, воркер перехватит ошибку, пометит задачу как `FAILED` и сразу возьмет следующую из очереди, не "роняя" всё приложение.
4. **Прозрачность для пользователя:** Пользователь видит честный статус: "Скачивание завершено, файл 3-й в очереди на конвертацию", что снимает вопросы "почему ничего не происходит".
