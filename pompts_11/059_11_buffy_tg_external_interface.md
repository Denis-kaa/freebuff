# ЗАДАЧА: Система промтов с диспетчером и TG-ботом

> ⚠️ **Clarification (2026-08-04, v5.74.0):** этот промт — про построение **внешнего интерфейса** к системе Freebuff. **Баффи = ИИ-мозг Freebuff**. Цель — не «запустить Баффи как subprocess», а «дать пользователю управлять системой Freebuff со смартфона, когда платформа (Workspace OS) уже скачана на телефон из облака и работает on-device». Подробнее — CORE_PROMPT §1 + BUFFY.md identity section + ADR-012.

## ЦЕЛЬ

Построить **внешний интерфейс взаимодействия** с ИИ-мозгом системы (Баффи/Freebuff), в котором:
0. **Контекст:** пользователь уже скачал платформу (Workspace OS = Freebuff) на телефон из облака; система запущена на Termux; нужно управлять ею извне, не только через локальный терминал.
1. Пользователь пишет в Telegram `/task <текст>` — промт сохраняется в `pompts_11/user/` как .md файл (файловая очередь = прокси-канал между Telegram и системой)
2. Диспетчер подхватывает промты из очереди, передаёт их Баффи (ИИ-мозгу Freebuff) на исполнение
3. Отчёт о выполнении возвращается в Telegram (в тот же чат + в Избранное) + хранится в `docs_10/e2e_logs/promt48_*.md`
4. Исполненные промты помечаются и не выполняются повторно

## КОНТЕКСТ

Ты работаешь в Termux на Android. Проект: Workspace OS (Buffy).
- Папка промтов уже существует: `pompts_11/`
- TG-бот уже есть: `scripts_01/telegram_bot.py`, `scripts_01/tgbot_base.py`, `plugins_04/tg_messenger/`
- Оркестратор уже есть: `scripts_01/orchestrator.py`
- Event bus уже есть: `scripts_01/event_bus.py`
- Баффи запускается через: `freebuff_cli.py`

Изучи существующие компоненты ПЕРЕД тем, как писать новый код. Используй то, что уже работает. Не дублируй.

## ПРАВИЛА

1. **Разберись сам.** Прочитай существующие файлы, определи структуру, пойми как запускается Баффи. Не спрашивай меня о том, что можешь определить сам.

2. **Reuse First.** Расширяй существующее, не создавай с нуля. Если `telegram_bot.py` уже умеет принимать команды — добавь команду `/task` туда, не пиши нового бота.

3. **Простота.** Не строй архитектуру на вырост. Нужно: папка user/ → диспетчер → Баффи → отчёт в TG. Всё.

4. **Детерминированность.** Статусы промтов (pending/running/done/failed) — через перемещение файлов между папками, не через БД. Это проще и надёжнее в Termux.

5. **Бесперебойность.** Реши сам, как лучше: cron, nohup, или автозапуск при открытии Termux. Учти, что Termux может быть убит Android. Предложи решение, которое реально работает.

## ЧТО НУЖНО СДЕЛАТЬ

1. **Определи окружение:** что уже есть, что работает, что нужно доработать.
2. **Спроектируй структуру:** папки промтов (user/running/done/failed), формат .md файла, приоритеты.
3. **Реализуй диспетчер:** скрипт, который берёт промты из user/, запускает Баффи, перемещает в done/ или failed/.
4. **Подключи TG-бот:** команда `/task <текст>` создаёт промт, отчёт возвращается в чат.
5. **Настрой бесперебойность:** чтобы диспетчер работал без ручного запуска.
6. **Напиши тесты:** хотя бы минимальные, чтобы проверить цикл.
