 Да. Я бы сделал ТЗ не просто на «мобильную версию сайта», а именно на mobile-first клиент Workspace OS, потому что у тебя мобильный интерфейс выполняет отдельную роль: быстрый захват мыслей + доступ к Workspace, а не попытка вместить весь desktop.

ТЗ — Workspace OS Mobile

React / Mobile-first Frontend v0.1

1. Цель

Создать мобильный frontend Workspace OS на React, оптимизированный прежде всего под:

1. быстрый захват Whim;


2. просмотр последнего Whim и истории;


3. доступ к Workspaces;


4. переход внутрь Workspace;


5. работу с Projects;


6. доступ к файловому менеджеру;


7. взаимодействие с AI/Chat;


8. работу при нестабильном или отсутствующем соединении;


9. последующую синхронизацию с desktop/tablet через backend relay.



Главный принцип:

> Mobile ≠ уменьшенный Desktop.



Мобильный интерфейс должен иметь собственную композицию и приоритеты.

8. Offline-first

Mobile приложение должно быть способно работать без постоянного соединения.

Минимально локально сохраняются:

Whims;

Workspace metadata;

Project metadata;

локальный sync state;

pending operations.


Например:

Whim
status:
  local
  pending_sync
  synced
  conflict

9. Sync

Backend рассматривается как Sync / Relay Layer.

PHONE
  │
  │ event
  ▼
SERVER
  │
  │ pending event
  ▼
DESKTOP

Server не должен быть обязательным местом хранения всей пользовательской рабочей среды.

Frontend должен работать через абстракцию:

SyncService

а не напрямую зависеть от конкретной реализации backend.

24. Security

Frontend:

никогда не хранит API secrets.

Не помещать в:

.env
frontend bundle
localStorage
source code

секреты backend/API.

Для authentication использовать безопасный механизм session/token, определённый backend-контрактом.

26. MVP Acceptance Criteria

Мобильный клиент считается готовым, если пользователь может:

Whim

открыть приложение;

одним действием создать текстовый Whim;

одним действием записать голосовой Whim;

увидеть последний Whim;

открыть историю;

работать с Whim offline.


Workspace

увидеть свои Workspaces;

открыть Workspace;

увидеть проекты;

создать проект.


Project

открыть проект;

увидеть его контекст;

открыть Chat;

открыть Files.


Sync

создать Whim offline;

закрыть приложение;

восстановить соединение;

автоматически отправить Whim;

увидеть статус Synced.



---

27. Ключевой UX-принцип

Вся мобильная версия должна отвечать на три вопроса:

«Что я сейчас делаю?»

→ текущий Workspace / Project.

«Что я только что придумал?»

→ последний Whim.

«Мне пришла новая мысль!»

→ одна кнопка Whim.

И именно третье я бы сделал самым быстрым действием во всём приложении.

Самая важная мысль: мобильный клиент здесь не должен пытаться показать пользователю всю Workspace OS. Он должен быть карманным входом в неё: поймал мысль → Whim; посмотрел, где работа → Workspace; открыл конкретную работу → Project. Остальное раскрывается только по мере необходимости.
