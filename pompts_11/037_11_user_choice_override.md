## 🎯 11-й канонический принцип: **User-Choice Override**

### Суть:
> **Система рекомендует, но пользователь выбирает.**

Пользователь должен иметь возможность:
1. **Назначить конкретную модель/агента** для каждого вида задач (capability)
2. **Переопределить автоматический выбор системы** в любой момент
3. **Использовать бесплатные ключи** (Qwen, Ollama, локальные модели)
4. **Миксовать провайдеров** (Claude для архитектуры, DeepSeek для кода, Gemini для исследований, Qwen для простых задач)

### Как это работает:

**Автоматический режим (по умолчанию):**
```
Пользователь: "Напиши код для API"
Система (Policy Engine): 
  → Capability: "coding"
  → Рекомендация: Claude Code (score 0.95)
  → Fallback: DeepSeek (score 0.85)
  → Используется: Claude Code
```

**Ручной режим (переопределение):**
```
Пользователь: "Напиши код для API, но используй DeepSeek"
Система:
  → Capability: "coding"
  → Пользователь переопределил: DeepSeek
  → Используется: DeepSeek (даже если score ниже)
```

## 📋 Обновлённые 11 канонических правил

Добавляем **правило 11** и уточняем **правило 7**:

### Правило 7 (уточнённое): **Delegation & Priority Engine (DPE)**
Ассистент — **не универсальный исполнитель**, а **делегатор**:
- Оценивает вес (weight) и приоритет (priority) задачи
- Сверяет с возможностями ролей (Role Capabilities)
- **Рекомендует** исполнителя на основе Policy Engine
- **НО:** Пользователь может переопределить выбор в любой момент

### Правило 11 (новое): **User-Choice Override**
Пользователь всегда имеет право выбрать исполнителя:
- Может назначить конкретную модель/агента для каждой capability
- Может переопределить автоматический выбор системы
- Может использовать бесплатные ключи (Qwen, Ollama, локальные модели)
- Может миксовать провайдеров (Claude для архитектуры, DeepSeek для кода, Gemini для исследований)

**Пример:**
```yaml
# config.yaml (User Preferences)
capabilities:
  coding:
    preferred: deepseek-v4-flash
    fallback: claude-code
  architecture:
    preferred: claude-code
    fallback: gemini-2.5-flash
  research:
    preferred: gemini-2.5-flash
    fallback: openclaw
  documentation:
    preferred: claude-code
    fallback: qwen-2.5:7b
```

## 11 КАНОНИЧЕСКИХ ПРАВИЛ (ЗАФИКСИРОВАТЬ)

1. **Иерархия:** Workstation (оболочка) → Workspace (сфера: Работа/Хобби/Личное) → Project (цель: Сайт/CRM/Блог).
2. **Work Area как View:** Это НЕ папка и НЕ сущность. Это динамический список проектов, связанных с конкретным Resource (нажал на Telegram → увидел все проекты с Telegram).
3. **Режимы работы:** SINGLE, COWORK, TEAM (параллельные ветки с разной изоляцией). COMMUNITY — будущее.
4. **Workspace Owner:** Создатель видит всё и управляет ролями.
5. **Context Isolation:** Участники видят только данные своей роли (сантехник не видит бухгалтерию).
6. **Presence-aware Delegation:** Система сама назначает задачу тому, кто онлайн и имеет нужную роль.
7. **DPE (Delegation & Priority Engine):** Ассистент — не исполнитель, а делегатор. Оценивает приоритет, рекомендует исполнителя на основе Policy Engine, **НО пользователь может переопределить выбор**.
8. **Context-Aware Routing:** Перед созданием задачи проверить Knowledge/Graph/Task System. Не создавать дубли.
9. **Плагины:** Архитектура есть. Нужен Plugin Contract Specification.
10. **Философия Knowledge as Byproduct:** Пользователь работает, система сама строит знания. Заметки — не точка входа. Точка входа — "Продолжить работу над проектом".
11. **User-Choice Override:** Пользователь всегда может выбрать исполнителя (модель/агента) для каждой capability. Система рекомендует, но не навязывает. Поддержка множества провайдеров (Claude, DeepSeek, Gemini, Qwen, Ollama и т.д.) и бесплатных ключей.
