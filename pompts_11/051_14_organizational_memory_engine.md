# MISSION: Проектирование Organizational Memory Engine (следующая эволюция платформы)

## КОНТЕКСТ

После архитектурного анализа принято решение отказаться от развития Lessons Memory Engine как отдельной подсистемы.

Вместо этого платформа переходит к более общей модели:

# Organizational Memory Engine

Lessons становятся лишь одним из типов знаний.

Архитектура должна быть рассчитана на развитие в течение нескольких лет без изменения базовой модели.

Главная цель —

создать единый слой памяти платформы,
который способен хранить опыт, решения, правила, процессы и любые другие знания,
используя уже существующую инфраструктуру проекта.

Запрещается проектировать систему вокруг одной сущности (Lesson).

Система должна строиться вокруг памяти организации.

---

# ЗАДАЧА 1. Architectural Fit Check (AFC)

Перед проектированием провести AFC.

Изучить существующие компоненты:

- knowledge_engine
- graph_index
- arch_decisions
- lessons
- event_log
- context.db
- Knowledge Index

Определить:

• что уже существует;

• что необходимо расширить;

• что нельзя ломать;

• какие компоненты становятся частью Organizational Memory.

# ЗАДАЧА 3. Универсальная модель Knowledge Object

Вместо специализированной таблицы lessons
предложить универсальную модель Knowledge Object.

Минимально предусмотреть поддержку типов:

- ADR
- Lesson
- Pattern
- Rule
- Observation
- Candidate
- Checklist
- Guideline
- FAQ
- Workflow

Архитектура должна позволять добавлять новые типы без изменения схемы данных.

---

Провести ревизию структуры хранения.

Проверить необходимость нормализации:

- tags
- source_files
- relations
- references

При необходимости предложить отдельные таблицы связей.

Аргументировать каждое изменение.

# ЗАДАЧА 8. Семантический слой

Не создавать новый движок.

Использовать существующий Knowledge Engine.

Предложить механизм индексации Organizational Memory.

Определить:

какие поля индексируются;

что используется в поиске;

что передаётся в RAG.

---

# ЗАДАЧА 9. Learning Loop

Спроектировать механизм самообучения.

Каждое использование Knowledge Object должно влиять на его качество.

Система должна учитывать:

• помогло;

• не помогло;

• устарело;

• противоречит новому опыту;

• подтверждено повторно.

Предложить механизм обновления confidence.

---

# ЗАДАЧА 10. Experience Analytics

Спроектировать аналитический слой.

Платформа должна уметь отвечать на вопросы:

Какие знания используются чаще всего?

Какие знания перестали быть актуальными?

Какие знания противоречат друг другу?

Какие Observation чаще всего становятся Lessons?

Какие Lessons никогда не используются?

Какие проблемы повторяются чаще всего?

Какие решения наиболее успешны?
