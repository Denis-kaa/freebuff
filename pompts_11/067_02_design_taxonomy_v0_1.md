ЗАДАЧА 01 — DESIGN TAXONOMY v0.1

Ты работаешь как Senior Design Systems Researcher / Design Taxonomist.

Мы создаём Design Blueprint Engine — детерминированный мастер, который помогает человеку без профессиональной дизайнерской насмотренности пошагово сформировать дизайн сайта.

Ключевой принцип:

«Пользователь не должен знать профессиональную терминологию. Он должен выбирать глазами или по простому человеческому описанию. Система затем детерминированно переводит выбор в конкретные дизайн-параметры.»

Сейчас НЕ создавай приложение, код или prompt.

Твоя задача — разработать DESIGN TAXONOMY v0.1: карту всех дизайн-параметров, которые необходимо определить для формирования качественного Website Design Blueprint.

1. Определи категории

Исследуй и предложи категории уровня:

- Visual Style
- Mood / Emotional Direction
- Typography
- Color
- Iconography
- Shapes / Geometry
- Layout / Grid
- Spacing / Density
- Navigation
- Buttons
- Cards
- Forms
- Imagery
- Illustration
- Decorative Elements
- Motion / Animation
- Interaction
- Content Presentation
- Responsive Behaviour
- Accessibility
- AI-Template Avoidance / Anti-Patterns

Но НЕ принимай этот список как окончательный.

Проверь, какие категории действительно нужны, какие следует объединить, разделить или добавить.

2. Для каждой категории определи

- CATEGORY_ID
- название для пользователя
- внутреннее техническое название
- что именно эта категория контролирует
- почему она влияет на визуальный результат
- какие решения внутри неё должен принимать пользователь
- какие решения можно детерминированно вывести из других выбранных параметров
- какие параметры нельзя оставлять на усмотрение LLM

3. Отдели независимые параметры от производных

Это критически важно.

Например:

USER CHOICE:
"Выразительные заголовки"

может детерминированно приводить к:

- font family profile
- weight
- scale
- line height
- letter spacing
- maximum line width

Такие производные параметры не обязательно должны быть отдельными вопросами пользователю.

Для каждой категории укажи:

DIRECT INPUTS

и

DERIVED PARAMETERS.

4. Проверь зависимости

Построй карту зависимостей:

STYLE
→ какие параметры он ограничивает?

TYPOGRAPHY
→ какие параметры layout он меняет?

COLOR
→ какие параметры contrast / accessibility / components он меняет?

ICONOGRAPHY
→ какие component rules он меняет?

MOTION
→ какие interaction rules он меняет?

и т.д.

Нас интересует не просто список настроек, а система взаимосвязанных дизайн-решений.

5. Учитывай AI-SLOP

Отдельно исследуй категорию:

AI TEMPLATE AVOIDANCE

Определи визуальные паттерны, которые сегодня часто делают сайты визуально похожими друг на друга.

Не ограничивайся очевидными:

- pill-shaped everything
- excessive rounded cards
- generic gradients
- glassmorphism
- bento grids
- oversized headings
- floating cards
- AI sparkles

Исследуй более глубокие признаки:

- повторяющиеся композиционные схемы;
- одинаковую визуальную иерархию;
- одинаковый rhythm;
- одинаковые CTA;
- одинаковую систему декоративных элементов;
- одинаковую motion choreography;
- типичные сочетания шрифтов;
- типичные сочетания цветов;
- другие признаки «AI-generated website».

Раздели их на:

- допустимые;
- использовать осторожно;
- избегать;
- избегать только при определённых стилях.

6. Детерминизм

Проект должен работать следующим образом:

USER INPUT
→ FIXED RULES
→ BLUEPRINT

а не:

USER INPUT
→ LLM RANDOM DESIGN DECISION
→ BLUEPRINT

Поэтому для каждой категории укажи, где необходима:

- фиксированная библиотека;
- фиксированный набор вариантов;
- mapping table;
- compatibility rules;
- derived rules;
- validation rules.

7. Не собирай пока референсы

На этом этапе НЕ ищи изображения.

Сначала необходимо понять:

ЧТО именно мы будем показывать пользователю.

После утверждения Taxonomy следующим отдельным этапом будет:

DESIGN REFERENCE LIBRARY

где для каждого варианта мы будем собирать:

- 3–5 визуальных референсов;
- простое человеческое описание;
- характеристики;
- техническую интерпретацию;
- связанные design tokens;
- совместимые варианты;
- anti-patterns.

8. Финальный результат

Представь результат в виде:

1. TAXONOMY OVERVIEW
2. CATEGORY MAP
3. DIRECT vs DERIVED PARAMETERS
4. DEPENDENCY GRAPH
5. AI-SLOP / ANTI-PATTERN TAXONOMY
6. DETERMINISM RULES
7. PROPOSED BLUEPRINT STRUCTURE
8. OPEN QUESTIONS

Не пытайся искусственно увеличить количество категорий.

Главный критерий качества:

«Если пользователь пройдёт будущий мастер и заполнит эти параметры, сможет ли система детерминированно собрать из них полноценную визуальную систему сайта, а затем превратить её в Design Prompt?»

Если нет — найди, чего не хватает.

Не пиши код.
Не проектируй UI.
Не создавай prompt.
Не собирай изображения.

Сейчас нам нужна именно архитектура пространства дизайн-решений.
