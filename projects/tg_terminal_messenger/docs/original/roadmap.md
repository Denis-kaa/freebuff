🗺 **ROADMAP: tg-terminal-toolkit**  
*Сформирован на основе `tz.md` (v1.0) и правил Kwork Arbitr v3 (атомарные задачи, строгий async, разделение ответственности).*

**Тип проекта:** `script` / `cli` (Локальное TUI-приложение)  
**Ожидаемая сложность (LISA TC):** 4–6 (Medium)  
**Цель:** Реализация MVP с прохождением всех критериев приёмки (DoD) из раздела 6 `tz.md`.

---

### 🟦 Этап 1: Инициализация и окружение (Day 1)
*Цель: Подготовка структуры проекта и зависимостей.*
- **1.1. Создание структуры каталогов**  
  - Генерация дерева папок: `ui/`, `storage/`, `utils/`.
  - Создание файлов-заглушек (`__init__.py`) для корректного импорта.
- **1.2. Настройка зависимостей**  
  - Создание `requirements.txt` (telethon>=1.34, textual>=0.40, rich>=13.0, aiofiles>=23.0).
  - Настройка `.gitignore` (исключение `*.session`, `__pycache__`, `.env`).
- **1.3. Базовая конфигурация**  
  - Создание шаблона `.env` для `API_ID` и `API_HASH`.

### 🟩 Этап 2: Ядро и авторизация (Day 1–2)
*Цель: Надёжное подключение к Telegram MTProto с соблюдением NFR-004 (безопасность сессии).*
- **2.1. Реализация `tg_client.py`**  
  - Создание обёртки над `TelegramClient` из Telethon.
  - Внедрение централизованного обработчика `FloodWaitError` (авто-пауза через `asyncio.sleep` + логирование в UI).
  - Реализация логики повторных попыток (retry) при сетевых ошибках.
- **2.2. Реализация `auth.py`**  
  - Функция интерактивного запроса номера телефона и кода (с поддержкой 2FA пароля).
  - Сохранение сессии в файл `.session`.
  - **Критический DoD:** Установка прав доступа `600` (`os.chmod(session_path, 0o600)`) сразу после создания файла.
  - Логика автоматического восстановления сессии при запуске.

### 🟨 Этап 3: Базовый TUI Интерфейс (Day 2–3)
*Цель: Двухпанельный интерфейс без блокировки event loop (NFR-001).*
- **3.1. Главный контейнер `ui/app.py`**  
  - Инициализация `textual.app.App`.
  - Разметка: левая панель (30% ширины) для чатов, правая панель (70%) для сообщений и ввода.
  - Обработка graceful shutdown (SIGINT/SIGTERM) с корректным отключением клиента.
- **3.2. Виджет списка чатов `ui/chat_list.py`**  
  - Отображение списка диалогов (название, последнее сообщение, индикатор непрочитанных).
  - Навигация стрелками `↑`/`↓` и `Enter` для выбора.
  - Асинхронная подгрузка следующих чатов при скролле вниз (ленивая загрузка).
- **3.3. Виджет сообщений `ui/message_view.py`**  
  - Отображение последних N сообщений выбранного чата.
  - Поле ввода текста внизу правой панели.
  - Отправка текстового сообщения по `Enter`.

### 🟥 Этап 4: Работа с медиа и FilePicker (Day 4–5)
*Цель: Реализация FR-010 – FR-014 (отправка файлов через кастомный TUI-менеджер).*
- **4.1. Реализация `ui/file_picker.py`**  
  - Кастомный виджет Textual для навигации по файловой системе.
  - Отображение директорий и файлов с фильтрацией по расширениям (`.jpg`, `.png`, `.mp4`, `.pdf` и т.д.).
  - Привязка горячей клавиши `Ctrl+F` для открытия модального окна FilePicker из `ui/app.py`.
- **4.2. Интеграция отправки медиа в `tg_client.py`**  
  - Валидация существования файла и его размера перед отправкой (FR-017).
  - Асинхронная загрузка файла через `client.send_file()` с обновлением прогресс-бара в TUI.
  - Обработка ошибок типа "файл не найден" или "неподдерживаемый формат".

### 🟪 Этап 5: Модуль архивации (Day 6–7)
*Цель: Реализация SHOULD-требований (FR-018 – FR-021).*
- **5.1. Реализация `storage/archive.py`**  
  - Функция экспорта истории чата в локальный JSON/SQLite.
  - Асинхронное скачивание медиа-файлов в директорию `./downloads/{chat_id***REMOVED***/` через `aiofiles`.
- **5.2. Интеграция прогресс-бара**  
  - Отображение статуса скачивания в TUI (использование `rich.progress` или встроенных виджетов Textual).

### 🟧 Этап 6: Валидация и полировка (Day 8–9)
*Цель: Прохождение всех критериев приёмки (DoD) из раздела 6 `tz.md`.*
- **6.1. Статический анализ**  
  - Добавление type hints во все модули (проверка через `mypy`).
  - Линтинг кода (через `ruff` или `flake8`).
- **6.2. Ручное и интеграционное тестирование**  
  - Проверка: запуск → auth → отображение чатов → выбор чата → отправка текста.
  - Проверка: вызов FilePicker (`Ctrl+F`) → выбор файла → успешная отправка.
  - Проверка: искусственный вызов `FloodWaitError` (или мокирование) для подтверждения авто-паузы без краша UI.
  - Проверка прав файла `.session` (`ls -l` должен показывать `-rw-------`).
