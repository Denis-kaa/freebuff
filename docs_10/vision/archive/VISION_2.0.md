## 1. Executive Summary

**Buffy больше не AI-агент. Buffy — Companion Platform.**

В эпоху, когда существует множество мощных AI-агентов (Claude Code, Cursor, OpenClaw, Codex, GPT-5), создание ещё одного агента не имеет смысла. Вместо этого Buffy становится **инфраструктурной надстройкой**, которая усиливает существующие агентные системы и обеспечивает:

- **Единое состояние проекта** для всех агентов
- **Долговременную память**, переживающую сессии
- **Knowledge Graph**, доступный из любого инструмента
- **Фоновые сервисы** (суммаризация, аудит, OOM-защита)
- **Совместную работу** человека и множества AI-агентов

Ключевой принцип: **Buffy работает рядом, а не вместо.**

## 2. Философия

### 2.1 Новое позиционирование

```
Buffy — не конкурент Claude Code или Cursor.
Buffy — инфраструктура, которую подключают к Claude Code или Cursor,
чтобы они стали умнее,記憶ливее и команднее.
```

### 2.2 Ключевые принципы

| Принцип | Описание |
|---------|----------|
| **Companion, not Competitor** | Не конкурирует с агентами, усиливает их |
| **LLM Sparingly** | Детерминированные алгоритмы где можно, LLM только где нужно |
| **Event-Driven** | Вся система построена на событиях |
| **Project State First** | Главная сущность — состояние проекта, а не диалог |
| **Model-Agnostic** | Не зависит от конкретной модели/агента |
| **Backward Compatible** | Любые изменения не ломают существующие workflows |
| **Offline-First** | Работает без интернета, синхронизация опциональна |

### 2.3 Что НЕ является Buffy

- ❌ ChatGPT/DeepSeek с файловой системой
- ❌ Ещё один AI coding assistant
- ❌ Agent framework (LangChain, CrewAI, AutoGPT)
- ❌ RAG-система / vector database
- ❌ MCP-сервер (хотя MCP — один из протоколов)

## 3. Целевая аудитория

| Аудитория | Проблема | Как Buffy помогает |
|-----------|----------|-------------------|
| **Solopreneur** | Контекст теряется между сессиями | Project State + Memory Engine |
| **Dev-команда** | Нет единой памяти проекта | Shared Knowledge + Event Log |
| **AI-агенты** | Нет доступа к истории проекта | MCP + Graph Memory |
| **Фрилансер** | Нужны готовые шаблоны задач | Scenario Engine |
| **Исследователь** | Много источников, нет связей | Knowledge Graph + RAG |

## 6. Критическая оценка

### 6.1 Сильные стороны текущей архитектуры (сохраняем)

1. **Неубиваемость** — контекст на диске (SQLite + JSON), OOM не страшен ✅
2. **Модульность** — каждый слой заменяется независимо ✅
3. **Model-Agnostic** — ядро не зависит от модели ✅
4. **Event Bus** — основа для событийной архитектуры ✅
5. **Knowledge Engine** — FTS5 + TF-IDF + SVD + Graph ✅
6. **Scenario Engine** — готовые шаблоны задач ✅
7. **freebuff_plugin** — точка расширения ✅

### 6.2 Слабые стороны (требуют изменений)

1. **Зависимость от Codebuff** — плагин завязан на один бинарник
2. **Нет MCP Client** — не можем подключаться к внешним MCP-серверам
3. **Нет Bridge Layer** — интеграция с другими агентами только через MCP Server
4. **Нет распределённости** — всё на одном устройстве
5. **Нет коллаборации** — один пользователь, одно устройство
6. **LLM используется слишком часто** — многие задачи можно решать детерминированно

### 6.3 Риски

| Риск | Вероятность | Влияние | Митигация |
|------|------------|---------|-----------|
| Feature creep — превратиться в очередного агента | Высокая | Критическое | Строго следовать философии Companion |
| Сложность интеграции с разными экосистемами | Высокая | Высокое | Начать с MCP, добавлять по одной |
| Потеря фокуса на Termux | Средняя | Среднее | Сохранить offline-first |
| Конкуренция с крупными платформами | Низкая | Низкое | Buffy не конкурирует, а дополняет |
| Усложнение кодовой базы | Средняя | Среднее | Модульность, тесты, документация |

## 7. Стратегия развития

### Этап 1: Foundation (текущий — v4.x)
**Фокус:** Стабильность, тесты, документация

- ✅ 649 тестов
- ✅ OOM Protection
- ✅ Scenario Engine (11 сценариев)
- ✅ Telegram бот
- ✅ Документация (ARCHITECTURE, API, QUICKSTART)
- 🔄 Укрепление существующих компонентов

### Этап 2: Ecosystem Integration (v5.0)
**Фокус:** Bridge Layer, MCP Client, интеграции

- MCP Client — подключение внешних MCP-серверов
- Bridge Layer — Claude Code + OpenClaw интеграция
- Plugin API v2 — плагины для разных экосистем
- Scenario Engine — экспорт промтов для разных агентов

### Этап 3: Collaboration (v6.0)
**Фокус:** Множество участников, присутствие, лента

- Presence System — статусы участников
- Project Pulse — лента событий проекта
- User Preferences — роли и назначения
- Session Manager — типы участников

### Этап 4: Intelligence (v7.0)
**Фокус:** RAG v2, Graph Memory, минимизация LLM

- Agentic RAG — агент выбирает стратегию поиска
- Graph Memory — авто-построение из документов
- Re-ranking + HyDE
- Детерминизация где возможно

### Этап 5: Distributed (v8.0+)
**Фокус:** Multi-device, real-time, сервер

- Event Bus v2 — распределённый
- Live Collaboration — real-time
- Remote Sync — синхронизация между устройствами
- Web UI — дашборд для мониторинга

## 8. Что НЕ меняется

1. **Termux остаётся основной средой** — offline-first, без сервера
2. **Python — основной язык** — никаких переписываний на Rust/Go
3. **SQLite — основная БД** — не переходим на PostgreSQL
4. **MCP — основной протокол интеграции** — не изобретаем велосипед
5. **Тесты — обязательны** — 649 тестов и больше
6. **CHANGELOG.md — обязателен** — полная traceability

---

## 9. Заключение

Buffy 2.0 — это не просто набор новых функций. Это смена парадигмы: **от AI-агента к платформе, усиливающей других агентов.**

Главная победа Vision 2.0 будет не в том, сколько новых фич мы добавим, а в том, что разработчик скажет: *«Я подключил Buffy к своему Claude Code, и теперь он помнит проект, знает контекст и может работать в команде»*.

Buffy не заменяет существующие инструменты. Buffy делает их лучше.
