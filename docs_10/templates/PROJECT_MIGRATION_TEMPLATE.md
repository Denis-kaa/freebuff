# PROJECT_MIGRATION_TEMPLATE.md — Протокол миграции проекта из платформы

> **Назначение:** экспорт проекта из Workspace OS на другую платформу/инфраструктуру
> **БЕЗ потери архитектурных решений** (project-local ADR + MANIFEST + инженерная память).
> **Статус:** шаблон-протокол (не принудительный; обязателен при любом выносе проекта).
> **Основание:** принцип портируемости MANIFEST-конвенции («проект не зависит от экосистемы freebuff») + PLATFORM.md:493 (открытый вопрос «Должны ли workspace-ы быть экспортируемыми?»).

---

## 0. Когда применять

- Проект **покидает платформу** (перенос в отдельный репозиторий/инфраструктуру/клиенту).
- Проект **копируется** на другой инстанс/устройство.
- Аудит «на случай развода» — проверка, что все решения задокументированы внутри проекта.

> Для 3-строчного фикса шаблон не нужен. Для выноса проекта — обязателен.

---

## 1. Инвентаризация (что должно жить ВНУТРИ проекта)

К моменту миграции проект ДОЛЖЕН содержать (в `projects_17/<project>/`):

| Файл | Роль | Обязателен |
|------|------|------------|
| `MANIFEST.md` | Паспорт проекта (по конвенции платформы) | ✅ |
| `decisions/DECISIONS.md` | Индекс project-local ADR | ✅ |
| `decisions/ADR-NNN_*.md` | Архитектурные решения проекта | ✅ |
| `ROADMAP.md` | План/этапы (по PIPELINE_TEMPLATE) | ✅ |
| `STEPS.md` | Живой чек-лист | ✅ |
| `LESSONS.md` | CON-/ANTI- находки | ✅ |
| `PHASE*.md` | Фазы исследования/архитектуры | ✅ (если были) |
| `app/`, `config/`, `src/` | Код проекта | ✅ |
| `tests/` | Тесты проекта | ✅ (если тесты в `tests_09/` по конвенции платформы — при миграции скопировать ВНУТРЬ проекта; см. §3 шаг 2b) |

**Платформенные ADR** (`docs_10/engineering-memory/decisions/ADR_NNN_*.md`) — НЕ переносятся как есть: их решения о проекте **копируются в project-local ADR** с пометкой provenance (см. §4).

## 2. Проверка самодостаточности (перед миграцией)

```bash
# 1. Проект не ИМПОРТИРУЕТ платформу (только реальные import-операторы):
grep -rnE '^\s*(import|from)\s+(freebuff_plugin|core_02|scripts_01)' projects_17/<project>/app/ projects_17/<project>/src/ \
  || echo "OK: нет платформенных импортов"

# 1b. Docstring/комментарий-упоминания платформы (provenance reuse-паттернов) —
#     ДОПУСТИМЫ и не считаются зависимостью (проверь глазами, что это не import):
grep -rnE 'freebuff_plugin|core_02|scripts_01' projects_17/<project>/app/ | grep -vE ':\s*(import|from)\s' || echo "только docstring-упоминания"

# 2. Ссылки в доках проекта не ведут за пределы проекта (кроме явных cross-link):
grep -rn '\.\./\.\./core_02\|\.\./\.\./scripts_01\|\.\./docs_10' projects_17/<project>/*.md projects_17/<project>/decisions/*.md

# 3. Тесты зелёные автономно (замените tests/ на фактические каталоги кода,
#    если структура иная — e.g. diet_platform: modules/):
#    Если тесты ещё в tests_09/ (конвенция платформы) — выполните эту проверку
#    ПОСЛЕ шага 2b (перенос тестов внутрь проекта в §3):
python -m pytest projects_17/<project>/ -q
```

> **Нюанс:** каталоги кода (`app/`, `src/`, `modules/`...) различаются по проектам —
> замените на фактические. Docstring-упоминания `scripts_01/...` как пояснение
> «паттерн переиспользован» — не зависимость (подтверждено lead_aggregator: 0 import,
> только provenance-комментарии).

**Если импорты есть** — это нарушение аддитивности (CON-40/ANTI-5). Два пути:
- **Встраивание:** скопировать нужную функцию платформы в проект (с лицензией/атрибуцией) — для малого объёма.
- **Контракт:** оставить интерфейс-заглушку в проекте (как `TLSClient`/`CheckpointStore` в lead_aggregator) + документально зафиксировать внешнюю зависимость.

## 3. Экспорт (шаги)

1. **Создать `decisions/`** если нет — см. конвенцию project-local ADR (§4).
2. **Скопировать весь каталог проекта** целиком (`MANIFEST.md`, `decisions/`, `ROADMAP/STEPS/LESSONS/PHASE`, `app/`, `config/`).
2b. **Перенести тесты из `tests_09/`** в `projects_17/<project>/tests/` (конвенция платформы хранит тесты в `tests_09/test_<project>_*.py`; при выносе они обязаны жить внутри проекта).
3. **Конвертировать платформенные ссылки** — §4.
4. **Добавить `MIGRATION.md`** в корень проекта (по правилу 15 промт 001_07): версионирование, что изменилось при выносе, как обновляться дальше.
5. **Обновить `MANIFEST.md`**: поле «Среда/Статус» → новое окружение; секция «Контроль Buffy» → удалена/заменена на владельца.

## 4. Конвенция project-local ADR

**Расположение:** `projects_17/<project>/decisions/` — `DECISIONS.md` (индекс) + `ADR-NNN_<slug>.md`.

> **Почему `ADR-` (дефис), а не `ADR_` (подчёркивание):** платформенные ADR используют
> `ADR_` (glob drift_check `ADR_*` в canonical dir). Дефис визуально и машинно отделяет
> project-local ADR и исключает конфликт glob, если проект когда-либо скопируют в
> каноническую директорию.

**Формат** — по образцу платформенных ADR (`ADR_012/013/014`), обязательные секции:

```markdown
# ADR-NNN: <Заголовок решения>
**Status:** Accepted (дата)
**Component:** <модуль внутри проекта>
**Scope:** PROJECT-LOCAL (решение принадлежит проекту, не платформе)
**Related:** [платформенный ADR/документ, если есть***REMOVED*** | [MANIFEST.md***REMOVED*** | [ROADMAP.md***REMOVED***
## 1. Context
## 2. Decision
## 3. Альтернативы, которые рассматривались
## 4. Consequences
```

**Граница scope:**
- **Platform ADR** (`docs_10/engineering-memory/decisions/`) — решения о ПЛАТФОРМЕ (разделяются между всеми проектами).
- **Project-local ADR** (`projects_17/<project>/decisions/`) — решения ПРОЕКТА: выбор источников, порядок, контракты-адаптеры, юр. гейты, торговые оффы (tension resolution), специфика стека.

**Provenance при конвертации:** если решение задокументировано в платформенном ADR, project-local ADR ставит:
`**Supersedes платформенную копию?** Нет — платформенная ADR-014 остаётся; эта запись — self-contained копия с provenance: ADR_014_... (2026-08-10).`

## 5. Приёмка (acceptance criteria)

- [ ***REMOVED*** `grep freebuff_plugin` в `app/` → 0 импортов (или задокументированные контракты).
- [ ***REMOVED*** `MANIFEST.md` обновлён (новое окружение, владелец).

- [ ***REMOVED*** Все платформенные решения о проекте скопированы в project-local ADR с provenance.
- [ ***REMOVED*** `MIGRATION.md` создан (что изменилось, как обновляться).
- [ ***REMOVED*** Тесты зелёные на новом окружении.
