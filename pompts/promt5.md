MISSION: Buffy Interoperability Layer — Universal Agent Integration Architecture

РОЛЬ

Ты — исследовательская команда мирового уровня, объединяющая компетенции:

- Principal Distributed Systems Architect
- AI Agent Researcher
- Protocol Designer
- Runtime Architect
- LLM Infrastructure Engineer
- Systems Integration Engineer

Твоя задача — провести глубокое архитектурное исследование и спроектировать компонент Buffy Interoperability Layer (BIL) — универсальный слой интеграции между различными агентными платформами, моделями и протоколами.

Это не "мост" между двумя системами. Это инфраструктурный слой, позволяющий независимым агентным экосистемам совместно работать без необходимости переписывать их внутреннюю архитектуру.

---

ПРОБЛЕМА

Сегодня существует множество мощных агентных фреймворков:

- Hermes
- OpenClaw
- Claude Code
- Codex CLI
- Aider
- локальные агенты
- будущие агентные платформы

Каждый развивается независимо.

У каждого:

- собственная память;
- собственный рантайм;
- собственные инструменты;
- собственные API;
- собственный протокол;
- собственая архитектура.

Практически отсутствует универсальный слой, который позволял бы использовать их совместно.

---

ЦЕЛЬ

Спроектировать архитектуру, в которой Buffy НЕ конкурирует с существующими агентными платформами.

Buffy должна стать нейтральной инфраструктурой, объединяющей их.

---

ГЛАВНЫЙ ПРИНЦИП

Не заставлять пользователей переходить на Buffy.

Позволить им продолжать использовать привычную экосистему.

Buffy должна легко подключаться к уже существующим решениям и расширять их возможности.

---

РЕВЕРСИВНАЯ ИНТЕГРАЦИЯ

Это ключевое требование.

Каждая поддерживаемая система должна работать в двух режимах.

Режим 1

Buffy является Host.

Buffy управляет:

Hermes

OpenClaw

Claude Code

Codex

другими агентами.

---

Режим 2

Buffy является Agent.

Hermes использует Buffy.

OpenClaw использует Buffy.

Claude Code использует Buffy.

Codex использует Buffy.

Buffy становится сервисом:

- памяти;
- Project State;
- Knowledge Engine;
- RAG;
- Task Manager;
- Planner;
- Orchestrator.

Любая внешняя система должна иметь возможность использовать Buffy как инфраструктуру.

---

НЕ ДУБЛИРОВАТЬ

Buffy не должна переписывать функциональность внешних систем.

Если Hermes лучше решает автономное планирование — использовать Hermes.

Если OpenClaw лучше анализирует код — использовать OpenClaw.

Если Claude Code лучше выполняет архитектурный анализ — использовать Claude Code.

Buffy должна использовать сильные стороны каждой системы.

INTELLIGENT ROUTING

Маршрутизация должна происходить не по названию агента.

Не:

"используй Hermes"

А по возможностям.

Например:

Требуется:

- глубокий архитектурный анализ;
- локальное выполнение;
- отсутствие облака.

Router самостоятельно выбирает наиболее подходящего исполнителя.

---

UNIVERSAL TASK MODEL

Спроектировать внутреннюю универсальную модель задачи.

Она должна быть независима от любых внешних платформ.

Любой внешний агент получает задачу через преобразование этой модели.

Обязательно исследовать:

какие поля должна содержать такая модель;

как хранить состояние;

как описывать зависимости;

как описывать ограничения;

как описывать требуемые способности исполнителя.

---

TRANSLATION LAYER

Спроектировать систему адаптеров.

Каждый адаптер должен выполнять:

входное преобразование;

выходное преобразование;

конвертацию ошибок;

конвертацию статусов;

конвертацию событий;

конвертацию результатов.

Ядро Buffy никогда не должно знать внутреннюю архитектуру Hermes, OpenClaw или других платформ.

ГЛАВНАЯ ЦЕЛЬ

Не создать ещё один агентный фреймворк.

Создать универсальный инфраструктурный слой, который позволит существующим и будущим агентным экосистемам безопасно, эффективно и двусторонне взаимодействовать друг с другом, сохраняя их автономность, сильные стороны и совместимость.

Результат исследования должен представлять собой полноценную архитектуру промышленного уровня с диаграммами, интерфейсами, жизненным циклом компонентов, анализом альтернатив, оценкой рисков и подробным планом реализации.
