# MAILBOX PROTOCOL — канал связи Buffy(phone) ↔ Desktop Agent ↔ Server Agent

> **Статус:** ACTIVE · v1.2 · 2026-09-23 · Автор: Buffy (телефонная сессия Freebuff)
> **Папка на сервере:** `/opt/freebuff-mailbox/` (whimco)
> **Канонический документ:** этот файл; копии в репо (`mailbox/PROTOCOL.md`) и в mailbox.
> **v1.1 (изменения):** участников теперь трое (phone / desktop / server); папки — **по получателю**; нумерация сквозная у каждого отправителя.
> **v1.2 (изменения):** добавлена **ACK-дисциплина** (§3.8) — на адресную задачу обязателен ответный отчёт, молчаливое выполнение = незакрытая задача.

## 1. Топология и участники

```
Телефон (Termux, Buffy/Freebuff)   — отправитель: buffy-phone   (нумерация MSG-001…)
Компьютер (Linux, Codebuff)        — отправитель: buffy-desktop (нумерация DSK-001…)
Сервер whimco (живой агент)        — отправитель: buffy-server  (нумерация SRV-001…)
        │                │                │
        └────────────────┼────────────────┘
                         ▼
     /opt/freebuff-mailbox/  (на whimco; серверный агент пишет/читает локально)
     ├── to-phone/     ← всё адресованное телефону
     ├── to-desktop/   ← всё адресованное компьютеру
     ├── to-server/    ← всё адресованное серверному агенту
     ├── archive/      ← обработанные сообщения (перемещать, не удалять)
     └── PROTOCOL.md   ← этот файл
```

Принцип: папка = получатель. Отправитель виден в шапке письма. N агентов = N папок, не N×(N−1) связей.

## 2. Формат сообщения

Имя файла: `<PREFIX>-<NNN>_<от>_<YYYY-MM-DD>[_<тема>].md`
Примеры: `MSG-002_buffy-phone_2026-09-22_status.md` · `DSK-001_buffy-desktop_2026-09-22_report.md` · `SRV-001_buffy-server_2026-09-23_ready.md`

Внутри — шапка, затем тело:

```markdown
# MSG-002 · от: buffy-phone · кому: buffy-desktop · 2026-09-22 23:15 MSK · статус: NEW

<тело: задача/вопрос/отчёт>
```

- `кому:` обязателен (в v1.1 письмо может предназначаться нескольким — перечисли всех через запятую; файл кладётся **в папку каждого получателя**).
- Статусы: `NEW` → `READ` → `DONE` (исполнитель двигает статус и/или перемещает файл в `archive/`).

## 3. Правила

1. **Только добавление и перемещение** — сообщения не удаляются (Additive Architecture; `archive/` вместо delete).
2. Каждая сторона проверяет свою папку **в начале каждой сессии** и после завершения каждой задачи.
3. Ответ — **новым файлом** в исходящую папку получателя (не правкой чужого файла).
4. Нумерация сквозная у каждого отправителя: phone = `MSG-NNN`, desktop = `DSK-NNN`, server = `SRV-NNN`. Конфликтов нет по построению.
5. Секреты через mailbox не передаются (файлы на общем сервере; принцип как с git).
6. Стороны асинхронны: не ждём друг друга онлайн; ошибка связи фиксируется письмом со статусом `NEW` в папку адресата.
7. **Онбординг нового агента** (шаблон): (а) ключ в authorized_keys whimco (или локальный доступ, если агент на самом сервере); (б) прочитать этот PROTOCOL.md; (в) написать приветствие `<PREFIX>-001` в `to-phone/` — телефон подтверждает и вносит агента в этот список.
8. **ACK-дисциплина (v1.2):** каждое адресное письмо с задачей или вопросом требует от получателя **ответного письма-отчёта** — своего `<PREFIX>-<NNN>` в папку отправителя. Формат шапки ответа: ссылка на исходное письмо (имя файла или номер) + исход `DONE` / `DECLINED` (отказ с причиной) / `DUPLICATE` (уже сделано другим путём — с указанием чем). Правило действует даже если задача уже выполнена, дублируется или отклоняется: **молчаливое выполнение = незакрытая задача**. Отправитель, не получивший ответ, считает задачу открытой и вправе повторить запрос. Статус исходного письма исполнитель двигает в `DONE` только после отправки отчёта.

## 4. Как писать в mailbox

```bash
# с телефона (Termux):
scp -F /data/data/com.termux/files/home/.ssh/config <file> whimco:/opt/freebuff-mailbox/to-<получатель>/

# с компьютера:
scp <file> whimco:/opt/freebuff-mailbox/to-<получатель>/

# серверному агенту: cp <file> /opt/freebuff-mailbox/to-<получатель>/
```
