# Инструкция: исправление ошибки входа на gapirai.uz

## Коротко о ситуации

Вход на сайт не работает **у всех пользователей на любом устройстве** — не только на Mac. Причина: на сервере, где сейчас развёрнут сайт, не настроен проброс адресов `/auth/*` в API. Это настройка сервера, а не ошибка в коде: код входа работает (проверено — на текущей копии проекта логин и регистрация проходят успешно).

Ниже — что нужно сделать. Это одна правка конфигурационного файла и одна команда.

---

## Что понадобится

- Доступ к серверу по SSH (тот, через который заказчик запускал проект; сервер в AWS).
- 10 минут времени.

Если заказчик не может сам — пусть передаст эту инструкцию своему системному администратору или в поддержку хостинга. Правка стандартная.

---

## Шаг 1. Зайти на сервер

На своём компьютере открыть терминал (на Mac — приложение Terminal) и выполнить:

```bash
ssh <пользователь>@<IP сервера>
```

(IP сервера и пользователь те же, что заказчик использовал при установке.)

---

## Шаг 2. Найти конфигурационный файл nginx

Выполнить по очереди:

```bash
ls /etc/nginx/sites-enabled/
```

Найти в списке файл, связанный с сайтом (например `ai-dubber`, `gapirai`, `default`). Далее вместо `ИМЯ_ФАЙЛА` подставлять найденное имя.

Открыть файл на редактирование:

```bash
sudo nano /etc/nginx/sites-enabled/ИМЯ_ФАЙЛА
```

---

## Шаг 3. Найти блок с `/api/`

Внутри файла найти строки (Ctrl+W в nano — поиск, ввести `location /api/`):

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8000;
    ...
}
```

---

## Шаг 4. Добавить два блока ПОСЛЕ блока `/api/`

Скопировать и вставить в файл сразу после закрывающей скобки `}` блока `location /api/`:

```nginx
location = /auth/callback {
    proxy_pass http://frontend_upstream;
    proxy_set_header Host $host;
}

location /auth/ {
    proxy_pass http://127.0.0.1:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

⚠️ Важно: если в конфиге имя upstream не `frontend_upstream`, а другое (смотрите, что написано в `location / { proxy_pass ...; }` — использовать то же имя), подставить его в первом блоке.

Сохранить: Ctrl+O, Enter. Выйти: Ctrl+X.

---

## Шаг 5. Проверить конфиг и перезагрузить nginx

```bash
sudo nginx -t
```

Должно написать `syntax is ok` и `test is successful`.

Если ошибок нет:

```bash
sudo systemctl reload nginx
```

---

## Шаг 6. Проверить, что вход работает

Выполнить:

```bash
curl -X POST https://gapirai.uz/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"test@test.com","password":"x"}'
```

Правильный результат — **JSON-ответ** от API, например:

```json
{"detail":"Bu email ro'yxatdan o'tmagan."}
```

Неправильный результат — большая HTML-страница со словами «404 This page could not be found». Если виден HTML — блок `/auth/` вставлен не туда или nginx не перезагружен.

Финальная проверка в браузере: открыть `https://gapirai.uz/login`, ввести любую почту и пароль — сайт должен ответить сообщением («неверный email или пароль»), а не пустой ошибкой 404.

---

## Если что-то пошло не так

- `nginx -t` выдаёт ошибку — значит блок вставлен с опечаткой или не в тот файл. Вернуть файл как был и вставить заново.
- Сайт перестал открываться — вернуть файл как был (`sudo cp /etc/nginx/sites-enabled/ИМЯ_ФАЙЛА.bak /etc/nginx/sites-enabled/ИМЯ_ФАЙЛА` — если бэкап создавался) и `sudo systemctl reload nginx`.
- Перед правкой можно сделать резервную копию: `sudo cp /etc/nginx/sites-enabled/ИМЯ_ФАЙЛА /etc/nginx/sites-enabled/ИМЯ_ФАЙЛА.bak`
