## Преамбула

Мы не строим ещё одного AI-агента.

Мы строим **открытую инфраструктурную платформу**, которая:
- помогает одиночным разработчикам и командам;
- может работать автономно как freebuff агент;
- усиливает существующие AI-агенты, а не заменяет их;
- легко интегрируется с новыми моделями и фреймворками;
- остаётся модульной, расширяемой и независимой от конкретных технологий;
- развивается эволюционно, сохраняя совместимость с уже реализованными компонентами.

## 2. ЧЕМ МЫ НЕ ЯВЛЯЕМСЯ

| ❌ Мы НЕ | Потому что |
|----------|------------|
| **Ещё один AI-агент** | На рынке есть Claude, Cursor, Codebuff, GPT-5. Создание ещё одного — тупик. |
| **Agent framework** | LangChain, CrewAI, AutoGPT уже существуют. Мы не конкурируем — мы работаем с ними. |
| **IDE или редактор** | VS Code, Cursor, JetBrains делают это лучше. Мы даём им память и контекст. |
| **ChatGPT с файловой системой** | LLM используем только где нужен интеллект. Всё остальное — детерминированные алгоритмы. |
| **RAG-система / Vector DB** | Knowledge Platform — часть нашей архитектуры, но не её суть. |
| **MCP-сервер** | MCP — лишь один из протоколов, которым мы владеем. |
| **Облачный сервис** | Local First — мы работаем на телефоне, offline, без сервера. |

Мы не пытаемся занять чужое место. Мы создаём место, которого не хватало.

## 3. ИНЖЕНЕРНЫЕ ПРИНЦИПЫ

### Open Architecture Manifesto

```
🧱 Runtime Agnostic       — не привязан к конкретному AI Runtime
                            (freebuff · Claude · OpenClaw · Hermes · Codex · будущие)

🏢 Provider Agnostic      — работает с любым API-провайдером
                            (OpenAI · Anthropic · DeepSeek · Gemini · OpenRouter · Ollama)

🧠 Model Agnostic         — не зависит от конкретной модели
                            (DeepSeek · GPT · Claude · Gemini · Qwen · freebuff)

🔌 Plugin First           — всё расширяется через плагины
                            (Plugin API · SDK для сторонних разработчиков)

⚙️ Deterministic First    — LLM только там, где нужен интеллект
                            (контекст · память · поиск — без LLM)

📡 Event Driven           — вся система построена на событиях
                            (Event Bus · Event Store · Replay · Timeline · Audit)

📱 Local First            — работает offline, синхронизация опциональна
                            (Termux · Android · без интернета · полная функциональность)

📋 Policy Driven          — все решения определяются политиками пользователя
                            (Runtime · Provider · Model · Workflow · Fallback · Cost)

🌍 Offline Friendly       — без интернета — полная функциональность
                            (freebuff модели · кэш · синхронизация при подключении)

👥 Collaboration Ready    — multiple users · runtimes · agents · servers
                            (Presence · Team Mode · Project Pulse)

🔄 Backward Compatible    — эволюция без разрушения
                            (миграции · deprecation policy · LTS компоненты)

🔗 API First              — всё доступно через API
                            (REST · MCP · ACP · CLI)

🧩 Modular by Design      — каждый компонент заменяем
                            (Core / Extensions / Labs · слабая связанность)

🗿 Immutable Ideas        — идеи никогда не удаляются, только меняют статус
                            (IDEAS.md · ADR · Decision Log)
```

### Дополнительные принципы

**Unix Philosophy Applied to AI Infrastructure:**
- Каждый компонент делает одну вещь и делает её хорошо
- Компоненты общаются через Event Bus (как pipes в Unix)
- Всё есть файл (SQLite, JSON, Markdown)
- Сложность скрыта за простыми интерфейсами

**Evolution over Revolution:**
- Никаких rewrite. Каждый компонент эволюционирует
- Миграции данных — автоматические, обратно совместимые
- Deprecation — минимум за один мажорный релиз

**Testing is Non-Negotiable:**
- Каждый компонент имеет тесты
- Boundary Testing для всех интерфейсов
- Регрессионные тесты перед каждым релизом
- Code review для каждого изменения

## 5. ЧТО МЫ ОБЕЩАЕМ ПОЛЬЗОВАТЕЛЮ

1. **Твои сессии не теряются.** ✅ *(реализовано)* — Никогда. Даже если телефон перезагрузится, OOM убьёт процесс или ты закроешь Termux. Всё состояние — на диске (SQLite + JSON).

2. **Твой контекст переживает агентов.** 🚧 *(в планах)* — Переключился с Codebuff на Claude? Buffy передаст контекст (через Bridge Layer). Вернулся через неделю? Buffy напомнит, на чём ты остановился.

3. **Ты не привязан к модели.** 🚧 *(частично, v5.0)* — Хочешь DeepSeek для кода, Claude для архитектуры, freebuff Qwen для простых задач — настраиваешь один раз через Policy Engine.

4. **Ты не привязан к провайдеру.** 🟡 *(частично)* — ModelGateway поддерживает 6 провайдеров. Policy Engine с failover — в разработке.

5. **Ты работаешь offline.** ✅ *(реализовано)* — Нет интернета? Qwen 0.5B на телефоне справится. Вся функциональность Core доступна offline.

6. **Твоя документация всегда актуальна.** ✅ *(реализовано)* — CHANGELOG обновляется автоматически. Drift check — ежедневно. ADR фиксируют решения.

7. **Ты можешь работать в команде.** 🚧 *(в планах, v7.0)* — Presence, Team Mode, Project Pulse — в Labs.

8. **Ты не теряешь идеи.** ✅ *(реализовано)* — IDEAS.md хранит все идеи вечно. Статус меняется, идея не удаляется.

9. **Твоя система не ломается при обновлении.** 🟡 *(частично)* — Schema-миграции через PRAGMA user_version. Обратная совместимость — без автоматических тестов, требуется CI.

10. **Buffy не мешает.** ✅ *(реализовано)* — Фоновые процессы, OOM Protection, минимальное потребление RAM.

| Ты | Проблема | Buffy даёт |

| **Solopreneur** | Контекст теряется между сессиями, инструментами, днями | Единое состояние проекта. Непрерывность работы. |

| **DevOps** | Развёртывание AI-среды — это боль. | Bootstrap Engine. Одна команда — готовая среда. |

## 7. ГРАНИЦЫ

Buffy не делает:
- Не генерирует код (это работа подключённых агентов)
- Не запускает LLM инференс (только через Runtime Adapter)
- Не предоставляет UI (CLI + Telegram + API — достаточно)
- Не хранит большие файлы (использует файловую систему)
- Не управляет контейнерами (это работа Docker/Kubernetes)
- Не заменяет Git (он работает рядом)

Buffy делает:
- Сохраняет и восстанавливает контекст
- Предоставляет единую память для всех агентов
- Оркестрирует работу агентов
- Применяет политики пользователя
- Следит за здоровьем системы
- Ведёт историю решений
