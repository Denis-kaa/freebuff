## §2 4 общепринятых принципа прогноза/заказа

### 2.1 Простое скользящее среднее (SMA, W=4) — принцип 1

**Формула (Excel):**
```
=AVERAGE('history'!D{h_end-3***REMOVED***:D{h_end***REMOVED***)
```

**Индустриальная норма:** для стабильных категорий (молочка / крупа / напитки) окно **4 недели** сглаживает шум и ловит краткосрочные тренды. Окно 7-14 дней — стандарт, 4 — нижняя граница для устойчивых категорий.

**Источник:** Chopra, S., Meindl, P. "Supply Chain Management: Strategy, Planning, and Operation" (главы про inventory planning + demand forecasting baseline).

### 2.2 Weekday seasonality index — принцип 2

**Принцип:** спрос варьируется по дню недели. Index для дня X = (средние продажи в этот день недели) / (общие средние). Прогноз_на_день = Базовый × Index(X). Сумма индексов за 7 дней должна ∑≈7 (баланс за неделю).

**Pattern (типичные значения для категорий демо):**

| Категория | Пн | Вт | Ср | Чт | Пт | Сб | Вс | Σ |
|-----------|----|----|----|----|----|----|-----|---|
| **Молочка** (скоропорт) | 1.10 | 1.00 | 1.00 | 1.05 | 1.20 | 1.40 | 1.30 | 8.05 |
| **Крупа** (длительного хранения) | 1.05 | 1.00 | 1.00 | 1.00 | 1.15 | 1.10 | 0.90 | 7.20 |
| **Напиток** (среднестабильное) | 0.90 | 0.85 | 0.85 | 0.95 | 1.25 | 1.50 | 1.30 | 7.60 |

Суммы немного выше 7 (8.05, 7.20, 7.60) потому что моделируем «пт-сб пик» как доминантный паттерн — для скоропорта это типичная retail-практика. В реальном инструменте индексы были бы откалиброваны по историческим продажам.

**Источник:** Hyndman, R. J., Athanasopoulos, G. "Forecasting: Principles and Practice" (OTexts, открытый; глава про seasonal data + multiple seasonality).

### 2.3 Safety Stock Z × σ × √(L) — принцип 3

**Формула (Excel):**
```
=STDEV.P('history'!D{h_end-3***REMOVED***:D{h_end***REMOVED***) * 1.65 * SQRT(L)
```

**Индустриальные магические числа (Z — service level):**
- **Z = 1.65** для 95% уровня сервиса (наиболее распространённый в ритейле)
- Z = 2.00 для ~97.7% (более агрессивный) — для premium-категорий
- Z = 1.28 для 90% (минимально допустимый) — для non-critical SKU
- **L** = lead_time **в днях** (не неделях)

**Источник:** AbcSupplyChain — "Safety Stock Formula Calculation" (https://www.abcsupplychain.com/safety-stock-formula-calculation/), классический tutorial с формулой и эмпирическими примерами.

### 2.4 Shelf-life correction — принцип 4

**Формула (Excel):**
```
=IF(shelf_life < 2 * lead_time, 0.5, 1.0)
```

**Логика:** если срок годности в днях меньше **2×lead_time**, заказ редуцируется на **50%** (типичное правило «успеть продать до истечения»), иначе — коррекции нет. 2×lead_time — эмпирический порог с 1 днём запаса на выкладку.

**Применяется в демо:**

| Категория | shelf_life | lead_time | 2×lead_time | shelf<2L? | factor |
|-----------|------------|-----------|-------------|-----------|--------|
| Молочка | 7 | 2 | 4 | НЕТ (7 > 4) | 1.0 |
| Крупа | 365 | 5 | 10 | НЕТ | 1.0 |
| Напиток | 90 | 3 | 6 | НЕТ (90 >> 6) | 1.0 |

В демо все три категории имеют **factor=1.0** — коррекция не сработает. Это потому что для наглядной формулы нужны были бы экстремально короткие сроки. **Аналитик должен увидеть IF-формулу и понять паттерн**, даже если в нашем демо она не применяется.

**Источник:** Relex Solutions — "Demand Forecasting" (https://www.relexsolutions.com/resources/demand-forecasting/); Chopra & Meindl — perishables chapter.

## §3 2 неочевидных элемента (legacy бизнес-логика, per Q3)

**Пояснение:** в реальных legacy-инструментах ритейлеров встречаются элементы, которые **невозможно понять** из одних лишь формул. Два намеренно воспроизведены как типичные паттерны.

### 3.1 NON_OBVIOUS_1: SERVICE_LEVEL_Z = 1.65 hardcoded без комментария

**Где:** sheet `forecast`, ячейка **`K5`**. Значение `1.65` висит **без видимого соседнего комментария** «что это Z для 95%». Соседняя ячейка `J5` содержит только label `SERVICE_LEVEL_Z:` — без пояснения семантики.

**Аналитик ОБЯЗАН** догадаться что это Service-Level Z по **контексту использования** (применяется с `STDEV.P × SQRT(L)` в формуле `safety_buffer`) либо по литературе (Z=1.65 → 95% service level — стандартная табличная величина).

**Типичная legacy-мотивация:** разработчик 3 года назад hardcoded Z в ячейку, потому что «так делают», без объяснительной записки для следующего аналитика. Это classic «knowledge bleed» в legacy VBA — когда следующий аналитик тратит часы на «восстановление намерений».

**Demo-назначение:** показывает механику разбора «магических чисел» через контекст использования, а не через документацию.

### 3.2 NON_OBVIOUS_2: INCIDENT_2024_CORRECTION = 0.92 как cell-content proxy для legacy defined name

**Где:** sheet `forecast`, ячейка **`H22` = 0.92** (значение -8% к заказу для категории «молочка» как legacy-норматив после инцидента в 2024).

**Реализация в demo:** в реальном legacy VBA это был бы **named range** `post_incident_2024_correction`, на который ссылается формула заказа через имя. **В нашем demo** — cell-content proxy:
1. xlsx_builder API **минимальный** — без `define_name()` helper (не входит в Task 0 scope);
2. cell-content **эквивалентен по видимости** для аналитика: видишь label `INCIDENT_2024_CORRECTION` в `J7` + значение `0.92` в `H22`;
3. parity_check работает одинаково с обоими подходами (read cached value vs reference).

**Demo-назначение:** показывает паттерн «говорящего имени» в формулах — как аналитик разбирает «почему именно -8%?» через контекст имени.

## §5 Почему это НЕ реальные данные ВкусВилла

| Параметр | Значение в демо | Что оно НЕ является |
|----------|-----------------|----------------------|
| SKU names | «Молоко 3.2% 1л», «Крупа гречневая 800г», «Напиток газир. 1л» | **Модельные** SKU — выдуманные для демо |
| `baseline_daily` | 35 / 12 / 22 | **Модельные** значения, отражающие порядок величин, **НЕ** измеренные продажи |
| Weekday pattern | [1.10, 1.00, …***REMOVED*** | Типичная форма «пт-сб пик» из **общепринятых** retail-паттернов, **НЕ измерено** для точки ВкусВилл |
| Drift +0.5%/week | Синтетика для наглядности | В реальном инструменте drift может быть нулевым или сезонным |
| `current_stock` | 10 / 15 / 20 | **Произвольные** значения для демонстрации формулы, **НЕ** реальные остатки склада |

Все параметры — **воспроизводимые** (seed=`base_date=2025-06-02`), **детерминированы**, документированы в этом файле. Никакого RNG.

**Честное позиционирование:** demo-skill показывает **как мы подходим к разбору legacy Excel/VBA инструментов** — а не что мы воспроизвели реальный инструмент ВкусВилла. Этот демо-файл — **симулятор реальной задачи**, не её прямая реализация.
