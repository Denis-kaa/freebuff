# ADR-010 — Feedback calibration determinism (P14)

> **Статус:** Accepted
> **Дата:** 2026-08-23
> **Связано:** `CALIBRATION.md`, `ROADMAP.md` P14, `STORAGE.md` (feedback table)

## Контекст

P14 требует «measurable quality improvement» без opaque-решений. Нужно связать
пользовательский feedback с порогами матчера, не вводя LLM и не делая
авто-изменений, которые нельзя объяснить и откатить.

## Решение

1. **Детерминированная калибровка** (`app/calibration/engine.py`): выборка
   (score, label) из `feedback` + сохранённых `MatchDecision`; порог accept,
   максимизирующий accuracy; кандидаты — наблюдаемые score.
2. **Рекомендация без авто-apply**: `CalibrationResult` только информирует;
   изменение порогов — явная операция с новой версией профиля
   (`save_profile(version+1)`), старая версия и decisions сохраняются.
3. **Отсутствие decision у feedback-записи** исключает её из выборки —
   рекомендации опираются только на подтверждённую историю.
4. **Минимальный размер выборки** (`min_samples=3`): до накопления evidence
   рекомендация не выдаётся.

## Альтернативы

- **LLM-ранжирование/калибровка** — недетерминировано, дорого, требует
  основания для обработки контента; отложено (опционально, P14-track).
- **Авто-применение порогов** — нарушает explainability и откат; отклонено.
- **Grid-поиск по интервалу** — сложнее без выигрыша для MVP; кандидаты-score
  дают те же максимумы accuracy.

## Последствия

- P14 «calibration» закрыт на уровне инструмента; ранжирование — отдельный track;
- each profile-version остаётся стабильной: рекомендации всегда сравнимы с текущей;
- CLI-интеграция `--calibrate` остаётся будущей (после pilot, на реальных данных).
