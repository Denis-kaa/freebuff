# ADR-013: Jobseek (Supply Mode) — Outreach-модуль для поиска работы/заказов

**Статус:** Accepted (Implemented)
**Дата:** 2026-08-23
**Вызвано:** запрос пользователя — расширить парсер для поиска работы (jobseek), добавить apply-ссылки, исследовать новые источники.

---

## Контекст

Система изначально спроектирована как demand-парсер: ищем публикации, где *кто-то ищет услугу* (intent = demand). Пользователь хочет дополнительный режим: искать публикации, где *предлагают работу/заказ* (supply), т.е. reverse-поиск — «аутрич-модуль».

Запрос включает: (a) поиск работы для себя, (b) apply-ссылки в карточках, (c) исследование новых источников (Kwork, Superjob, Avito, YouDo, Профи.ру и др.).

---

## Решение

### 1. `SearchMode` в `SearchProfile` (P3-контракт)

```python
class SearchMode(str, Enum):
    DEMAND = "demand"    # ищем «ищут услугу» (классика)
    SUPPLY = "supply"    # ищем «предлагают работу/заказ» (jobseek)
```

- Обратно совместимо: по умолчанию `DEMAND`.
- Один профиль = один режим. За двумя режимами — два профиля.

### 2. Matcher: intent-гейт по режиму

| Режим | offer-формулировка («ищем разработчика») | demand-формулировка («нужен разработчик») |
|--------|------------------------------------|------------------------------------|
| `DEMAND` | REJECT (без demand-сигнала) | ACCEPT при совпадении |
| `SUPPLY` | intent-бонус к score | не reject (вакансии часто пишут «нужен») |

SUPPLY-режим: offer-формулировки дают +0.1 к score и НЕ являются причиной отклонения.

### 3. Apply-ссылки (официальный механизм площадок)

- HH API отдаёт `apply_alternate_url` — официальная ссылка для отклика. Адаптер кладёт её в `metadata["apply_url"***REMOVED***`.
- `render_card()` показывает кнопку «Откликнуться» при наличии `apply_url`.
- **Никаких авто-откликов** (спам-риск). Apply — всегда ручное действие пользователя по ссылке.
- Для trudvsem: у вакансий есть `vac_url` (ссылка на страницу вакансии), которая уже выводится как «Открыть источник».

### 4. Новые источники (research 2026-08-23)

| Источник | API | Статус |
|----------|-----|--------|
| **SuperJob** | `api.superjob.ru` + публичная оферта | `allowed` — официальный API, требует регистрации приложения |
| **Kwork** | нет официального API | `blocked` — только неофициальные скрейперы, нарушает ToS |
| **Avito** | API для бизнеса (вакансии через платформу) | `blocked` — требует договора с Avito |
| **YouDo** | нет открытого API | `blocked` — партнёрская программа (веб-форма, не API) |
| **Профи.ру** | нет API для парсинга | `blocked` — закрытая экосистема |
| **FL.ru** | нет API | `blocked` — скрейпинг явно запрещён |
| **Rabota.ru / Zarplata.ru** | нет открытого API | `blocked` |

**SuperJob** — единственный новый кандидат с официальным API. Требует отдельной регистрации приложения (по аналогии с HH).

### 5. Что НЕ делаем (anti-spam)

- ❌ Авто-отклики (через сессионный парсинг / эмуляцию браузера).
- ❌ Сбор контактов заказчиков (email/телефон).
- ❌ Direct-messaging через площадки (Kwork/Avito DM).
- ❌ Создание аккаунтов / ботов для обхода ограничений.

---

## Последствия

- **Позитивные:** система покрывает оба сценария — «ищут услугу» и «предлагают работу». Apply-ссылки делают карточки actionable.
- **Негативные:** два режима = два профиля = две очереди. Смешивать demand/supply в одном профиле нельзя.
- **Риски:** SuperJob API требует приложения (как HH) — не блокер, но отдельный шаг активации.

---

## Альтернативы

- **Раздельные pipeline'ы** для demand/supply — избыточно, когда один матчер с режимом решает задачу.
- **Авто-отклики** — отброшено: спам-риск, блокировки, нарушение ToS площадок, нет данных о качестве заказчика.
