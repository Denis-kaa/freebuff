# STEPS.md — журнал шагов Model Dispatcher (081_19_model_dispatcher)

> Живой журнал: что сделано и ПОЧЕМУ приняты решения.

## Шаг 1: Исследование платформы и аудит (Этапы 1–2 промт81)

**Что:** изучены корневая структура, каноны (`AGENTS.md`, `docs_10/core/PROJECT_RULES.md`),
существующие скрипты (`prompt_dispatcher.py`, `prompt_queue.py`, `model_gateway.py`,
`freebuff_plugin_03/wrapper.py`/`monitor.sh`), очередь `pompts_11/`.

**Почему:** 081_19_model_dispatcher требует следовать методологии платформы, не выдумывать
структуру. Классифицировали найденное: готовые скрипты → основа (оставляем),
отдельного «Model Dispatcher» не было → создаём как проект по канону.

**Вывод:** 90% функционала уже есть; недостающее — «человеческий» слой
(чтение экрана, выбор доступной модели по убыванию, таймер с сохранением).

## Шаг 2: Уточнение требований у пользователя

**Что:** пользователь уточнил: freebuff — это TUI (а не только CLI); выбор
провайдеров есть в самом приложении (сейчас выбран GLM 5.2 — подтверждено
`settings.json: freebuffModel: z-ai/glm-5.2`); скрипт должен имитировать
человека — смотреть доступные мощные модели и выбирать по убыванию;
контролировать вылеты и таймер (~1 час); «часовая сессия» не исчезает —
можно прерваться и вернуться через 3 часа; промты собираются в
`pompts_11/user/`, после выполнения → `done/`.

**Почему:** дизайн драйвера определяется реальным поведением инструмента.

## Шаг 3: Инициация проекта (каркас)

**Что:** создан `projects_17/model_dispatcher/` по PROJECT_RULES §2:
MANIFEST, LESSONS, decisions (ADR-001/002/003), ROADMAP, README, RUNNABLE,
CHECKLIST, STEPS.

**Почему:** проект = контейнер контекста (канон платформы).

## Шаг 4: config.yaml

**Что:** таймер сессии 60 мин по умолчанию, приоритет моделей
(GLM → MiMo → MiniMax → DeepSeek free), маркеры недоступности, пути очереди,
логирование.

**Почему:** пользователь: «настройки в конфиге, по умолчанию 1 час на сессию».

## Шаг 5: md_models.py

**Что:** `parse_screen()` (детект строк моделей по keywords + маркеры
недоступности) и `pick_model()` (выбор первой доступной по приоритету,
free-fallback на DeepSeek). 7 тестов.

**Почему:** выбор «какой мощной модели доступна» = эвристика по экрану TUI
(ADR-001); точный layout зависит от версии freebuff, поэтому keywords/markers
вынесены в конфиг.

## Шаг 6: md_queue.py

**Что:** самодостаточная файловая очередь с форматом, совместимым с
`pompts_11/` (шапка `# TASK:` + метаданные + `---` + тело + `## Отчёт`).
6 тестов.

**Почему:** reuse структуры очереди, но без жёсткой зависимости от
платформенных скриптов (PROJECT_RULES §7, ADR-003).

## Шаг 7: md_freebuff.py

**Что:** tmux-драйвер: `start`/`stop`/`capture`/`wait_for_screen`/
`select_best_model`/`send_prompt`/`monitor`/`save_context`. Все tmux-операции
инъектируемы. 8 тестов.

**Почему:** имитация человека (ADR-001) + таймер без kill (ADR-002) +
тестируемость без реального tmux.

## Шаг 8: dispatcher.py (CLI)

**Что:** `--check` / `--models` / `--dry-run` / `--once` / `--all` / `--screen`.
Цикл: user/ → running/ → freebuff → done|failed|timeout-saved. 6 тестов.

**Почему:** пользователю нужен простой интерфейс: «положил промт в user/,
запустил --once».

## Шаг 9 (план): Боевой прогон

Когда инстанс freebuff свободен (сейчас занят живой сессией — мы в ней):
положить промт в `pompts_11/user/`, запустить `--once`, проверить done/.
При таймауте — проверить `.md_state/<task_id>.json` и продолжение через
`--continue`.

## Шаг 10 (план): Авто-resume отложенных сессий

Задачи в `running/` с пометкой «Отложено» — авто-продолжение при освобождении
инстанса (этап 9 ROADMAP).
