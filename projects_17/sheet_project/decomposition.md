# DECOMPOSITION — sheet_project (D2 конфигурируемый генератор Excel-дашбордов)

> **Роль:** decomposer (AI System Decomposer)
> **Метод:** bounded contexts + разделение «неизменяемое (ядро) / изменяемое (CONFIG)».

## Принцип декомпозиции

Главный критерий D2: **структура XLSX, данные, стили и проверки отделены от кода генератора**. Декомпозиция строится так, чтобы ядро (GENERATOR) не содержало ни одного зашитого названия листа, ни одной ветки `if project_dashboard:`. Всё изменяемое выносится в CONFIG / DATA / STYLES.

## Bounded contexts

```
CONFIG (описание) ──┐
DATA (вход) ────────┼──→ GENERATOR (ядро) ──→ XLSX ──→ VALIDATOR (проверка)
STYLES (визуал) ────┘
```

| Контекст | Ответственность | Изменяемость |
|----------|-----------------|--------------|
| **CONFIG** | декларативное описание структуры (листы, колонки, типы, KPI, блоки, карточки, справочники, формулы, правила) | изменяемое (данные) |
| **DATA** | нормализованные входные данные (не зависят от источника) | изменяемое (данные) |
| **STYLES** | визуальная конфигурация (цвета, шрифты, границы, ширины) | изменяемое (данные) |
| **GENERATOR** | ядро: создаёт XLSX из CONFIG+DATA+STYLES | **неизменяемое** (ядро) |
| **VALIDATOR** | структурная проверка результата (не расчёт формул) | неизменяемое (ядро) |

## Границы контекстов

- **CONFIG → GENERATOR:** CONFIG — чистые данные (dict/dataclass), никогда не исполняемый код. GENERATOR читает CONFIG, не знает конкретного шаблона.
- **DATA → GENERATOR:** DATA нормализован и source-agnostic. Источник (Python/CSV/JSON/Google Sheets/API/Bitrix24) — будущий адаптер, не часть ядра.
- **STYLES → GENERATOR:** стили применяются декларативно в конце генерации, ядро не знает конкретных цветов.
- **GENERATOR → XLSX → VALIDATOR:** validator перечитывает сгенерированный XLSX и сверяет с CONFIG (structural). Расчёт формул (calculation) — отдельный слой (LibreOffice), не в validator.

## Неизменяемое (ядро) vs изменяемое (CONFIG)

**Неизменяемое:**
- механика создания XLSX (openpyxl workbook/sheet);
- общие функции форматирования;
- создание формул, validation, таблиц;
- общая система ссылок и ошибок;
- механизм структурной проверки.

**Изменяемое (через CONFIG):**
- названия и порядок листов;
- поля, типы, обязательность;
- блоки Dashboard, KPI, карточки (с вариантами);
- стили, справочники, правила;
- конкретные формулы, условное форматирование.
