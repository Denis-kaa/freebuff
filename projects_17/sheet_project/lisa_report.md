# LISA Report (LISA-3 AI-Native Complexity Estimator)

**Описание:** # PROJECT BRIEF: sheet_project (D2 — конфигурируемый генератор Excel-дашбордов)

## 1. PROJECT OVERVIEW
- **Название:** sheet_project
- **Тип:** Python Library / CLI (local script + reusable core)
- **Цель:** Спроектировать и реализовать архитектуру **D2** — конфигурируемый генератор Excel-дашбордов, в котором структура XLSX, данные, стили, правила отображения и проверки **отделены от кода генератора**. Первый результат — рабочий эталонный XLSX для управления проектами, полностью собранный через эту архитектуру. Затем та же архитектура позволяет создавать другие XLSX без переписывания ядра генератора.
- **Целевая аудитория:** проектные менеджеры и команды, которым нужны Excel-дашборды для управления проектами (и потенциально — продажи, производство, другие процессы).

## 2. КЛЮЧЕВАЯ ИДЕЯ (архитектурный контракт)

```
CONFIG → GENERATOR → XLSX
             ↑
           DATA
           STYLES
           VALIDATION
```

- **config** — декларативное описание структуры (листы, колонки, KPI, блоки, карточки, справочники, формулы, правила);
- **data** — нормализованные входные данные (не зависят от источника);
- **generator/builder** — ядро, создающее XLSX (без бизнес-логики конкретного шаблона);
- **validator** — структурная проверка результата;
- **styles** — визуальная конфигурация.

## 3. FUNCTIONAL REQUIREMENTS (MUST HAVE)

### 3.1 Конфигурируемость (ядро D2)
- Структура XLSX задаётся CONFIG, а не кодом генератора.
- Изменение CONFIG даёт другой XLSX **без правки ядра GENERATOR**.
- Никакого отдельного генератора под каждый шаблон.
- Никаких зашитых названий конкретных листов в ядре.

### 3.2 Входные контракты
- **CONFIG:** листы, порядок листов, колонки, типы полей, обязательные поля, связи, KPI, блоки Dashboard, карточки (с вариантами), справочники, выпадающие списки, условное форматирование, порядок элементов, настройки отображения.
- **DATA:** проекты, задачи, статусы, дедлайны, справочники, другие сущности — нормализованные, независимые от источника (Python / CSV / JSON / Google Sheets / API / Bitrix24 в будущем).
- **STYLES:** цвета, шрифты, размеры, границы, выравнивание, ширины колонок, визуальные параметры.
- **GENERATION OPTIONS:** имя выходного файла, выбранный шаблон, дополнительные параметры генерации.

### 3.3 Первый эталонный шаблон
- Рабочий проектный XLSX для управления проектами, собранный через новую архитектуру.
- Только те элементы, которые реально нужны первому рабочему сценарию (без D3/D4-функциональности ради будущего).

### 3.4 Validator (структурная проверка)
Минимум: существование листов, порядок листов, наличие обязательных колонок, соответствие CONFIG↔DATA, наличие ожидаемых формул, корректность формульных ссылок на уровне структуры, наличие validation и корректность его диапазонов, наличие hyperlinks, отсутствие ссылок на несуществующие листы, наличие Dashboard-блоков, соответствие карточек CONFIG.
Разделять **STRUCTURAL VALIDATION** (сами) и **CALCULATION VALIDATION** (отдельный слой, требует Excel/LibreOffice calculation engine).

## 4. NON-FUNCTIONAL REQUIREMENTS
- **Без VBA, без макросов** (жёсткое ограничение).
- openpyxl **не вычисляет формулы** — только пишет их (не утверждать «формула посчитана», если движок расчёта не выполнялся).
- Без внешних интеграций на первом этапе (Bitrix24 / Google Sheets / API) — только интерфейс для будущего подключения.
- Архитектура должна оставаться достаточно простой для развития (KISS).
