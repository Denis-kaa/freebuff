Вопросы вердикта (`layout` / `layout_with_cut_contour` — «макет готов?») умирали на UI:
ответ сотрудника логировался в аудит S4, но **не возвращался в расчёт**. «Макета нет»
означала, что сотруднику нужно вручную добавить позицию дизайна — ровно то, что Smart
Order должен был убрать (промт_6 §1: сотрудник не обязан помнить технологию).

## 3. Решения по ходу (и почему)

1. **Позиция дизайна, а не параметр wide** — design-калькулятор уже умеет «Макет под
   плоттерную резку» (Простой 500 / Стандарт 1000 ₽); wide-флагов для макета нет.
   Доп. позиция в черновике — сотрудник видит её и может сменить уровень.
2. **Уровень по умолчанию «Простой»** — сотрудник правит в позиции; не делаем вопрос
   об уровне (минимум вопросов — принцип интервью §4).
3. **«no» без подтверждённой OP-22 → ничего** — иначе ответ на производственный вопрос
   тихо создавал бы услугу без контекста. Не молча: позиция просто не возникает,
   вопрос остаётся вопросом.
4. **Валидация громкая (400)** — поле/ответ вне закрытых наборов = ошибка клиента,
   не тихое игнорирование (единый стандарт ANTI-6b/CON-8).
