## 2. Правила «чего НЕ трогать» (найденные ошибки-уроки)

- **BR-W1:** один и тот же материал должен называться одинаково во всех словарях («Самоклеющаяся/Самоклеящаяся/Самоклейка» — 3 варианта в 3 файлах).
- **BR-W2:** прайс-позиции с ценой 0 («Вывеска» в M1, PRICE_PER_CM в Sign) должны блокировать расчёт или явно помечать «цена не задана» — сейчас молча дадут 0.
- **BR-W3:** доп-услуга обязана иметь единицу — отсутствие в legacy было причиной дрейфа люверсов (м vs шт).

## 3. Целевая модель правил (PROPOSED — data-driven)

```
BusinessRules (general.json, редактируемое)
├── tax_rate: 0.06            # одно место вместо трёх
├── rounding: {"mode": "none|up|to_05", "precision": 2}   # PROPOSED — в коде сейчас нет
├── min_order: {riso: 500, digital: 500, wide: 0, ...}
├── urgencies: [PROPOSED: нет в исходниках]
└── units: {input → calculation → display}   # MATERIAL_MODEL.md §4
```

Каждое BR-01…BR-17 переезжает в конфиг калькулятора (input_schema + params), вычисление остаётся в pure-функции движка printcalc. Менять правило = менять данные, не код. Что **невозможно** вынести в данные без кода: сама формула нового типа расчёта (например, новый калькулятор) — для этого существует реестр калькуляторов + новый `compute()` (см. CALCULATOR_ARCHITECTURE.md).
