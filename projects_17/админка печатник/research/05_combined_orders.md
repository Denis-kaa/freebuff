## Модель разборки мультизаказа (по §19 промта)

```json
{
  "customer_request": "исходное сообщение",
  "items": [
    {
      "item_id": 1,
      "intent": "document_photo",
      "span_in_text": [0, 18],
      "known": {"document_type": "passport_rf"},
      "missing_required": ["quantity_block", "photo_subject_ready"],
      "confidence": 0.9
    },
    {
      "item_id": 2,
      "intent": "photo_print",
      "span_in_text": [20, 44],
      "known": {"size": "10x15", "quantity": 20},
      "missing_required": ["files"],
      "confidence": 0.95
    }
  ],
  "unassigned_fragments": [],
  "order_confidence": 0.92
}
```

## Правила разборки (выведены из материала, D-B уровни)

1. **Сегментация по служебным словам перечисления** («и», «ещё», «плюс», запятая) — D.
2. **Привязка параметров к ближайшему intent слева** («20 штук» относится к фоткам, не к баннеру) — D.
3. **Каждая позиция получает свой confidence; заказ в целом — минимум из позиций** — дизайн-решение из системы §28.
4. **Вопросы формируются по позициям, а не по заказу**; объединять можно только однотипные уточнения — D.
5. **Никогда не «съедать» фрагмент без интерпретации**: непонятый кусок → `unassigned_fragments` → обязательный вопрос — принцип анти-галлюцинации §2.

## Пример разбора (иллюстрация логики §30, НЕ данные)

Сообщение-агрегат (из профиля услуг салона как источника вероятного запроса):
«Мне фото на паспорт, 20 фоток 10×15 и табличку на дверь»

```
ITEM 1  document_photo  known: document_type=passport_rf
        missing: пакет/штуки, срочно ли
ITEM 2  photo_print     known: size=10x15, quantity=20
        missing: files
ITEM 3  sign            known: placement=дверь
        missing: material, size, текст/макет
```
Минимальное уточнение: «На паспорт — пакетом 6 шт или нужно больше? Фотки 10×15 — 20 шт, файлы с собой? По табличке — какой размер и что написать?»
Статус: иллюстрация. Фактические правила — из 14_dialog_rules.md.
