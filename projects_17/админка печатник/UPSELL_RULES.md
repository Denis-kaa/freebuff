# UPSELL_RULES.md — контекстные рекомендации доп-услуг

> Статус: COMPLETE (проект) · Дата: 2026-09-07 ·
> Принцип §25: рекомендации контекстные (условие → действие), не постоянный список. Каждая доп-услуга: название, описание, цена, единица, условие применения, правило рекомендации, отключаемость, редактируемость владельцем.

## 1. Правило (data-модель)

```json
{
  "id": "R-03",
  "when": {"usage": "улица", "area_sqm": [">=", 3]},
  "suggest": [{"add": "grommets", "why": "крепление на улице"}, {"add": "edge_protection", "why": "ветровая нагрузка"}],
  "priority": 10,
  "editable": true, "enabled": true
}
```

Механизм: после каждого ответа правила пересчитываются; сработавшие показываются карточкой «+ предложение» с кнопкой добавить/отклонить (никогда не добавляются молча). AI-слой может только ранжировать правила, не создавать их (AI_ASSISTANT_CONCEPT.md).

## 3. Анти-правила (не предлагать)

- Не предлагать люверсы на холсте (галерея натяжки) — INFERRED, правится владельцем.
- Не предлагать второй раз то, что клиент отклонил в этом заказе (запоминается в сессии расчёта).
- Не добавлять ничего автоматически в цену: только показ с объяснением «почему» (§25).
- Лимит: ≤ 2 активных предложения на шаг — иначе анкета (§23).

## 4. Куда попадает рекомендация

1. В диалог (SALES_SCRIPT.md, шаг B) с формулировкой и ценой.
2. В breakdown результата отдельной строкой (если добавлена).
3. В операции заказа (люверсы → операция «установить люверсы», OPERATIONS_CATALOG.md).
4. В материалы (люверсы = расходник, MATERIAL_MODEL.md).

## 5. Настраиваемость

Все правила — в `upsell_rules.json`: включить/выключить, поменять условие/цены/приоритет без кода; новые правила создаются владельцем в разделе «Правила рекомендаций» (ADMIN_CONFIGURATION.md). Ограничение честно: правило, требующее нового поля расчёта, добавляется вместе с полем schema (данные), но новая физическая обработка — только с новым compute (движок).
