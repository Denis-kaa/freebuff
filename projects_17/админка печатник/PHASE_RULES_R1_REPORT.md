## 2. Единицы размера — каскад закреплён golden-примерами

Без явной единицы в тексте (`(мм/см/м)` перекрывает всё):

| Пример | Разбор | Источник |
|---|---|---|
| «Баннер 3×6» | обе ≤ 10 → **метры** = 3000×6000 мм | промт_6 §4.3 |
| «Наклейка 50×30» / «Бэклит 80×60» | обе ≤ 100 → **см** = 500×300 / 800×600 мм | §4.1, §4.4 |
| «200×100» | иначе → **мм** | районные прайсы |

Внутренняя единица OrderDraft.size_mm — мм (как consumption/units.py);
`facts["size"]` — каноническая строка «3000x6000» (мм) для when_facts-equality.

## 3. Честная фиксация: парсер v2 не знает wide-продуктов (проба перед кодом)

Живая проба парсера на 10 примерах (скрипт удалён после пробы, вывод в истории сессии):

- «Наклейка 50×30…» → items: **cnc** (ложечный матч «резк»), unknown: наклейка/50×30/шт/+/по/контуру;
- «Баннер 3×6 + люверсы 30 см» → items: пусто, всё в unknown;
- «Бэклит 80×60…» → items: **cnc**, unknown: бэклит/80×60/dpi/…;
- прайсовые примеры (ксерокс/фото/визитки) — распознаются корректно.

Следствие (зафиксировано в docstring normalize.py): нормализатор читает
ТЕКСТ напрямую; ParseResult используется только как источник qty (если
парсер распознал тот же продукт) и unknown. Контракт парсера
(items/unknown/needs_operator/reasons/segment_id/volume_hints) не
менялся — тест `test_parse_result_fields_superset` закрепляет.

## 4. Семантика приоритета продуктов (найдено тестом, не предположением)

«Наклейка для оформления витрины» = **наклейка** (+факт vitrine), а не
«оформление витрины»: конкретный продукт сильнее контекстной услуги.
Порядок паттернов: бэклит → баннер → наклейка → оформление витрины
(последний — фолбэк для текста без конкретного продукта). Тест
`test_vitrine_fact_also_for_sticker_mention` закрепляет; сам тест словил
ошибку первого порядка паттернов — написан раньше фикса.

## 6. Открытые вопросы (не блокируют S2)

1. **Ширина рулона бэклита** — в документации проекта НЕ зафиксирована;
   в сиде 1520 мм с пометкой (как закупочные цены — подтверждается
   владельцем при заполнении реестра). Влияет только на расход движка.
2. **Подсветка бэклита** — LED/блок питания отсутствуют в каталоге
   операций; правило BACKLIT_ILLUMINATION_CLARIFY только уточняет.
   Если подсветка станет платной операцией — REGISTER-FIRST → новый код.
3. **«12 м2» (площадь без размера)** — не извлекается в facts (нет ключа
   area в KNOWN_FACT_KEYS). Для витрин площадь — главный параметр;
   кандидат в schema_version 2 через REGISTER-FIRST, вопрос Денису.
4. **qty-фолбэк парсера** — «наклейка 5» (без «шт») qty не получает:
   число без слова шт рядом с wide-продуктом парсер тоже не видит
   (продукт в unknown). Решение (жадный фолбэк) отложено до S2/живых
   кейсов, чтобы не выдумывать семантику.
