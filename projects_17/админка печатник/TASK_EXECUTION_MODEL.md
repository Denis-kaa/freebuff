# TASK_EXECUTION_MODEL.md — помощник выполнения заказа

> Статус: COMPLETE (проект) · Дата: 2026-09-07 · Цель: сотрудник получает не только «сколько стоит», но и «что теперь делать, в какой программе, в какой последовательности и как проверить». Всё PROPOSED (в коде нет); привязки — к EXISTING услугам.

## 1. Компоненты

```
Заказ (статус) → план операций (ORDER_WORKFLOW) → карточка операции
     ↓                                        ↓
Режим новичка («Я не знаю, как это сделать»)   Дерево решений способа
     ↓                                        ↓
Пошаговый проводник: Шаг → [Готово | Нужна помощь] → … → ГОТОВО
```

## 2. Режим новичка (§7 промта)

Сотрудник выбирает проблему («фото не подходит для документа») → проводник:

```
Шаг 1. Проверяем фон.                        [Готово] [Не знаю, как проверить]
Шаг 2. Проверяем положение головы.           [Готово] [Нужна помощь]
Шаг 3. Исправляем наклон. Способ: [Photoshop] [AI] [Другой]   (SOFTWARE_CATALOG + AI_SAFETY)
Шаг 4. Проверяем результат (чек-лист).        [Готово]
→ ГОТОВО: операция закрыта, критерии выполнены
```

Каждый «Не знаю» раскрывает: определение (глоссарий), как проверить (2-3 действия), типовые ошибки. Система — внутренний наставник: не выполняет за сотрудника, а ведёт по шагам.

## 3. Дерево решений (§6)

Дерево — данные (`decision_tree.json`): узел-вопрос → ветки-способы, у каждого способа: когда использовать, плюсы/минусы, что проверить после, пометка доступности ПО. Пример «Подготовить фотографию» — SOFTWARE_CATALOG §3. Система объясняет, почему выбран способ (строка «потому что …»).

## 4. План выполнения заказа (§2 промта)

Для заказа «баннер 3×1, 440г, 2 шт, люверсы 50 см» система показывает сгенерированный план (ORDER_WORKFLOW) с возможностью открыть детальную инструкцию каждой операции:

```
1. Проверить макет (CL-MACET)        [ ]
2. Подготовить файл (OP-02)          [ ]
3. Проверить материал (CL-BANNER)    [ ]
4. Напечатать (Roland, 12 м²/час)    [ ]
5. Подрезать (OP-09)                 [ ]
6. Люверсы 16 шт, шаг 50 см (OP-13)  [ ]
7. Контроль качества (OP-20)         [ ]
8. Упаковать и выдать (OP-21)        [ ]
```

Числа операций/материалов — из расчёта движка; время — оценочное поле операции.

## 5. Критерии готовности (§10)

Закрытие операции = прохождение done_criteria (не просто кнопка). См. OPERATIONS_CATALOG §4.

## 6. Роли и границы

- Наставник подсказывает, не требует; ветеранские режимы скрывают подсказки.
- Ошибки ведения новичка видны владельцу в истории заказа (обучение, не наказание).
- AI-советы внутри проводника подчиняются AI_SAFETY_RULES.
