## 2. Одинаковые формулы/параметры — кандидаты на общий движок

1. **Диапазонный прайс по объёму** — 4 реализации: Riso TIERS (тираж), Wide `get_price` (площадь), Digital PRODUCT_PRICES (тираж). Одинаковая логика «найди строку, где min≤x<max, иначе последняя» (wide_format.py:114-122). → общая сущность `PriceTier`.
2. **Пара cost/sell на каждой позиции** — Wide, Tablichki, Sign. → единый `PricePair`.
3. **Люверсы по периметру с шагом** — Wide (шаг 50, `is_grommet`) и Tablichki (шт). Одна формула = ceil(периметр/шаг). → общая доп-услуга.
4. **Площадь = Ш×В×кол-во** — везде. → базовая функция нормализации единиц (мм/см/м → м²).
5. **Монтаж по высоте** — Wide (7 фиксированных вариантов) и Sign (база + % по высоте). Два паттерна одной услуги.
6. **Налог 6% + наценка** — Riso/Tablichki/Sign. → общие `BusinessRules`.

## 4. Ответ на ключевой вопрос §41 (краткий)

На базе обнаруженного функционала строится **не каталог калькуляторов, а помощник приёма и выполнения заказа**: услуга (данные) → вопросы (schema) → расчёт (движок printcalc, уже реализован для Riso) → рекомендации → скрипт → заказ → операции → материалы. 6 из 8 модулей уже хранят цены в JSON — целевая data-driven модель (§37) реализуема без «переписывания бизнеса»: перенос = перенос данных, не логики. Полный ответ — в финальном отчёте.
