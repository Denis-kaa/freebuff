## 1. Что представляет собой система

**FACT.** «Печатникъ» — операционная система типографии/фотоцентра/полиграфического
производства, а не набор калькуляторов. Целевая цепочка (промт_4 §60, MVP-цикл):
свободный ввод → распознавание → параметры → недостающие вопросы → производственные
подсказки → калькулятор → расход материалов → стоимость → смета → заказ → производство
→ QC → выдача. Интерфейс — web-приложение FastAPI + SQLite на сервере whimco
(`http://185.233.184.192:8300`, systemd `printcalc-web.service`).

**FACT.** Владелец — Денис; все цены и ценовые решения — его прерогатива
(рыночные исследования калибруют, не заменяют — RESEARCH_ADOPTION_PLAN, ПРОТИВОРЕЧИЕ 1).
ИИ никогда не источник цены (AI_SAFETY_RULES §38).

## 2. Архитектура

**FACT.** Четыре слоя, разделённые контрактами (Additive Architecture, низкая связанность):

```
printcalc/engine/          — CALC-контракт: spec.py (CalculatorSpec/FieldSpec frozen),
  registry.py              — реестр «id → (spec, compute)», закрытый словарь ANTI-6b,
  validate.py              — валидация по схеме, первая ошибка прерывает (legacy-паритет),
  result.py                — CalcResult frozen (price/price_no_tax/cost/net_profit/lines/warnings/details),
  consumption/             — движок расхода: Nesting(roll.py) → Consumption(engine.py) → Cost(будущее) → Pricing
printcalc/calculators/     — 8 портов legacy, pure-функции + frozen-конфиги (riso, wide, tablichki,
                             digital, sign, cnc, design, cost)
printcalc/assistant/       — intents TOP-20 (мост «фраза клиента → параметры», без калькуляторов)
printcalc_web/             — FastAPI-слой: db.py (19 таблиц) → store.py (2981 стр., вся доменная логика)
                             → api.py (72 роута) → views.py (10 страниц) → static/*.js
printcalc_web/rules/       — v7 Smart Order: schema.py (YAML-паки), normalize.py (OrderDraft),
                             engine.py (RuleVerdict), packs/{sticker,banner,backlit}.yaml
printcalc_web/{pricing,emailer,outbox,margin,telegram,p0_services,export}.py — сервисные модули
```

**FACT.** Тесты: 403 passed (26 файлов: golden × 8 калькуляторов, store, api, consumption,
rules, outbox…). `mypy src/` — clean (70 файлов); `mypy tests/` — 22 ошибки в 3 старых
тестовых файлах (см. §8). Интеграционные тесты используют собственный ASGI-клиент
(`tests/asgi_client.py`) из-за несовместимости starlette 0.27 / httpx 0.28.

## 5. Что действительно работает (проверено кодом и смоуками)

**FACT:**
1. Калькуляторный конвейер: `calculate(registry, id, inputs)` = валидация схемы → compute.
   8 калькуляторов, паритет с legacy закреплён golden-тестами (например Riso: формула
   `price = (base_rate*qty + (master+extras)*(1+markup)) / (1 - tax)`, min-order до диапазона).
2. Расход материалов: ROLL_NESTING (с поворотом при непомещении + ручная ширина рулона —
   решение Дениса), SHEET_NESTING; разделение production ≠ billing (§7/§18); трассировка.
   Подключён к заказам wide/Табличек через `consumption_json`.
3. Полный цикл сметы: расчёт → estimate (серверные цены) → accept+snapshot → заказ без
   ручного переноса (§9).
4. Склад: резерв по расходу заказа, ADJUST-инвентаризация, план закупок
   Need = Required − Available − Reserved, автосписание при завершении последнего задания.
5. Производство: каталог-данные, генерация заданий по триггерам, монтажные правила, QC-гард.
6. Inbox: Telegram-поллер (env, no-op без токена), парсер v2 (сегментация «и/плюс»,
   needs_operator, volume_hints), клиент-matching (telegram/email), заявки, сметы,
   ответы (6b: outbox + детерминированное письмо из сметы + SMTP/Telegram dispatch).
7. Аналитика: маржинальность Себестоимость↔прайс (SERVICE_COST_ROUTES закрытый словарь,
   Riso-мастер на партию 500, gaps с причинами).
8. P0 кассовые услуги: 20 позиций в 7 разделах, CSV round-trip «скачал → поправил в Excel →
   загрузил».
9. v7-правила: нормализатор OrderDraft → вердикты паков (наклейка+контур → OP-22/ready,
   бэклит без количества → ready_for_calculator=False), runtime-прайс wide.

   без супервизии отдельного процесса поллер зависит от жизненного цикла web-сервиса.
   (ASSUMPTION: для текущих объёмов достаточно.)

   `printcalc/assistant/intents.py` ссылается на него как на источник фраз (CR-01…CR-111).
   UNKNOWN: осознанно ли (как missing_registry) или упущение синка.
