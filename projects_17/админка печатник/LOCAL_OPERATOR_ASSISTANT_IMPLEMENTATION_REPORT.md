## 1. Что уже существовало

Аудит (A0/A1) показал, что вердикт-слой был способен больше, чем казалось:

- **Parser v2** (`parser.py`): мульти-заказ, перечисления, размеры «N на M» /
  «N×M», слова-тиража («шт», «листов»…), стемминг флексий, словарь из БД.
- **Нормализатор** (`rules/normalize.py`): OrderDraft, контур→режим резки,
  шаг люверсов, dpi, mounting_film, vitrine, usage, словесные «полметра».
- **Rules Engine** (`rules/engine.py` + packs `sticker/banner/backlit.yaml`):
  12 правил, контур→OP-22 (без ложного ЧПУ), golden-фраза S7.1 проходила.
- **Smart Order S0–S6**: `/api/parse`, `/api/order/analyze`,
  `/api/order/bridge`, `/api/suggestions/decision`, Question Engine через
  `missing`, аудит решений, цена только движком.
- Сид кассы P0 (42 позиции), полные тесты (481) и mypy.

## 2. Что изменено

- `rules/schema.py` — REGISTER-FIRST: факты `thickness_mm`, `material_hint`,
  `extra_sizes`; продукты «табличка», «фото на документы» (ANTI-6b: только
  редакция закрытых словарей).
- `rules/engine.py` — `RuleVerdict.warnings` + `"warnings"` в `to_json`;
  `_PACKAGE_POLICY_WARNINGS` (qty-политика фото, ТЗ §16).
- `p0_services.py` — сид «Бэклит (за м²)» 260 ₽/м² (C-грейд research/17) +
  синоним «табличка пвх».
- `parser.py` — decimal-comma защита токенизации, «резк» убран из ключей ЧПУ,
  **`qty_explicit`** (явно названное число vs дефолт) и не-тиражные
  «число+единица» («4 мм», «1440 dpi» больше не становятся тиражом).
- `rules/normalize.py` — словесные размеры «3 на 6», безопасный
  `_UNIT_TAIL_RE` (ПВХ-баг), толщина/материал-факты, `extra_sizes`,
  фильтр unknown- passthrough (распознанное не позорится как unknown).
- UI: роут `/assistant`, шаблон `assistant.html`, `static/assistant.js`,
  CSS-блок чата, пункт навигации «Помощник».

## 3. Какие пробелы parser исправлены

Семь проблем ТЗ §40-этап2 — все закрыты (доказано тестами §37):

1. contour → plotter (OP-22, НЕ ЧПУ) — было живо, закреплено тестом;
   ложный «резк»→ЧПУ удалён.
2. grommet step: «люверсы через 30» → `grommets_step_cm=30`.
3. backlit alias: «Бэклит» распознаётся нормализатором И парсером (сид).
4. print_quality: «качество 1440 dpi» → `dpi=1440`, число не становится qty.
5. finishing normalization: контур/поштучно/люверсы/накатка/загибка →
   закрытые токены KNOWN_FINISHINGS.
6. quantity policy фото: 6 шт при пакете 4 → warning; без конверсии.
7. decimal comma: «0,5 на 0,5» = 500×500 мм.

Дополнительно (найдено пробами): «Табличка ПВХ 4 мм» больше не даёт
qty=4 (толщина ≠ тираж); «ПВХ 4 мм» не читается как размер; unknown чата
чист на всех 7 фразах.

## 4. Как подключён чат

ТЗ §36 соблюдено: **чат = интерфейс, Smart Order = логика**. Новых
парсеров/движков НЕТ. Страница `/assistant` (views.py) → шаблон →
`assistant.js`, который вызывает только существующие API. Мульти-режим
контекста (follow-up «добавь/убери») — в v2-итерации (см. §12).

## 5. Какие режимы реализованы

Все 8 из ТЗ §18–26 в `assistant.js` (презентационный слой над вердиктом):
Быстрый, **Рабочий (дефолт)**, Подробный, Обучение, Только уточнения,
Производство, Продажа, Проверка. Переключение перерисовывает последний
вердикт без повторного запроса. Дополнительные предупреждения
(`warnings`) показываются во всех режимах, кроме «Проверка» (там это
отдельный блок «Конфликты»).

## 6. Как работают suggestions

Без изменений по контракту: предложения движка (`kind`, `label`, `reason`,
`options`, `rule_id`) приходят в вердикте; UI показывает кнопки
`[+ операция]` / `[без операции]` и апселлы; `kind=question` кнопкой не
становится (вопросы живут в `missing`). Авто-применения по-прежнему нет
(`auto=False` — константа движка v1).

## 7. Как используется suggestion_decisions

Существующий `POST /api/suggestions/decision` (§28 «не создавать новую
систему»): каждое нажатие кнопки пишет решение
(`accepted/rejected/…`, kind, token, source_text) в журнал;
`GET /api/suggestions/decisions` — аудит. Подтверждённые операции
накапливаются клиентом и уходят в мост как `accepted_operations`
(контракт S4: в цену попадает только подтверждённое).

## 8. Какие API использованы

- `POST /api/order/analyze` — текст → вердикт (S3);
- `POST /api/order/bridge` — вердикт + подтверждённые операции →
  `{calculator_id, params, result.price}` (S5; 400 при нехватке данных — §30);
- `POST /api/suggestions/decision`, `GET /api/suggestions/decisions` — аудит (S4);
- `GET /assistant` — страница чата; `/static/assistant.js`, `/static/style.css`.
