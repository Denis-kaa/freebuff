## 1. Единый реестр материалов (цель)

Сейчас материал живёт в 6 разных словарях с дублями и разной орфографией («Самоклеющаяся» / «Самоклеящаяся» / «Самоклейка»). Целевой реестр:

```json
{
  "id": "mat_banner440",
  "name": "Баннер 440 г/м²",
  "aliases": ["Баннер 440г", "Баннер (обычный)"],
  "unit": "м²",
  "purchase_cost": 80,            // ₽/м² — из equipment.json EXISTING
  "sell_in_pricelists": {"wide": 200},   // ссылки, а не копии
  "min_stock": 30,
  "supplier": null, "active": true
}
```

Калькуляторы ссылаются на материал по id; цена закупки — одна (уже есть в equipment.json: баннер 80 ₽/м², холст 220, самокл 180 и т.д.), цена продажи — своя у каждой услуги (как сейчас).

## 2. Закупки (PROPOSED)


## 3. Расход и остатки (PROPOSED, расчётные)

```
Расход_материала = Σ (норма_расхода_операции × параметры заказа)
Остаток = Σ закупок − Σ расходов     ← РАСЧЁТНЫЙ, не инвентаризация
```

Нормы расхода для каждой доп-операции/услуги — конфигурируемые: баннер = площадь×1.1 (запас на загибку — коэффициент задаёт владелец), люверсы = периметр/шаг (BR-06 уже считает количество → 1 шт расхода на люверс), краска RISO = 20 л на 1000 оттисков (equipment.json EXISTING: `ink_per_1000: 20`), тонер Xerox = 0.8 мл/лист (EXISTING), мастера = количество оригиналов×цветов (BR-01).

**Дашборд остатков** (пример §29, числа — расчётные):

| Материал | Закуплено | Израсходовано | Остаток (~) | Мин. запас | Статус |
|---|---|---|---|---|---|
| Баннер 440 г | 50 м² | 31.5 м² | **~18.5 м²** | 10 м² | OK |
| Мастер RISO | 20 шт | 17 шт | **~3 шт** | 5 | ⚠ ЗАКАЗАТЬ |

Маркировка: везде «~» и подпись «расчётный, по нормам расхода; сверять с фактом инвентаризации». Кнопка «Коррекция остатка» (фактический пересчёт) — обязательна.

## 4. Единицы и нормализация (§31)

Существующие единицы (факт): мм, см, м, м², пог.м, шт, лист, копия, заказ, час, оттиск/час, м²/час, лист/час, км, мл, л, кВт. Allowlist digital: `["лист","копия","заказ","шт","м","м²"]` (digital_calc.py:41).

```
Input Unit (мм/см/м — что удобно)
    ↓ normalize → расчётная единица (м для длины, м² для площади, шт для счётного)
    ↓ Display Unit (как в прайсе: пог.м, м², шт)
```

Единица материала — атрибут реестра; формула расхода обязан указывать единицу (урок BR-W3: люверсы «м» vs «шт»).

## 5. Планировщик закупок «Что нужно купить» (PROPOSED §30)

```
Потребность = max(0, min_stock − остаток) + Σ(расход по запланированным заказам) × (1 + запас %)
Рекомендуемая закупка = округление вверх до упаковки (атрибут материала: рулон 50 м² и т.п.)
```

Таблица: Материал | Остаток (~) | Потребность | Мин. запас | Рекомендуемая закупка | Поставщик. Прогноз расхода (V2) — по средней скорости списания за N дней; при малой истории показывать «данных недостаточно» вместо числа (§30: не выдавать прогноз как точный).

## 6. Себестоимость и маржа (§32)

**EXISTING база:** каждый расчёт уже даёт cost и sell отдельно (пары cost/sell в прайсах Wide/Tablichki/Sign; в Riso — себестоимость и цена отдельными полями). Целевое дерево:

```
Цена продажи (sell)
├── Материалы (реестр × нормы)      ← EXISTING (cost_unit)
├── Работа оператора (₽/час × часы) ← EXISTING (universal_calc)
├── Амортизация + накладные         ← EXISTING (BR-15)
└── Прочее (доставка и т.д.)
= Себестоимость
Валовая прибыль = sell − cost        ← EXISTING (lbl_profit во всех Tk-калькуляторах)
Маржинальность = прибыль / sell ×100 ← INFERRED (не отображается сейчас — добавить)
```

## 7. Связи

- Расчёт заказа → расход материалов (автосписание при переводе заказа в «Выполнен», с возможностью ручной правки).
- Доп-услуги → расходники (люверс, скотч, плёнка).
- Границы честности: без реальных инвентаризаций остатки остаются расчётными — это явное свойство, не баг.
