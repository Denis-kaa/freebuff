## Q1 — БЛОКИРУЕТ СТАРТ КОДА: среда исполнения и UI-стек главного экрана

Phase 1 целиком — это UI (главный экран Р5б, список заказов, «+»-форма, диалог). Ни стек, ни место запуска в v3 не зафиксированы, а строить оба параллельно нельзя.

Контекст для решения:
- Рабочее место Дениса — стойка, рядом WF-клиент под Windows (Р1).
- Прежнее целевое решение (TARGET_ARCHITECTURE.md, PROPOSED): FastAPI + web-SPA; платформа живёт на сервере whimco (`/opt/freebuff`, ADR-022 server-first).
- Старые калькуляторы — desktop EXE (Tkinter) — привычный Денису формат, но это legacy-стек.

Варианты: (а) web-приложение на whimco, Денис открывает браузер на стойке; (б) desktop-приложение под Windows; (в) web сейчас (UI и API на whimco), desktop-обёртка позже.
**РЕШЕНО (2026-09-07): вариант (а) — web-приложение на whimco, Денис открывает браузер на стойке; desktop-обёртку не строим, пока не попросят.**

## Q2 — нужно ДО финализации главного экрана (не блокирует каркас): список способов оплаты

Р5б прямо запрещает придумывать список самостоятельно. **РЕШЕНО (2026-09-07): наличные / карта / перевод** — значение храним строкой/enum, список редактируемый в настройках без кода.

## Q3 — нужно ДО первого показа Денису (не блокирует код): откуда берутся 4 статуса в списке заказов «на mañana»

Р2 фиксирует 4 статуса и список заказов, но не говорит, кто меняет статус: только Денис вручную в списке, или статус должен меняться и из карточки заказа на главном экране. Технически решается тривиально (одна и та же операция), вопрос влияет только на расстановку элементов UI. Версия по умолчанию (PROPOSED): смена статуса доступна в обоих местах.
