# CLIENT_HISTORY_MODEL.md — клиенты и история заказов

> Статус: COMPLETE (проект) · Дата: 2026-09-07 ·
> EXISTING: единственный прообраз — список менеджеров (M1 settings.json, 2 шт) и карточка сметы; клиентов в системе нет. Всё ниже PROPOSED, с правами «история ≠ истина» (§12).

## 1. Карточка клиента

```
Client: {id, name, kind: физлицо/компания, phone[], email, note,
         orders[], preferred_params (только отображение), files[],
         first_seen, last_order_at, orders_total, repeat_services[]}
```

Автосохранение при создании заказа (телефон — ключ поиска дублей). Никаких обязательных полей, кроме имени — барьер ввода минимален.

## 2. Повторный заказ

При новом заказе: поиск по телефону/имени → «Найден существующий клиент: …» → карточка истории:

- «Последний похожий заказ: визитки 500 шт, мел. глян. 300, матовая ламинация (12.05)»
- Кнопка «Повторить параметры» — заполняет схему расчёта СТАРЫМИ значениями как черновик.

## 3. Правила безопасности (§12-13)

1. **Старые параметры — только отображение/черновик.** Автоподстановка в расчёт — после явного «применить».
2. **Цены из истории не переносятся:** расчёт всегда по текущему прайсу (цена могла измениться — сообщение «цена с прошлого заказа: 3320 ₽, сейчас: 3480 ₽»).
3. Никаких автоматических изменений заказа без подтверждения сотрудника (§13).
4. Согласие на обработку контактов — флаг в карточке (простой, без CRM-переусложнений).

## 4. История как источник знаний

- Для сотрудника: «клиент ранее заказывал …» — контекст разговора (SALES_SCRIPT слой C).
- Для владельца: повторяемость услуг, средний чек (V2-аналитика; без прогнозов при малой выборке).
- Для производства: спец-настройки клиента (напр. «у этого заказчика всегда 510г») — в заметках, не в правилах по умолчанию.

## 5. Хранение и права

- SQLite (продакшн) / JSON (desktop). Роли: менеджер видит своих + общих; владелец — всех. Экспорт/удаление по запросу клиента (минимальная гигиена данных).
