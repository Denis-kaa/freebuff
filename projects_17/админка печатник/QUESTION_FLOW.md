# QUESTION_FLOW.md — динамический опросник заказа

> Статус: COMPLETE (проект) · Дата: 2026-09-07 ·
> Принцип §23: минимальное число вопросов, зависящих от предыдущих ответов. Всё, что можно вывести, — не спрашиваем.

## 1. Механизм (data-driven)

Вопросник — часть определения услуги (SERVICE DEFINITION), а не код:

```json
{
  "field": "grommets",
  "question": "Нужны ли люверсы?",
  "type": "bool", "default": false,
  "show_if": {"material": ["Баннер 440г", "Баннер 510г", "Плёнка самоклеящаяся"]},
  "glossary": "люверс",
  "optional": true
}
```

Типы полей: number, text, choice, bool, choice_mult, computed. Условия `show_if`/`enable_if` от других полей. Каждый вопрос может иметь `glossary` (ⓘ-справка) и `recommend_hint` (UPSELL_RULES.md).

**Существующая база:** input_schema уже реализована в движке printcalc (validate → compute, Phase 2) и в M1 `form_schema` (4 секции) — модель не придумана, она обобщает оба факта.

## 2. Скрипт «Баннер» (S-01) — эталонный поток

| # | Вопрос | Тип | Default | Авто/условие |
|---|--------|-----|---------|--------------|
| 1 | Что печатаем? | choice | Баннер | выбор услуги |
| 2 | Размер (Ш×В) | number×2 (см) | 200×100 | — |
| 3 | Количество | number | 1 | — |
| 4 | Где будет использоваться? | choice: помещение/улица/неизвестно | — | → влияет на печать и допы |
| 5 | Материал | choice | Баннер 440г | улица+большой размер → подсказка 510г (правило R-03) |
| 6 | Печать | choice | Экстерьерная, если #4=улица; Интерьерная — помещение | автодефолт из #4 |
| 7 | Люверсы? | bool | true для улицы | show_if материал = баннер/плёнка |
| 8 | Шаг люверсов, см | number | 50 | show_if #7=true |
| 9 | Загибка / карман | bool×2 | false | show_if материал = баннер |
| 10 | Накатка на основу / монтаж на сетку | bool×2 | false | по желанию |
| 11 | Нужен монтаж? | choice: нет / без подъёма / автовышка | нет | → уточнить высоту (до2/2-3/3+) |
| 12 | Высота монтажа | choice | до 2 м | show_if #11 ≠ нет |
| 13 | Доставка? | bool | false | → адрес (для км-тарифа, если включён) |
| 14 | Макет есть? | bool | — | если нет → дизайн (M1: до3/до9/от9 м²) |
| 15 | Дизайн баннера (уровень) | choice | Стандарт | show_if #14=false |
| 16 | Срок / срочность | **PROPOSED** | обычный | в исходниках срочности нет |

**Автовывод (не спрашиваем):** площадь = Ш×В×кол-во (BR-04 диапазон цены применится сам); количество люверсов = 2×(Ш+В)×2 / шаг (BR-06); базовая цена материала и печати — из прайса по площади. Итог вопросов: 16, из них обязательных — 3 (размер, количество, назначение).

## 4. Скрипт «Табличка» (S-02)

1. Размер (default 20×10 см) → 2. Материал (ПВХ 3мм default) → 3. Печать (УФ; УФ+лак для улицы — правило R-03) → 4. Двусторонняя? (×2 материал) → 5. Крепёж (скотч/пена/винты/дюбели) → 6. Обработка (скругление/фрезеровка/скотч по периметру/люверсы) → 7. Сложность (Средний; сейчас не влияет, BR-16) → 8. Доставка/монтаж.

## 5. Скрипт «Буквы/вывеска» (S-03)

1. Тип (5 моделей) → 2. Высота, см (ширина авто ×0.7; короб — в м²) → 3. Количество букв → 4. Материал лицевой/боковой/задней (авто PART_DEFAULTS по типу) → 5. Свет? (авто из модели) → 6. Электрика/БП (если свет) → 7. Каркас → 8. Нанесение (УФ/аппликация) → 9. Монтаж → высота (%) → 10. Доставка → км.

## 6. Скрипт «Тиражная печать» (S-04 Riso / S-05 Digital)

Riso (схема уже в printcalc): тираж (≥500, автоподнятие), формат, цветность, оригиналов, duplex, бумага, допы (резка/ламинация/фальцовка/скоба/доставка), наценка.
Digital: изделие (9 шаблонов), размер, тираж, страницы, цветность, duplex, бумага, постоперации (6).

## 7. Правила потока (INFERRED из принципа §23 + код)

1. Обязательный минимум = поля без default в schema (у Riso: qty, originals — факт из printcalc spec).
2. Вопрос задаётся только если поле влияет на цену (все допы optional с default=false).
3. Условия «улица → материалы/защита» — правила рекомендаций (UPSELL_RULES.md), а не жёсткие ветки.
4. Изменённый ответ пересчитывает всё каскадно (расчёт < 50 мс, pure-функция).
5. Любое поле → ⓘ (CONTEXTUAL_HELP.md).
6. Скрипт генерируется из того же дерева (SALES_SCRIPT.md) — единый источник, двойной рендер: форма для сотрудника + текст для клиента.
