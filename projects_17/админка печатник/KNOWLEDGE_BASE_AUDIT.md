## 2. Что полезно из WorkflowForms (как концептуальная основа)

- **FormObjects/Controls** — формы описываются данными (XML) → подтверждает data-driven QUESTION_FLOW.
- **Commands/Conditions** — правила как данные → подтверждает UPSELL_RULES/BUSINESS_RULES модель.
- **DataConnections** — связь с внешними данными через конфигурацию.
- **i18n-ключи локалей** — паттерн для терминов глоссария.
Ограничение: 0 исходников (W-01) — берутся ПАТТЕРНЫ, не код.

## 3. Разделение EXISTING / INFERRED / PROPOSED

- **EXISTING:** прайсы и материалы как знания о продукции; менеджеры (M1, 2 шт); оборудование с параметрами (M8); терминология в лейблах (см. TERMS_GLOSSARY §2).
- **INFERRED:** последовательность изготовления следует из набора доп-услуг (люверсы → операция «пробить люверсы»); уровни сложности M1 намекают на категорию «процесс».
- **PROPOSED (всё остальное):** операции, инструкции, чек-листы, справка, AI-помощник, карточка заказа, история клиентов, остатки, закупки.

## 4. Вывод

Слой знаний **строится с нуля** — в исходниках нет ни одного элемента. Но весь исходный контент знаний уже существует в виде данных прайсов (цены/материалы/единицы) — база знаний будет структурировать те же сущности, добавляя слой «как это делается» поверх «сколько это стоит». Начинка стартовых операций/чек-листов — PROPOSED и требует валидации практикой производства (Денис/сотрудники) до фиксации как канон.
