# CONTEXTUAL_HELP.md — контекстная справка

> Статус: COMPLETE (проект) · Дата: 2026-09-07 · В коде справки нет (grep — 0, только messagebox ошибок ввода). Система — PROPOSED; словари терминов — TERMS_GLOSSARY (существующие токены EXISTING).

## 1. Два уровня справки (§1 промта)

**A. Для общения с клиентом** — «что это и зачем клиенту»:
- что такое баннер/люверс/ламинация; чем 440г отличается от 510г;
- какие вопросы задать; что предложить дополнительно (UPSELL_RULES).

**B. Для выполнения заказа** — «как это сделать»: карточки операций (OPERATIONS_CATALOG), чек-листы, ПО, дерево решений (TASK_EXECUTION_MODEL).

## 2. Модель привязки

```json
{"anchor": "field:grommets",        // поле схемы, кнопка, колонка прайса, операция
 "kind": "term|operation|rule|error",
 "ref": "люверс",                    // id в глоссарии/каталоге
 "short": "Металлическое кольцо для крепления (20 ₽/шт)",
 "details": true}                    // клик → полная карточка
```

Анкеры (точки входа): поле ввода ⓘ, название услуги, строка сметы, доп-услуга в рекомендации, операция в заказе, пункт чек-листа, термин в скрипте.

## 3. Правила показа

1. Краткая справка — на месте (tooltip/строка 1-2); полная — по клику (панель/модал, не уводя с экрана расчёта).
2. Справка не блокирует ввод и не исчезает при печати сотрудником.
3. Для новичка — режим «показывать подсказки» по умолчанию (переключатель в профиле).
4. Содержимое редактируется владельцем (раздел «Термины» + карточки операций) — без правки кода.
5. Правило содержимого: каждый термин имеет source — если текст предложен AI/агентом и не подтверждён производством, метка «черновик» видна сотруднику (KNOWLEDGE_ARCHITECTURE §4).

## 4. Ошибки ввода тоже справка

Сообщение об ошибке расчёта (например, «Нет цены для формата») даёт ссылку «что делать»: открыть нужный прайс в настройках (если роль позволяет) или объяснить клиенту ограничение (SALES_SCRIPT). Прямое использование существующих текстов ошибок движка — EXISTING (тексты из riso перенесены в printcalc дословно).
