# ORDER_WORKFLOW.md — карточка заказа и производственный workflow

> Статус: COMPLETE (проект) · Дата: 2026-09-07 ·
> Сметы в legacy живут только в памяти окна + CSV (RUN-факты) — сущность «заказ» PROPOSED целиком. WF-паттерн (HelpDesk-тикет, статусы) — концептуальная опора.

## 1. Карточка заказа (§11)

```
Order:
├── id, created_at, status
├── client_id (CLIENT_HISTORY_MODEL) · manager (EXISTING: список managers в M1)
├── service_id + params (расчёт: input схемы)
├── calculation: breakdown[], cost, sell, margin, warnings
├── materials[]: material_id, qty(расч.), расход спланирован/списан
├── operations[]: op_id, status, done_criteria[] (OPERATIONS_CATALOG)
├── files[]: макет, смета PDF/CSV
├── deadline, priority (срочность — PROPOSED)
├── responsible (роль/сотрудник)
├── comments[] / history[] (кто что менял)
└── delivery/montage: адрес, высота, дата
```

Источники полей: расчёт — движок printcalc (результат уже содержит price/cost/breakdown); operations — генерация из параметров; materials — нормы расхода.

## 2. Статусы (§11)

```
Новый → Принят → Подготовка (макет/файл) → Производство (печать/резка/сборка)
     → Контроль качества → Готов → Выдан (закрытие = списание материалов)
```

Переходы требуют завершения операций текущего этапа (done_criteria). Расхождение статусов с операциями блокируется (не «Готов» при незакрытых OP). Автосписание материалов при «Выдан» — с ручной коррекцией (MATERIAL_MODEL §7).

## 3. Динамический производственный workflow (§9 промта)

```
Баннер 3×1, улица, люверсы, без ламинации, монтаж 2.5 м
→ OP-01 проверка макета → OP-02 подготовка файла → OP-04 печать (Roland)
→ OP-09 подрезка → OP-13 люверсы → OP-20 КК → OP-19 монтаж
(без ламинации OP-08 НЕ включена; при добавлении монтажа появился OP-19)
```

Генерация: `service → operations map` + `param → condition` — данные, редактируемые владельцем.

## 4. Связи с другими блоками

- Расчёт → заказ: кнопка «Оформить заказ» из результата калькулятора (цены уже посчитаны, повторного ввода нет).
- Заказ → материалы: расход спланирован при создании; списание при выдаче.
- Заказ → клиент: автосохранение клиента, «повторить заказ».
- Заказ → скрипт: карточка содержит сгенерированный скрипт разговора для менеджера (SALES_SCRIPT).

## 5. Модель системы целиком (§14)

```
CLIENT → ORDER → SERVICE → QUESTIONS → CALCULATION → RECOMMENDATIONS
      → OPERATIONS → WORKFLOW → PRODUCTION → QC → COMPLETED → CLIENT HISTORY
KNOWLEDGE_BASE → (клиенту/сотруднику/производству) ; AI_ASSISTANT → анализ/рекомендации/решение проблем
```

Каждая стрелка — уже спроектированный артефакт этого набора документов.
