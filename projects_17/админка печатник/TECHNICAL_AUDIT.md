# TECHNICAL_AUDIT.md — технический аудит «Калькуляторы»

> Статус: COMPLETE · Дата: 2026-09-07 · Все доказательства — file:line в распакованной копии на whimco.

## 1. Архитектура (as-is)

- **8 независимых desktop-приложений** без общего ядра: 6 Tkinter-окон, 2 pywebview-окна, 1 генерируемая обёртка.
- Двухслойная эволюция: `Коды на калькуляторы/` — исходные standalone-версии (Tk-классы, конфигов нет у Riso/Tablichki/Sign/Wide); `Общий калькулятор печати/` — их **модифицированные копии** (добавлены JSON-конфиги, конверсия Tk→Frame регэкспом в `build_exe.py:35-58`).
- Общего слоя данных/валидации/UI нет; повторно используется только палитра цветов (BG/PANEL/ACCENT… копируется в каждом файле).

## 2. Backend / бизнес-логика

- Логика расчётов — внутри GUI-классов (`calculate()` каждого приложения); нет отделения расчёта от UI → нет тестируемости.
- Формулы проверяемы по коду: Riso `Коды…/Riso/riso_calc.py:520-645` (бумага+краска+мастера+работа, цена = (прайс×тираж + (мастера+допы)×(1+наценка))/(1−0.06)); Sign `Буквы/sign_calc.py:638-790` (двухрежимный: прайс ₽/см или cost+markup); Wide `Shirokoformat/wide_format.py:570-670`; Tablichki `Tablichki/tablichki.py:548-665`; Digital `Общий…/digital_calc.py:349-457`; Universal `себестоимости/universal_calc.py:449-590` (амортизация/накладные на машино-час).
- Налог 6% захардкожен в трёх файлах (`TAX_RATE = 0.06`), MIN_ORDER — в двух.

## 3. Frontend

- Tkinter/ttk с вкладками Notebook; 2 webview-приложения с inline HTML/JS (design_calc: HTML ≈ строк 242–325; cnc: 164–588).
- Общий визуальный стиль (палитра) скопирован в 6 файлов; два webview-приложения используют другой стиль — визуально система неоднородна.

## 4. API

- Сетевого API нет. JS-bridge `pywebview.api` — единственный «API-слой» (design_calc.py:194-235; cnc_calc.py:84-160).

## 5. Database

- Нет БД. Персистентность = JSON-файлы рядом с exe (`settings.json`, `cnc_settings.json`, `equipment.json`, `*_config.json` в dist). Сметы — только в памяти окна + CSV-экспорт.

## 6. Calculator engine

- Отсутствует как понятие: у каждого калькулятора своя структура входов/выходов, свой прайс и своя валидация. Контракта «Calculator → Input Schema → … → Result» нет.

## 7. Dependencies

- `requirements.txt`/`pyproject.toml` **отсутствуют** (find — 0 файлов). Зависимости восстанавливаются только чтением импортов.

## 8. Security

- Секретов/сети нет (grep паттернов — 0 релевантных). Риски: открытие файлов внешними программами (`design_calc.py:188` `xdg-open`; `universal_calc.py:370` `notepad`), `subprocess` в build_exe (только сборка).

## 9. Error handling

- 151 голый `except:` и 74 `pass` в 19 файлах (grep-счёт). Валидация — точечная (float()/ValueError с messagebox), нет единой схемы ошибок.

## 10. Performance

- Проблем нет: расчёты O(1)/O(n) по прайсам, объёмы малы. Не является риском.

## 11. Testing

- Тестов нет (find `*test*` — 0). Регрессия при правке цен/формул не контролируется.

## 12. Code duplication (проверено diff)

- 4 калькулятора существуют в двух редакциях: standalone (Коды…) и wrapper-копия (Общий…/build_all). Diff подтверждает расхождения: у wrapper-копий добавлены JSON-конфиги, у Tablichki изменён люверс с «м» на «шт» и добавлен print()-дебаг (`Общий…/tablichki.py:2`), у Wide — минимальная сумма заказа стала настройкой.
- `digital_calc.py` дублируется в `Общий…/digital_calc.py` (51 674 B) и `build_all/calc_digital.py` (51 672 B).

## 13. Technical debt

- Мёртвые артефакты в архиве: `build/` (84 файла), `dist/` (12 файлов EXE), `__pycache__`, пустой файл `python`, файл `Общий…/python` (0 байт).
- Windows-only хардкод: `C:/Users/777/...` в spec, `notepad`, `os.startfile`.
- print()-дебаг в прод-файле (tablichki.py:2 в двух копиях).

## 14. Scalability

- Добавление нового калькулятора = копирование 700–1300 строк и ручная интеграция в обёртку + правка build_exe.py (FILES, BUTTON_LABELS). Масштабирование деградирует линейно.
