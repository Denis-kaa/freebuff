## 2. Тесты (15 новых)

**Тест 7 `test_reports_hub_server.py` (8):** нет токена в env → 401 на всё (гейт до маршрутизации); токен в env без `?token` → 401; неверный токен → 401, верный → 200 (index + вложенная страница); cookie после первого входа работает без `?token`; `/download/zip` → 200, `application/zip`, в архиве index + projects/demo; path traversal (`../` и `%2e%2e`) → не 200; неизвестный файл → 404. Плюс unit `make_zip` (состав архива).

**Платформа `test_reports_hub_platform.py` (7):** синтетический корень (TASK/CHANGELOG/реестр/docs_10) → 4 секции, только открытые чекбоксы (2 из 3), релизы в порядке свежести, реестр 2 implemented из 3, плитки метрик; отсутствующие источники → «источник отсутствует» + диагностика, метрики остаются (§11); рендер: прогресс-бар с «2/3», без реестра — без бара; `--platform` через `generate_site` пишет `platform/index.html`, без флага — не пишет.

## 3. Решения по ходу (и почему)

1. **Cookie HttpOnly после первого успешного входа** — спека §10.2 («cookie после первого входа»); повторные переходы по страницам не требуют видимого токена в URL.
2. **Zip в памяти** — сайт маленький (генерация 1.3с, ~260 файлов), файловый кэш не нужен; сервер «ничего не считает на лету (кроме zip)» — ровно как в спеке.
3. **`_log_hint_once` + стартовая подсказка** — «нет токена в env → 401 + подсказка в лог (не молча, не падает)»: печатается один раз при первом 401 и один раз при старте, чтобы не заспамить лог под нагрузкой.
4. **Платформа вне `projects`-модели** — `SiteModel.platform` отдельно от списка проектов: платформа не из projects_17, у неё другая структура источников; главная-галерея не ломается.
5. **Реестр для прогресс-бара передаётся отдельным аргументом** — `RegistrySummary` не сериализуется в ReportModel (модель — контракты §7.1, а не всё подряд).
