## 2. Закрытый словарь единиц (ANTI-6b)

`store.UNIT_CATALOG` — 13 канонов: `шт, компл, пачка, упак, рулон, лист, копия,
м², пог.м, час, пакет, услуга, заказ` (источники: живой каталог, MATERIAL_UNITS,
orders.js, практика прайсов района). `UNIT_ALIASES` — нормализация ввода
(«штука»→шт, «м2»/«m2»/«кв.м»→м², «п.м.»→пог.м, «комплект»→компл…).
`normalize_unit()`: None/пусто → None (legacy = «шт»); неизвестное → **StoreError
с перечнем допустимых** (тихий фолбэк запрещён). Валидация включена в
`add_price_item`, `update_price_item`; CSV-импорт проходит через них автоматически.

## 3. Единица в заказе (аддитивно)

- **db.py:** миграция `order_items ADD COLUMN unit TEXT` (guard, как segment_id);
- **store.py `_resolve_item`:** price_list → `unit оператора или из каталога`;
  manual → unit оператора (и в каталог при save_to_catalog); INSERT пишет unit;
  чтение заказа отдаёт unit; сметы показывают unit из каталога по ссылке;
- **api.py:** `OrderItemIn.unit`, `EstimateItemIn.unit` (опциональны — обратная совместимость);
- **UI:** цена в черновике «300 / м²», селектор новой позиции — все 13 единиц,
  подсказка на qty для м² («2.5 = 2,5 м²»), карточка заказа показывает единицу.

## 4. Парсер: размер ≠ тираж

- `_SIZE_WORDS` {на, х, x, ×} вынуты из потока: `_dimension_indices()` находит
  trio «N на M», числа не съедаются тиражом, коннекторы не в unknown;
- `_QTY_WORDS` (шт/штук/лист/копия/упак/…): «наклейка 100 шт» → qty=20…100 осознанно;
  «баннер 440г, 2 штуки» больше не поднимает needs_operator (был ложный unknown);
- **result["sizes"]** (аддитивно): распознанные размеры «20 на 30», «20×30» —
  видны оператору; размер без услуги → reason «указан размер без услуги» (не молча);
- unit позиции едет из словаря в parsed item → addItem → заказ.
