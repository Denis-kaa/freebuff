# AI_ASSISTANT_CONCEPT.md — AI-слой системы

> Статус: COMPLETE (проект) · Дата: 2026-09-07 · В исходниках AI нет (сети нет вовсе). Концепция PROPOSED. Главный принцип: **AI — инструмент среди инструментов, а не «магия»**; AI не может быть источником непроверенных фактов.

## 1. Три зоны применения (§14)

| Зона | Что делает AI | Чего НЕ делает |
|---|---|---|
| Анализ | Разбор описания потребности клиента вольным текстом → предложение услуги и черновика ответов схемы («хочу баннер на фасад 3×1» → S-01 + черновик схемы) | Не фиксирует ответы молча — сотрудник подтверждает |
| Рекомендации | Ранжирование сработавших upsell-правил, формулировка «почему» человеческим языком | Не создаёт новые правила/цены сам — только предлагает черновик правила владельцу |
| Решение проблем | Мастер устранения проблемы («фото не подходит» → дерево решений, шаги, ПО) с опорой на OPERATIONS/SOFTWARE_CATALOG | Не выполняет операцию сам и не гарантирует результат |

## 2. Встраивание

```
QUESTION_FLOW ← AI-черновик схемы (подтверждение обязательно)
UPSELL_RULES ← AI-ранжирование (порядок показа)
TASK_EXECUTION ← AI-совет «каким способом» (из настроенного дерева)
KNOWLEDGE_BASE ← AI-поиск по терминам/операциям (RAG по локальной базе)
```

AI работает поверх существующих данных (прайсы, правила, операции) — не вместо них. Цены/остатки/итог расчёта **никогда** не генерируются AI: только движок.

## 3. Проверка результата AI-действий (§5 промта)

После любого AI-шага — обязательный чек: соответствие исходнику, отсутствие дорисованных деталей, артефактов; для документов — особый режим (AI_SAFETY_RULES §3). UI показывает «сделано AI — проверь по чек-листу» на каждом артефакте AI-происхождения.

## 4. Ограничения и конфигурация

- Offline-first: базовый функционал (расчёт, заказы, материалы) не зависит от AI/сети; AI — опциональный слой (кнопка «спросить помощника»).
- Провайдер настраивается (админка); при недоступности — система работает без него (деgradable).
- Журнал AI-действий (что предлагал, что сотрудник принял) — для аудита.
