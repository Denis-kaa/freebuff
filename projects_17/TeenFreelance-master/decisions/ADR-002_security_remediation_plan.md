# ADR-002: Принятие аудита и план security-ремедиации

- **Дата:** 2026-09-05
- **Статус:** 🟡 Accepted (исполнение pending — отдельные заходы по CON-68 п.4)
- **Контекст задачи:** STEPS.md, Сессия 2; `docs_10/audits/AUDIT_TEENFREELANCE_2026-09-04.md` (36 находок, §11 owner-check sweep, §12 WS/messages deep-dive)
- **Ревизия 2026-09-05:** реестр расширен до REC-001..023 (REC-012 P2→P1 — grooming-вектор; +REC-022 antiflood, +REC-023 WS manager redesign); ADR-002 ссылается на актуальное состояние реестра, состав волн ниже — снапшот от даты ADR

## Context

Проект — фриланс-платформа для **несовершеннолетних** с денежными балансами (RUB + tf_coins). Полный аудит обнаружил 36 подтверждённых находок: 4 critical, 9 high. При этом боевой инстанс на whimco уже принимает реальный трафик. Канон платформы (CON-68 п.4) запрещает править код объекта в заходе аудита — фиксы идут отдельными заходами с verify.

## Options

| # | Вариант | Почему нет/да |
|---|---|---|
| 1 | Игнорировать аудит до «следующего релиза» | Неприемлемо: критичные находки эксплуатируются прямо сейчас на живом инстансе (подделка токенов, чтение ставок подростков) |
| 2 | Чинить всё разом одним мега-заходом | Нарушает ANTI-5 (scope discipline): 21 REC в одном заходе непроверяемы |
| 3 | **Волны ремедиации по приоритетам P0→P1→P2, каждая волна = отдельный заход, закрывает свои REC-ID с verify-ссылкой** | Соответствует ANTI-5 и CON-68; каждый заход проверяем и откатываем |

## Decision

Вариант 3. Волны (детали и диффы — в строках REC `docs_10/RECOMMENDATIONS.md`):

- **Волна 1 (P0, ×7 — REC-001/002/003/004/006/018/019):**
  1. `SECRET_KEY` обязательный (`Field(...)` + валидатор против placeholder), per-env ключ `openssl rand -hex 32`; ops-фикс на whimco `.env` + рестарт (REC-001/018);
  2. TLS на whimco + security-заголовки nginx (REC-002);
  3. auth + ownership на чтение offers; draft-фильтр на листинг заказов (REC-003/019);
  4. ownership на `delete_file` + убрать `file_path` из ответа upload (REC-004);
  5. убрать `ports: 5433:5432` из docker-compose (REC-006).
- **Волна 2 (P1, ×14 с ревизией 2026-09-05):** token_version+logout+короткий JWT (REC-007), rate-limit login/register (REC-008), payment-flow integrity (REC-009), PII-lifecycle несовершеннолетних (REC-010), first-name+initial вместо полных имён (REC-011), **модерация + контент-фильтры (REC-012, повышена с P2)**, WS-логи/is_active/ws-ticket (REC-013), create_message-валидация (REC-014), мелкие auth-фиксы пачкой (REC-015), compose-гигиена (REC-016), стриминг файлов (REC-005), auth на `GET /portfolio/{item_id}` (REC-021), **rate-limit сообщений WS/REST (REC-022)**, mark_as_read IDOR (REC-020).
- **Волна 3 (P2, ×2):** magic-bytes + signed URLs (REC-017), ConnectionManager redesign (REC-023).

## Rationale

- **Additive/low-risk:** волна 1 — маленькие хирургические диффы (сводятся к нескольким строкам + конфиг), не переписывают модули.
- **Несовершеннолетние = усиленные требования:** PII и приватность транзакций подростков оправдывают P0-карантин до дальнейшей эксплуатации.
- Каждая волна закрывает конкретные REC-ID в реестре со статусом DONE + verify — соответствие CON-68 п.2 и RECOMMENDATIONS-жизненному циклу OPEN → IN_PROGRESS → DONE.

## Consequences

- ✅ После волны 1 на whimco: невозможна подделка токенов, закрыто неаутентифицированное чтение ставок/драфтов/файлов.
- ⚠️ Смена SECRET_KEY инвалидует все текущие JWT — пользователи перелогинятся (сейчас это только тестовый юзер).
- ⚠️ TLS (REC-002) требует домен — на голом IP Let's Encrypt недоступен; до получения домена HTTPS остаётся открытым пунктом.
- 📋 Прогон `fix_enum_cases.py` после миграций на новых инстансах — постоянный шаг RUNNABLE.md.
