### Часть 1. Чего не хватает? (Gap Analysis)

Сейчас у нас есть UI, но нет «мозгов» экосистемы. Вот 5 критических вещей, которые нужно добавить в логику:

1.  **Движок «Сборки Команды» (Team Assembly Engine)**
    *   *Проблема:* Сейчас ментор просто «видит» подростков.
    *   *Решение:* Нужен алгоритм совместимости. Ментор создает слоты: «Мне нужен 1 Дизайнер (Figma > 70) и 1 Копирайтер». Система подсвечивает кандидатов, у которых эти навыки есть, и показывает их «Chemistry Score» (насколько они подходят друг другу по графику и стилю работы).

2.  **Асинхронный Workflow Ревью (The Review Loop)**
    *   *Проблема:* Сейчас кнопка «Отправить» сразу меняет статус. В реальности это чат с вложениями, версионность файлов (v1, v2, final) и комментарии к конкретным областям макета.
    *   *Решение:* Интерфейс должен позволять ментору кликнуть на часть изображения и оставить комментарий («Поправь кернинг здесь»). Подросток видит пин, исправляет и загружает v2. История изменений сохраняется как доказательство обучения.

3.  **Динамический Skill Graph (Не просто список)**
    *   *Проблема:* Список навыков статичен.
    *   *Решение:* Навыки должны быть связаны. Если ты качаешь «UX Research», это автоматически дает буст к «Empathy» и немного к «Copywriting». Визуально это должно выглядеть как нейронная сеть, где узлы пульсируют при получении нового опыта.

4.  **Talent Pool Analytics (Для B2B)**
    *   *Проблема:* Нет вида для компаний.
    *   *Решение:* Отдельный дашборд, где компания видит не людей, а *тренды*. «В этом месяце 15 подростков в вашем регионе освоили Blender на уровень Junior». Это продает подписку на доступ к базе талантов.

5.  **Юридический слой (Parental Consent Flow)**
    *   *Проблема:* Родитель просто «смотрит».
    *   *Решение:* Перед началом коммерческого проекта родитель должен получить push-уведомление: «Максим хочет взять проект за 5000р. Условия такие-то. Подтвердить?». Без криптографической подписи (или простого токена) контракт не активируется.

### Часть 2. Рефакторинг в React (Архитектура Продукта)

Чтобы это стало продуктом, мы уходим от «страниц» к «компонентам состояния».

#### Стек для продакшена:
*   **Core:** React 18 + TypeScript (строгая типизация данных обязательна).
*   **State:** Zustand (легче Redux, идеален для такого типа данных) или TanStack Query (для серверного состояния).
*   **UI:** Radix UI (доступные примитивы) + Tailwind CSS (для скорости).
*   **Animation:** Framer Motion (для сложных переходов между состояниями задач).

#### Структура папок (Feature-Sliced Design):
```text
src/
  features/
    team-building/     # Логика драфта и сбора команды
    skill-tree/        # Визуализация графа навыков
    review-system/     # Чат, версии файлов, комментарии
  entities/
    user/              # Профиль, роль (teen/mentor/parent)
    project/           # Сущность проекта, бриф, бюджет
    task/              # Конкретное задание внутри проекта
  widgets/
    dashboard/         # Сборка виджетов
    parent-control/    # Виджет контроля
  app/                 # Роутинг, провайдеры
```

              animate={{ width: `${level}%` }}
              transition={{ duration: 1, ease: "easeOut" }}
            />
          </div>
          <span className="font-mono font-bold">{level}</span>
        </div>
      </div>

      <AnimatePresence>
        {isOpen && (
          <motion.div
            initial={{ height: 0, opacity: 0 }}
            animate={{ height: 'auto', opacity: 1 }}
            exit={{ height: 0, opacity: 0 }}
            className="overflow-hidden"
          >
            <div className="pt-4 pl-4 space-y-2">
              <p className="text-xs uppercase tracking-wider text-gray-400 mb-2">История развития:</p>
              {proofs.map((proof) => (
                <div key={proof.id} className="flex items-start gap-3 text-sm">
                  <span className={`w-2 h-2 mt-1.5 rounded-full ${
                    proof.type === 'project' ? 'bg-green-500' : 'bg-blue-500'

                    <span className="font-medium text-gray-800">{proof.title}</span>

                </div>
              ))}
            </div>
          </motion.div>
        )}
      </AnimatePresence>
    </div>
  );
};

9. Почему ментору это выгодно

Это один из главных вопросов бизнес-модели.

Почему опытному специалисту вообще становиться наставником?

Потому что платформа даёт ему возможность масштабировать собственную экспертизу.

Обычный фрилансер:

«сам получил заказ → сам сделал → получил деньги.»

Ментор:

«получил проект → собрал команду → распределил работу → обучил участников → проконтролировал результат → получил вознаграждение.»

То есть он начинает зарабатывать не только собственными руками, но и своей экспертизой и умением организовать команду.

10. Платформа не должна брать деньги с ментора за право быть ментором

Это выглядит неправильно.

Ментор приносит платформе ценность.

Поэтому базовая модель может быть обратной:

«платформа получает заказ → из экономики заказа платформа вознаграждает ментора за его роль.»

То есть ментор не платит:

««Хочешь быть наставником? Заплати нам».»

Вместо этого:

««Ты помогаешь платформе создавать качественные команды и результаты — платформа делится с тобой доходом от проектов».»

Конкретный процент — отдельный вопрос, который нужно рассчитывать позже.

11. Экономика платформы

Базовый источник дохода:

Комиссия с заказов

Клиент платит за результат через платформу.

Из суммы:

часть → подросткам

часть → ментору

часть → платформа

Например, условно:

«Заказ 20 000 ₽»

Неважно, какие именно проценты мы в итоге выберем.

Важно, что:

клиент платит за результат, а не за обучение.

12. Но комиссия — не единственный источник денег

Со временем появляются дополнительные модели.

Компании

Компании могут быть заинтересованы не только в выполнении заказов.

Им нужны будущие специалисты.

Например:

««Через два года нам понадобятся дизайнеры».»

Платформа уже видит:

- кто развивается в дизайне;
- кто быстро растёт;
- кто умеет работать в команде;
- кто хорошо выполняет проекты;
- кто интересуется конкретной отраслью.

Получается Talent Pool.

Компания может наблюдать за развитием талантов и в будущем предложить:

- стажировку;
- практику;
- работу;
- обучение;
- собственную программу.

Таким образом компания получает доступ не к «школьникам», а к будущим специалистам с подтверждённой историей развития.

13. Самая сильная особенность — время

Обычный рынок смотрит:

««Что ты умеешь сейчас?»»

Наша система может смотреть:

««Как ты развивался последние четыре года и куда ты движешься?»»

Например:

14 лет

Начал изучать дизайн.

15 лет

10 практических работ.

16 лет

Первый коммерческий проект.

17 лет

Работает в командах, имеет Mentor Score и портфолио.

18 лет

Уже не новичок.

Компания видит не просто резюме.

Она видит траекторию человека.

15. Почему подросток остаётся на платформе

Самая важная задача — не просто зарегистрировать пользователя.

Нужно, чтобы ему было интересно возвращаться.

Потому что каждый следующий этап открывает новые возможности.

Сегодня:

««Хочу попробовать дизайн».»

Через месяц:

««Хочу получить первый бейдж».»

Через полгода:

««Хочу попасть в команду этого ментора».»

Через год:

««Хочу получить более сложный проект».»

Через два года:

««Хочу попасть в Talent Pool компании».»

В 18:

««У меня уже есть портфолио, опыт и люди, которые знают, как я работаю».»

Это создаёт долгосрочную ценность.

16. Почему это может быть большим бизнесом

Потому что мы начинаем работать с человеком до того, как он выходит на полноценный рынок труда.

Если человек пришёл в 14 лет и остался до 18:

платформа постепенно знает:

- его интересы;
- навыки;
- проекты;
- сильные стороны;
- слабые стороны;
- наставников;
- команды;
- профессиональный рост;
- интересующие отрасли.

Получается очень глубокий профессиональный граф.

И на выходе человек уже становится интересен взрослому рынку.

17. Главная идея

Мы не хотим построить:

«Авито для школьников».

И не хотим построить:

«Курсы для школьников + фриланс».

Мы хотим построить:

Платформу первой профессиональной траектории.

Место, где подросток может начать с нуля и постепенно пройти путь до настоящего специалиста.

14 лет — попробовать.

15 — научиться.

16 — работать.

17 — специализироваться.

18 — выйти на взрослый профессиональный рынок уже с опытом.

И если мы действительно сможем связать в одну систему:

обучение + наставничество + реальные проекты + команды + портфолио + репутацию + Talent Pool,

то главным активом платформы станет не база заказов.

Главным активом станет история развития каждого человека.

Именно это и будет нашей основной защитой от копирования.

Не отдельная функция.

А накопленная за годы профессиональная история миллионов маленьких решений, проектов, навыков, команд и результатов.
