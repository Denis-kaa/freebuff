# ADR-002 — Фазовые гейты B+C → N, запрет перескоков

> **Статус:** 🟢 Accepted (2026-08-23)
> **Источник:** prompt1.md (scope §3, запреты §35, gate §40), prompt2.md (серия промтов-гейтов D–N)

## Context

Платформа обучения состоит из многих связанных компонентов (corpus → grader → sandbox → анализаторы → hints → evidence → FSRS → selector → projects → API → UI). При смешанной реализации «всё сразу»: непроверяемые модули накапливаются, ревью-петля раздувается (платформенный анти-паттерн ANTI-5), а ошибка контракта между слоями обнаруживается поздно.

## Options

1. Один монолитный промт на всю систему (как prompt3 master) — быстро, но невалидируемые промежуточные состояния.
2. **Серия фаз-гейтов**: каждая фаза по своему DoD + acceptance + тестам, финальный статус `* COMPLETE · WAITING FOR REVIEW`, переход — только после ревью.
3. Случайный порядок по «что хочется» — блокировки зависимостей.

## Decision

Принят вариант 2: **рокировка исключена — фазы исполняются строго по цепочке B+C → D → E → F → G → H → I → J → K → L → M → N, каждая с выходным gate G-<ID> и отчётом A–I (prompt1 §39); «реализовать компонент будущей фазы на лету» запрещено — только фиксация зависимости в отчёте.**

## Rationale

- Контракты каждой фазы тестируются изолированно (hermetic tests), прежде чем следующий слой опирается на них.
- Ранний quality-gate именно на контенте/компетенциях (B+C) — дешёвое обнаружение ошибок в фундаменте.
- Совместимость с платформенным ANTI-5 (scope discipline) и метрикой «зелённые тесты на каждом шаге».

## Consequences

- Каждая фаза: свой `doD`/acceptance-чек-лист; прогресс фиксируется в ROADMAP/STEPS/CHANGELOG.
- При необходимости «прыжка» — сначала ADR с обоснованием, а не молча.
- Ожидаемая длительность ядра ~24–42 сессии (ROADMAP §6).
