# ADR-001 — Детерминированное ядро первично; LLM — только внешний опциональный слой

> **Статус:** 🟢 Accepted (2026-08-23)
> **Источник:** prompt3.md §0/§2, blueprint v0.1 §7, prompt2.md (схема Deterministic Core + LLM Layer)

## Context

Исходная идея — «AI-тьютор» с ролями на LLM (методика v1.0). Параллельно сформировано требование автономного детерминированного ядра (prompt.md: «ядро должно работать полностью автономно»), которое заменяет роли правилами: Куратор → rules-engine, Ревьюер → автогрейдер+статика, Ментор → AST-паттерн + банк подсказок, Заказчик → дерево вопросов по готовым ТЗ.

## Options

1. **LLM-система с детерминированной обвязкой** — LLM остаётся «мозгом», ядро лишь вспомогательное.
2. **Детерминированное ядро первично, LLM — внешний слой** — все образовательные состояния и правила — код; LLM подключается через чистый API и не может нарушить детерминизм.
3. Гибрид без границы — LLM и правила смешаны, решения не воспроизводимы.

## Decision

Принят вариант 2: **детерминированное ядро — продукт и источник истины; LLM — внешний опциональный слой поверх чистого API (фаза O), промты ролей заготовлены (`python_ai_tutor_prompts.md`) и не входят в ядро.**

## Rationale

- Воспроизводимость обучения: состояние/результаты не зависят от «мозга», который может меняться хоть каждый день (prompt2, финал).
- S6 / ось Thinking остаются честной точкой эскалации `pending_llm_review` (в ядре — флаг, не вычисление).
- Zero-cost и локальность (prompt.md) без обязательного внешнего API.

## Consequences

- В ядре: LLM-call = 0; генерация hints/exercises/curriculum/transitions через LLM запрещена.
- Быстрые решения с субъективной оценкой возвращают `UNRESOLVED / REQUIRES_HUMAN_RULE`, а не «домысл».
- Phase O отдельным ADR после P-N; ядро при этом не модифицируется.
