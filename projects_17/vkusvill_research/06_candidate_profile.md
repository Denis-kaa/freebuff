## § 20 — Сценарий первых 90 дней (per brief)

### Первые 30 дней — Discovery

- [ФАКТ per S069***REMOVED*** Задача: «анализ текущей логики» — **все 30 дней посвящены reverse-engineering**.

Конкретный план:
- [НЕДЕЛЯ 1-2 per СИЛЬНАЯ ГИПОТЕЗА***REMOVED*** Каталогизировать все Excel/VBA-инструменты автозаказа в ВкусВилл. Установить контакт с **ритейл-менеджерами** (5-10 объектов) и собрать их рабочие Excel-процедуры.
- [НЕДЕЛЯ 3 per СИЛЬНАЯ ГИПОТЕЗА***REMOVED*** Построить **shadow-mode harness**: Python-скрипт, который берёт legacy Excel-inputs → сохраняет expected_output → читает existing Excel → сравнивает. Aim: **0% mismatch baseline** для всех существующих категорий.
- [НЕДЕЛЯ 4 per СИЛЬНАЯ ГИПОТЕЗА***REMOVED*** **Pitch на 30-day review** с ритейл-директором: «вот legacy-логика в формализованном виде; вот предложения, где AI-shadow-mode может дать улучшение». **Цель:** получить buy-in для следующего этапа.

### 30-60 дней — Shadow Mode Build

Конкретный план:
- [МЕСЯЦ 2 per СИЛЬНАЯ ГИПОТЕЗА***REMOVED*** **Создать первые 2-3 AI-инструмента** для тестовых категорий (молочка, крупы, напитки). Каждый: входные данные → AI-output → parity-check с Excel.
- [МЕСЯЦ 2 per СИЛЬНАЯ ГИПОТЕЗА***REMOVED*** Тесты на **исторических данных** за прошлый год. Цель: AI-output «не хуже» Excel'овского baseline (по MAPE/WAPE).
- [МЕСЯЦ 2 per СИЛЬНАЯ ГИПОТЕЗА***REMOVED*** **Начать Shadow Mode в production**: AI-shadow считает параллельно с Excel для 1-2 категорий. Ретейл-менеджеры видят **«new column»** с AI-прогнозом, но решения принимают на основе Excel (per S069 «дублировать»).

### 60-90 дней — Pilot + Tolerance

Конкретный план:
- [МЕСЯЦ 3 per СИЛЬНАЯ ГИПОТЕЗА***REMOVED*** **A/B-TESTING**: на 1-2 дарксторах использовать **только AI** (legacy — control). На 1-2 дарксторах — оба. Сравнить: availability, freshness, manual-override-frequency, ритейл-менеджер satisfaction.
- [МЕСЯЦ 3 per СИЛЬНАЯ ГИПОТЕЗА***REMOVED*** **Validation в shadow-mode** до перехода: если AI-output стабильно лучше — **дать бизнес опцию «use AI»** в их дашборд.
- [МЕСЯЦ 3 per СИЛЬНАЯ ГИПОТЕЗА***REMOVED*** **Document для wider rollout**. Полная документация: что сделано, метрики, риски, roadmap для следующих категорий.

[ФАКТ per S082***REMOVED*** «Дешёвая проверка гипотез» — это значит, что **если pilot покажет**, что AI **НЕ лучше legacy** на 1-2 дарксторах, **откат в legacy = OK** (per продуктовый подход). Pilot — **не «prove it works», а «prove it might work or kill it cheaply»**.
