ROLE

Ты — Senior Software Architect + Repository Forensics Engineer +
Documentation Systems Architect.

Твоя задача НЕ реализовать Content Intelligence.

Твоя задача — провести глубокий анализ существующей платформы Freebuff /
Workspace OS и создать работающий слой связи:

REAL CODE
↔ DOCUMENTATION
↔ ARCHITECTURAL CONTRACTS
↔ TESTS
↔ RUNTIME
↔ EVENTS
↔ KNOWLEDGE GRAPH

После выполнения этого задания любой последующий AI-agent должен иметь
возможность определить не только "что написано в документации", но и:

1. где это реализовано;
2. каким конкретным кодом реализовано;
3. каким API/CLI вызывается;
4. какие события порождаются;
5. где хранится состояние;
6. какими тестами подтверждается;
7. какие документы описывают этот механизм;
8. какие архитектурные контракты на него ссылаются;

10. какие утверждения пока являются только проектными решениями.

5. SEMANTIC ANCHORS
============================================================

Введи систему semantic anchors.

Не используй обычные пользовательские hashtags как единственный механизм.

Создай структурированный формат машинных идентификаторов.

Минимальный namespace:

@entity
@component
@module
@symbol
@contract
@event
@storage
@test
@decision
@requirement
@scenario
@factory
@forge
@opportunity
@whim

Пример:

@entity scenario.registry
@symbol ScenarioRegistry.find_role
@contract scenario.selection
@event scenario.selected

Anchors должны быть:

- стабильными;
- уникальными;
- машиночитаемыми;
- независимыми от номера строки;
- пригодными для graph indexing;
- пригодными для semantic/vector search.

НЕ используй line number как identity.

12. "BUTTON → SCRIPT → INSTRUCTION"
============================================================

Особенно важно.

Нам нужна возможность для будущего AI-agent получать
не абстрактное описание, а конкретную навигацию.

Для каждой capability определи:

CAPABILITY
    ↓
ENTRYPOINT
    ↓
SCRIPT / FUNCTION
    ↓
INPUT
    ↓
OUTPUT
    ↓
SIDE EFFECTS
    ↓
RELATED CONTRACTS
    ↓
RELATED DOCUMENTATION

Например:

CAPABILITY:
scenario execution

ENTRYPOINT:
scripts_01/forge.py chain

IMPLEMENTATION:
ForgeFacade.run_chain()

INPUT:
project slug

OUTPUT:
ChainRun

SIDE EFFECTS:
ForgeRegistry.record_run()

DOCUMENTATION:
...

TEST:
...

Таким образом агент должен иметь возможность получить инструкцию:

"Чтобы выполнить X — используй Y."

А не:

"Архитектура предполагает, что X когда-нибудь будет делать Y."

14. VECTOR SEARCH + GRAPH
============================================================

Не заменяй graph embeddings.

Используй три слоя:

LAYER 1 — STRUCTURED INDEX

точные anchors/entities/contracts.

LAYER 2 — VECTOR INDEX

семантическое содержимое документов,
кода, комментариев, ADR и артефактов.

LAYER 3 — GRAPH

явные связи между сущностями.

Идеальный retrieval:

QUERY
 ↓
VECTOR SEARCH
 ↓
SEMANTIC CANDIDATES
 ↓
ANCHOR RESOLUTION
 ↓
GRAPH EXPANSION
 ↓
CODE / DOC / TEST
 ↓
EVIDENCE

Это должно уменьшать hallucination и ускорять repository navigation.
