## 1. TL;DR

| Вопрос | Ответ |
|--------|-------|
| Что такое Attract-модуль | Обратная сторона промта 69: не «ищу исполнителей», а **«ищу заказчиков»**. Пользователь задаёт запрос («разработка телеграм ботов»), модуль генерирует сигнатуры → парсит биржи/TG-каналы/вакансии/аутрич-базы → отдаёт лиды с интентом «клиент ищет исполнителя» |

## 5. СЛАБЫЕ МЕСТА ПЛАТФОРМЫ (дополнение к PHASE1_RESEARCH.md §6)

| ID | Слабое место | Влияние на Attract-модуль | Приоритет |
|----|--------------|---------------------------|-----------|
| **W-8** | Нет машиночитаемого **реестра компетенций** пользователя (стек собран вручную из артефактов) | Модуль не знает, под кого искать → запросы генерируются вручную | 🔴 Высокий |
| **W-9** | Нет **scan-модуля ФС вне workspace** (исследование `/storage/emulated/0` — вручную через shell) | Профилирование стека не автоматизировано | 🟡 Средний |
| **W-10** | Нет **коннекторов к источникам заказов** (Kwork-парсер, TG-агрегаторы, вакансии) | Это и есть ядро Attract; Telegram-интеграция платформы есть, но однонаправленная (свои сообщения) | 🔴 Высокий |
| **W-11** | Нет **интент-профиля заказчика** и привязки LDE к competence_profile (в промте 69 «ищу исполнителя» = лид, «ищу работу» = мусор — та же полярность, что нужна Attract; нужна не инверсия, а query-driven таргетинг + скоринг под стек) | LDE из промта 69 уже фильтрует ровно то, что нужно Attract — требуется адаптация под запрос и профиль | 🟡 Средний |

### 5.1 Рекомендации
1. **W-8 → `competence_profile.yaml`** (стек → сигнатуры запросов), seed из резюме/portfolio/KWORK-ledger (уже собран в §2).
2. **W-10 → адаптеры:** KworkParser (первый), TG-агрегатор (по образцу @Golubin_bot), hh-проектная. Всё — на базе async-HTTP + `curl_cffi` (W-4).
3. **W-11 → доработка LDE:** query-driven таргетинг (сигнатуры из competence_profile) + скоринг под стек; L2-полярность не меняется («нужен/ищу» = клиент — как в промте 69).
4. **W-7 (юр. гейт)** — до деплоя: отсев запросов, нарушающих ToS (накрутка, спам) — часть программы из `/ВАКАНСИИ/5.md` попадает в эту зону.

## 6. КОНЦЕПЦИЯ ATTRACT-МОДУЛЯ (вход в Фазу 2)

```
Запрос пользователя («разработка телеграм ботов»)
        │
        ▼
[1***REMOVED*** Генератор сигнатур (W-8: competence_profile.yaml → запросы)
        │
        ▼
[2***REMOVED*** Коннекторы источников (W-10: Kwork / TG-каналы / вакансии / 2ГИС)
        │   (общая шина из промта 69: curl_cffi, прокси, retry+jitter)
        ▼
[3***REMOVED*** Lead Detection Engine — ПЕРЕИСПОЛЬЗУЕМЫЙ (W-11)
        ├─ L1: regex + стоп-слова (отсев «ищу работу», накрутки)
        ├─ L2: intent «клиент ищет исполнителя» (полярность из промта 69)
        └─ L3: ModelGateway → lead_score 0–100 под стек пользователя (competence_profile)
        ▼
[4***REMOVED*** Дедупликация + скоринг (общий с лид-агрегатором)
        ▼
[5***REMOVED*** Delivery: TG-бот платформы (notification.py) — «найден клиент: ...»
```

**Принцип:** Attract-модуль = **тот же конвейер промта 69 с query-driven таргетингом по competence_profile** и дополнительным входом «профиль компетенций». Экономит оценочно ~70% архитектуры.
