## 1. Context

Сбор лидов — зона юридического риска (ToS бирж, 152-ФЗ о персональных данных, GDPR для данных заказчиков). Платформа не имеет встроенного policy-гейта (W-7 из PHASE1_RESEARCH). Промт 69 требует «обходить WAF, баны, CAPTCHA, 24/7» — зона риска, требующая явного ограничения.

## 2. Decision

В v1 действует **жёсткий юридический гейт**:

1. **Read-only:** адаптеры только читают публичный контент (страницы поиска Kwork, публичные TG-каналы).
2. **Без outbound:** никаких автоматических сообщений заказчикам (B2-ветка — park).
3. **Без приватных данных:** не парсить переписки, приватные каналы, персональные данные сверх публичного.
4. **Фиксация:** гейт — часть Output Contract base prompt (PROMT_ARCHITECT_RUN.md §5, PROHIBITIONS).

## 3. Альтернативы, которые рассматривались

- **Без гейта (максимальная автономия)** — **rejected**: риск ToS-бана, юридических претензий; B2-автоотклик увеличивает этот риск.
- **Автоотклик только по явному разрешению пользователя** — deferred: требует policy-гейта на платформе (нет), фаза 2+.

## 4. Consequences

- ✅ Безопасно для боевого использования v1.
- ⚠️ Ограничивает конверсию (контакт только через переход в отклик пользователем вручную).
- ⚠️ Требует дисциплины: каждое новое расширение источников — ревью на соответствие гейту.
- ✅ Зафиксировано как project-local решение → переживёт миграцию (протокол §5).
