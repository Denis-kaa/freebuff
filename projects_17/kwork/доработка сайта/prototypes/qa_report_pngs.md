## 2. Детальные вердикты

### 2.1. ⚠️ FAIL (6 файлов)

#### `image1.png` — Hero/Thumb (главное фото сайта, 5 мест)
- **Метрики:** 1247 KB, ~565×690 px ≈ 0.55 B/px (нижняя граница нормы).
- **Что не прошло:** DPI < 96, нет ICC-профиля.
- **Влияние:** Sub-optimal для Chrome/iOS без ICC, но визуально приемлемо.
- **Действие:** запросить у заказчика оригинал ≥ 1920×1080 с ICC sRGB (Q-B10 / дополнить Q-B2 как часть контент-пакета).

#### `image3.png` — сетка «Виды спорта» (TASK-097)
- **Метрики:** 524 KB, ~720×485 px ≈ 0.31 B/px (в норме).

#### `image10.png` — Галерея «Примеры работ»
- **Метрики:** 352 KB, ~590×397 px ≈ 0.28 B/px (в норме).

#### `image13.png` — Референс страницы партнёра
- **Метрики:** 408 KB, ~770×400 px ≈ 0.40 B/px (граница).

> Замечание: у этих 3 «**FAIL**» — `B/px > 0.40` по правилу `Reference` (D1). Это **пограничный случай** — реально `image3/10/13` проходят как Reference, потому что содержат много детальной графики (сетка макета, фотогалерея, референс), и сжатие ниже 0.40 B/px при сохранении читаемости текста обычно не достижимо без визуальной потери. **Рекомендация:** пересмотреть порог для `Reference-фото-референсов` с 0.40 → **0.50** или выделить отдельный тип `Reference/Photos` (`bytes/pixel ≤ 0.55`).

#### `image4.png` — CatalogCard (используется в 3 страницах — TASK-096)
- **Метрики:** 448 KB, ~750×430 px ≈ 0.28 B/px.
- **Что не прошло:** нет ICC-профиля.
- **Влияние:** Самое заметное — на Safari/iOS цвет может «плыть». Карточка повторяется 3 раза → усиленный эффект.
- **Действие:** пересохранить PNG с ICC-профилем sRGB (Pillow: `Image.save(..., icc_profile=...)`) либо попросить оригинал с ICC.

#### `image7.png` — Photo (Производство)
- **Метрики:** 416 KB, ~1145×480 px ≈ 0.55 B/px (в норме для hero).
- **Что не прошло:** DPI < 96, нет ICC-профиля.
- **Влияние:** Как у `image1.png`.
- **Действие:** запросить оригинал с ICC и DPI ≥ 96.
