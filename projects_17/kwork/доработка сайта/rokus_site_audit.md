**Вывод:** Из 10 URL в `sitemap.xml` **3 страницы реально заблокированы** (DDoS-Guard куки `__ddg1_`) — это значит **Яндекс.Метрика, sitemap-side и поисковые боты получают 403 на эти URL**. Один и тот же 373-байтовый ответ на все три URL.

**Это критический GAP:**
- `/newbasketball` — блокирует страницу «Баскетбол» из ТЗ.
- `/newhockey` — `[NEEDS VERIFICATION***REMOVED***` — вне ТЗ, но если клиент хочет, не получится получить.
- `/infoblok` — потенциальный контент для «О нас»/«Партнёрство».

**Манифестация в sitemap.xml:** Google Яндекс обходятся иначе (вероятно bot-trusted bypass). Это объясняет, почему страницы ИНДЕКСИРУЮТСЯ в `sitemap.xml`, но НЕ доступны пользователям из поиска, если в кэше устарело.

## 1. Site-wide findings (кросс-страничные)

### 1.1. Title по страницам `[FACT***REMOVED***`
- `/` → `Rokus | Производство спортивной одежды на заказ с дизайном в подарок.`
- `/costumes` → уникальный, про костюмы.
- `/newfootball` → уникальный, про футбольную форму.
- `/newvolleyball` → уникальный, про волейбольную форму.
- `/tkani`, `/policy`, `/requisites` → уникальные (шаблонные/стандартные).

**Title — OK.** Каждая страница имеет уникальный, тематический title.

### 1.2. Meta Description — критическая проблема `[FACT — DUPLICATE***REMOVED***`
На **всех 4 проверенных публичных страницах** (`/`, `/costumes`, `/newfootball`, `/newvolleyball`) используется **идентичный текст description**:

> `«Изготавливаем спортивную одежду с нанесением имени, фамилии, номера игрока и логотипа команды»`

**SEO-impact:** это канонический пример Duplicate Meta Description в Яндексе/Google → снижение релевантности по спортивным запросам. **Требует немедленного исправления** как часть SEO (Section 9 Master Roadmap).

### 1.3. Heading hierarchy (H1 / H2 / H3) — критическая проблема `[FACT — ABSENT***REMOVED***`
- В статическом HTML на проверенных страницах **нет ни одного `<h1>`, `<h2>`, `<h3>`**.
- Это значит: контент оформлен либо **как изображения** (текст «зашит» в PNG/JPG), либо через **кастомные Tilda-блоки без семантических тегов** (Zero Block + `t-text` или `t-cover`).

**SEO-impact:** Поисковики не могут корректно индексировать иерархию контента. **Требует** в Master Roadmap **TASK-HE1** (явная задача: переделать заголовки в `<h1>/<h2>/<h3>`).

### 1.4. Формы — критическая аномалия `[FACT — ZERO <form> in static HTML***REMOVED***`
- На проверенных страницах **`<form>` элементов нет**.
- Input-поля (по именам атрибутов `name=`) **присутствуют**: `Email`, `Name`, `Phone`, а на `/newfootball` — специфические `footdiz`, `footteam`.

**Вывод:** формы реализованы через **Tilda-обёртку / JS-инжект** — Tilda «вписывает» input-поля в общий JS-rendered pop-up (`t-popup`). curl их не видит как завершённый `<form>`.

**Consequence:** `[NEEDS VERIFICATION***REMOVED***` через **submit-тест в браузере**, потому что:
- какие именно pop-up срабатывают → не видно из HTML;
- куда уходят лиды → только через проверку настроек Tilda Forms.

### 1.5. CTA-инвентарь `[FACT — повторяющиеся тексты***REMOVED***`
По всем 7 страницам встречаются повторяющиеся текстовые CTA:
- `Получить подарок`
- `Заказать`
- `Подробнее`
- `Отложить`
- `Load more`
- *(+ 24 прочих `t-btn` за пределами grep-лимита)*

**Вывод:** для GAP-анализа «CTA» означает: **где на главной можно кликнуть, чтобы появилась форма**. Их явно больше чем в ТЗ требуется.

### 1.6. Top-Nav структура `[FACT***REMOVED***`
- Top-nav на всех страницах содержит ссылки на основные разделы:
  - `/newfootball`, `/newvolleyball`, `/costumes` (прямые URL, **без dropdown**)
  - Контакты
  - Телефон
- Меню **НЕ содержит выпадающего «Виды спорта»** → это **прямое противоречие ТЗ** (см. Section 4 Master Roadmap, Gap #1).

### 1.7. Footer структура `[FACT***REMOVED***`
По всей видимости (статический HTML + классы `t-footer`):
- 3 колонки: **Каталог / Информация / Контакты**
- Ссылки: `/policy`, `/requisites`
- Соцсети + телефон (WhatsApp **присутствует**)
- **МАКС отсутствует** (вероятно — `[NEEDS VERIFICATION — точная экстракция***REMOVED***`)

## 3. Tilda block inventory (кросс-страничный)

`[FACT***REMOVED***` — самые частые классы `t-*` блоков, ранжированы по частоте:

| Класс / паттерн | Где встречается | Что это |
|-----------------|----------------|---------|
| `t-records` | везде | контейнер страницы (Tilda records body) |
| `t-popup`, `t-popup__container` | везде | модальные окна (формы, «Подарок») |
| `t-form__errorbox` | везде | валидационные сообщения форм |
| `t-cover` | hero-блоки | обложки с наложением текста |
| `t-slds`, `t-slds__arrow` | везде | слайдер |
| `t-menu`, `t-menusub` | везде | навигация |
| `t-store`, `t-store__card__btn` | где есть магазин | Tilda Store-карточки |
| `t706__cartpage-open-form` | магазин | корзина |
| `js-store-load-more-btn` | магазин | «Показать ещё товаров» |
| `t-btn`, `t-submit` | везде | кнопки |
| `t-gallery` | некоторые | галереи (например, «Примеры работ») |
| `t985` | не извлекли | формат PDF-каталога (по ТЗ упоминается) |

**Вердикт:** все 7 доступных страниц построены на **стандартных Tilda-блоках**, без явных признаков самописного HTML/JS-injection. Это упрощает GAP-анализ — для большинства новых блоков можно использовать STANDARD или STANDARD+CUSTOM (RULE 4 promt1.md).
