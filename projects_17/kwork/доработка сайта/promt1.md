ЭТАП 5. КЛАССИФИКАЦИЯ TILDA-БЛОКОВ

Для каждого блока предложи наиболее рациональный способ реализации.

Категории:

STANDARD BLOCK

Можно использовать стандартный блок Tilda практически без изменений.

STANDARD + CUSTOMIZATION

Стандартный блок с настройкой.

ZERO BLOCK

Лучше реализовать через Zero Block.

ZERO BLOCK + CUSTOM CSS

Требуется дополнительный CSS.

ZERO BLOCK + JS

Требуется JavaScript.

CUSTOM HTML

Стандартных возможностей Tilda недостаточно.

NEEDS VERIFICATION

Невозможно уверенно определить без доступа к редактору проекта.

Не усложняй решение без необходимости.

Если задачу можно нормально решить стандартными средствами Tilda — не предлагай кастомную разработку.

ЭТАП 20. SCOPE CONTROL

Отдельно определи:

Особенно отслеживай потенциальный scope creep.

Если ТЗ содержит формулировки вроде:

- "сделать красиво";
- "улучшить";
- "добавить современности";
- "переделать по аналогии";
- "сделать удобнее";

не считай их автоматически конкретными задачами.

ФИНАЛЬНОЕ ТРЕБОВАНИЕ

Не ограничивайся составлением красивого документа.

Roadmap должен быть пригоден как реальный рабочий план реализации проекта на Tilda.

После его получения разработчик должен понимать:

«что делать → в каком порядке → где делать → каким способом реализовать → что требуется от заказчика → от чего зависит задача → как проверить результат → когда задача считается выполненной.»

Если информации недостаточно — не останавливайся.

Сначала максимально используй доступные данные, а неизвестные параметры помечай:

"NEEDS VERIFICATION"

и выноси их в список вопросов.
