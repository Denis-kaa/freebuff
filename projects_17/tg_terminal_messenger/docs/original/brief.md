# PROJECT BRIEF: tg-terminal-toolkit

## 1. PROJECT OVERVIEW
- **Название:** tg-terminal-toolkit
- **Тип:** Terminal TUI Application (CLI)
- **Цель:** Разработка терминального клиента Telegram с TUI интерфейсом для отправки медиа-файлов через встроенный файловый менеджер и архивации истории переписок
- **Целевая аудитория:** 
  - Разработчики и системные администраторы
  - Пользователи, предпочитающие терминальные интерфейсы
  - Автоматизаторы рабочих процессов

## 2. FUNCTIONAL REQUIREMENTS

### 2.1 Core Features (MUST HAVE)

#### 2.1.1 Авторизация и сессия
- **FR-001:** Авторизация по номеру телефона с поддержкой 2FA
- **FR-002:** Сохранение сессии в локальный файл `.session`
- **FR-003:** Автоматическое восстановление сессии при повторном запуске
- **FR-004:** Установка прав доступа `600` для файла сессии (только владелец)

#### 2.1.2 Интерфейс TUI
- **FR-005:** Двухпанельный интерфейс: список чатов (слева), сообщения (справа)
- **FR-006:** Навигация по чатам с помощью стрелок и горячих клавиш
- **FR-007:** Отображение последних N сообщений в активном чате
- **FR-008:** Асинхронная загрузка сообщений при скролле (не блокировать UI)

#### 2.1.3 Отправка сообщений
- **FR-009:** Отправка текстовых сообщений в активный чат
- **FR-010:** Отправка изображений (JPG, PNG, GIF, WebP)
- **FR-011:** Отправка видео (MP4, MOV, AVI)
- **FR-012:** Отправка документов (любой формат)
- **FR-013:** Встроенный файловый менеджер (FilePicker) для выбора файлов
- **FR-014:** Горячая клавиша для вызова FilePicker (например, `Ctrl+F`)

#### 2.1.4 Обработка ошибок
- **FR-015:** Обработка `FloodWaitError` с автоматической паузой и уведомлением пользователя
- **FR-016:** Обработка сетевых ошибок с возможностью повторной попытки
- **FR-017:** Валидация существования файлов перед отправкой

### 2.2 Secondary Features (SHOULD HAVE)

#### 2.2.1 Архивация
- **FR-018:** Команда для скачивания всей истории чата в локальное хранилище
- **FR-019:** Сохранение сообщений в формате JSON/SQLite
- **FR-020:** Скачивание медиа-файлов из чата в локальную папку `./downloads/{chat_id***REMOVED***/`
- **FR-021:** Прогресс-бар при массовом скачивании

#### 2.2.2 Улучшения UI
- **FR-022:** Поиск по чатам и сообщениям
- **FR-023:** Индикаторы непрочитанных сообщений
- **FR-024:** Отображение статуса онлайн/оффлайн собеседников

### 2.3 Nice-to-Have (COULD HAVE)
- **FR-025:** Экспорт истории переписки в Markdown/HTML
- **FR-026:** Рендеринг превью картинок в терминале (Kitty/Sixel протоколы)
- **FR-027:** Поддержка тем оформления

## 3. NON-FUNCTIONAL REQUIREMENTS

### 3.1 Performance
- **NFR-001:** UI не должен блокироваться при сетевых операциях (строгий async)
- **NFR-002:** Время отклика на действия пользователя < 100ms
- **NFR-003:** Потребление памяти < 200MB при работе с чатами до 10k сообщений

### 3.2 Security
- **NFR-004:** Файл сессии должен иметь права `600` (rw-------)
- **NFR-005:** Запрет на логирование конфиденциальных данных (номера телефонов, коды)

### 3.3 Reliability
- **NFR-006:** Graceful shutdown при получении SIGINT/SIGTERM
- **NFR-007:** Автоматическое переподключение при потере соединения

### 3.4 Compatibility
- **NFR-008:** Поддержка Python 3.10+
- **NFR-009:** Кроссплатформенность (Linux, macOS, Windows)
- **NFR-010:** Совместимость с основными терминалами (xterm, tmux, screen)

## 4. TECHNICAL CONSTRAINTS
- **Язык:** Python 3.10+
- **Типизация:** Type hints обязательны
- **Зависимости:**
  - telethon 1.34+ (MTProto API)
  - textual 0.40+ (TUI фреймворк)
  - rich 13.0+ (рендеринг в терминале)
  - aiofiles 23.0+ (асинхронный I/O)
  - sqlite3 (stdlib, локальное хранилище)
- **API:** Telegram MTProto (User API через Telethon)
- **Bot API:** НЕ используется
- **Архитектура:** Async/Await, Event-driven, Separation of concerns

## 5. ASSUMPTIONS
- Пользователь имеет Python 3.10+ установленный
- Пользователь работает в терминале с поддержкой UTF-8
- Стабильное интернет-соединение доступно
- Пользователь имеет валидный номер телефона для авторизации
- Telegram не накладывает критических ограничений на частоту запросов для данного случая использования
- Рендеринг картинок в терминале зависит от поддержки протоколов терминалом (опциональная фича)

## 6. ACCEPTANCE CRITERIA

### 6.1 Functional
- [ ***REMOVED*** Приложение запускается без ошибок
- [ ***REMOVED*** Успешная авторизация по номеру телефона
- [ ***REMOVED*** Отображается список чатов с возможностью навигации
- [ ***REMOVED*** Можно выбрать чат и увидеть сообщения
- [ ***REMOVED*** Можно отправить текстовое сообщение
- [ ***REMOVED*** Можно вызвать FilePicker горячей клавишей
- [ ***REMOVED*** Можно выбрать файл через FilePicker и отправить его в чат
- [ ***REMOVED*** UI не блокируется при загрузке файлов

### 6.2 Non-Functional
- [ ***REMOVED*** Код покрыт type hints
- [ ***REMOVED*** Нет блокирующих операций в event loop
- [ ***REMOVED*** Файл сессии имеет права `600`
- [ ***REMOVED*** Обработка FloodWaitError реализована
- [ ***REMOVED*** Время отклика < 100ms
- [ ***REMOVED*** Потребление памяти < 200MB

## 7. SCOPE RISKS
- **Telegram API лимиты:** FloodWait может замедлить работу при массовых операциях
- **Кроссплатформенность:** Поведение терминала может отличаться на Windows/macOS/Linux
- **FilePicker:** Навигация по файловой системе может быть сложной в TUI
- **Производительность:** Большие чаты (10k+ сообщений) могут потреблять много памяти
- **Безопасность:** Хранение сессии в файле требует надежной защиты
- **Рендеринг медиа:** Поддержка Kitty/Sixel протоколов зависит от терминала

## 8. OUT OF SCOPE (WON'T HAVE)
- Голосовые и видео звонки
- Инлайн-боты
- Создание каналов/групп
- Редактирование сообщений
- Удаление сообщений
- Bot API (только User API)
